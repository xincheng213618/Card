# 用牌生命周期：实现契约与交接

2026-09-21。本文是下一阶段的设计契约，**不是已实现能力清单**。当前已验收范围和限制见 [内容模块架构](CONTENT_MODULE_ARCHITECTURE.md)。第一位消费者是经典简雍的巧说；不得把技能名称写进通用用牌运行时。

## 交接目标

内容作者描述“什么时候、允许哪些牌、产生什么效果”；运行时负责“选择、校验、付费、暂停、恢复和清理”。新增同类技能复用这些能力，不再复制专属 pending、AI、命令和 WPF 分支。公共文件是否修改不是验收指标。

持续迭代任务负责本契约的 Core 实现、内容接入和验证，可自行完成契约范围内的适配和修复。架构任务负责边界决策和关键切片审查，不承接逐个武将的开发队列。已经验收的能力无需逐项申请使用；只有需要改变既定边界或规则含义时再提出具体问题。

## 已有基线与尚缺能力

- 已有：无状态阶段模块、冻结计划、数据帧、稳定技能身份、共享提示/AI、阶段子拼点、结果取牌、天义/陷阵/驱虎适配。
- 尚缺：统一的用牌准备与目标调整、回合内用牌限制、所有相关牌种的目标执行适配、烈刃伤害后的嵌套拼点接入。
- 简雍当前只有纵适测试消费者，没有正式武将注册。以上缺项及规则验收完成前，不得把不完整技能加入正式武将池。
- 现有 Checkpoint 通过命令前缀重放恢复。数据帧可序列化不等于支持直接反序列化整个运行中引擎。

## 内容侧契约

以下为建议签名，允许按现有代码风格调整命名，但不得改变语义边界。

```csharp
[Flags]
public enum CardUseCategories
{
    None = 0, Basic = 1, InstantTrick = 2, DelayedTrick = 4, Equipment = 8
}

public enum SkillEffectCondition { Always, PindianWon, PindianNotWon }

public sealed record GrantNextCardTargetAdjustment(
    CardUseCategories Categories,
    int MinimumTargets = 1,
    bool AllowAdd = true,
    bool AllowRemove = true,
    bool IgnoreExtraTargetDistance = true,
    SkillEffectCondition When = SkillEffectCondition.Always) : SkillModuleEffect;

public sealed record ForbidCardUseUntilTurnEnd(
    CardUseCategories Categories,
    SkillEffectCondition When = SkillEffectCondition.Always) : SkillModuleEffect;
```

类别取自最终有效牌种，不取自用于转化的实体牌。内容模块声明类别组合，Core 不猜测技能文案。经典规则版本来源沿用架构文档；具体技能的作用期限、牌种和目标下限必须先核对该版本，不混入 OL 变体。

条件效果消费同一激活计划中已经完成的拼点结果；平点属于未赢。冻结计划时拒绝没有前置拼点的条件效果、未知枚举位、非法下限及无意义的空类别。无状态模块不得把上一次结果保存在字段中。通用效果可供合成测试模块或第二个真实消费者调用。

状态至少保留来源 `SkillId + BindingId + OwnerSeat + SkillInstanceId`、授予序号、回合身份、类别和参数。来源保留用于审计；已经合法授予的效果是否因失去技能而撤销，由明确规则定义，不由模块对象是否存在偶然决定。本次回合期限从授予到当前回合真正结束，不因进入额外出牌阶段而清除。

同一授予操作因恢复不得重复写入。类别禁令取并集；独立的一次性目标调整按稳定授予顺序处理，各自对前一步的目标计划再校验，并在匹配用牌正式提交时各消费一次。每项效果至多增加一个或删除一个目标组；不因多项效果而绕过最少目标数和目标唯一性。

## 宿主数据模型

复用 `CardActionContext` 的使用者、提供者、有效牌种、实体代价原位置、转化链和父动作身份。不要另建一套只有“卡牌 ID + 目标座位”的用牌身份。

用牌计划至少区分：

1. 原始合法动作与原始目标组。
2. 准备阶段的当前目标组和允许的下一步选择。
3. 正式提交后不可变的最终目标组、效果游标及实体代价所有权。

目标组是一个完整规则单位。普通牌是一名目标；借刀是武器持有者及其被杀角色的组合；顺手/过拆还带有选取区域或公开牌选择。可以用 `CardTargetGroup(TargetSeat, AuxiliarySeat, TargetCardSelection)` 表达，也可使用显式的牌种适配 DTO。私有手牌选择保留槽位/区域语义，不把对方手牌实体 ID 填进公开选项。

无中生有、酒、桃等自身效果在计划中显式归一为自身目标，不能用空数组与“无目标”混为一谈。群体牌先按原规则生成实际目标，再允许调整。铁索重铸另有动作语义，不是零目标用牌，不触发或消费下一张使用牌的修饰。

待决策帧只保存数据：父帧 ID、计划、修饰游标、冻结选项及步骤。不得保存模块对象、闭包、可写玩家引用或 UI 对象。帧自身管理暂停与恢复，内容模块不调用父流程的 Resume。

## 准备、提交与结算顺序

1. **验证原始动作**：保留现有服务端合法动作匹配、归属、Revision 和 PromptId 校验。未经授权的距离或目标修改不能混入原始动作。
2. **建立准备计划**：原牌种适配器生成初始目标组，查询匹配的回合效果。准备阶段尚未重复声明、扣牌或增加用牌次数。
3. **生成有限合法选择**：使用通用 `SkillPrompt`，提供保持、增加或删除。服务端持有每个 choice 对应的完整目标计划；客户端只提交选择标识。选择 ID 和枚举顺序必须稳定。
4. **确认选择**：服务端重新检查计划仍有效；额外目标只豁免授权的距离条件，其他规则照常。拒绝伪造、越权、过期和不匹配的回答且不产生副作用。
5. **正式提交一次**：最终合法性、代价归属和一次性效果消费构成一次不可重复的提交。保留现有用牌/移动事件所要求的相对顺序；既有触发只能看到同一份最终目标，不得观察到半份已提交状态。
6. **逐目标结算**：`TargetsConfirmed`、既有目标确定后的程序窗口、实际效果和回放消费同一份最终计划。牌级触发和代价执行一次；目标级触发按目标规则执行。子响应、伤害、濒死等完成后推进宿主游标。
7. **结束一次**：只清理本次动作仍持有的处理区实体牌，完成事件只发一次，恢复父帧。被其他合法效果移走的牌不重复弃置。

保持原目标也会在正式使用匹配牌时消费下一张效果。如果只剩保持选择，可确定性自动前进；不要制造必点且无决策意义的 UI。非法提交、未完成的准备、普通打出/响应和重铸都不消费。准备被真正取消时释放准备状态，不能留下已经消费却未使用牌的记录。

不能通过全局拦截 `MoveCard`、临时关闭所有合法性检查或识别具体技能名字来完成续接。已有 `CardUseTargetsFinalized` 是目标确定后的窗口，不能改名冒充准备阶段。

## 牌种适配必须保持的语义

| 类别 | 适配要求 |
| --- | --- |
| 杀及属性杀 | 一次实体付费、次数记录和酒效果消费；共用多目标续接，不能伪造方天画戟/天义来源获得权限；最终目标的响应与伤害真实发生 |
| 无中生有、桃、酒 | 显式自身目标，再按规则处理增减；桃的受伤条件等仍适用；酒的新增受益者不能因仅清理当前角色而跨回合残留 |
| 南蛮、万箭、桃园、五谷 | 先保留原始排除/禁令/可用牌数约束，再调整最终列表；响应、收牌和结束条件以最终列表为准 |
| 决斗、火攻、顺手、过拆 | 每个最终目标独立子结算；原单目标完成函数不能提前结束整张牌；私有区域选择不能泄露其他目标手牌 |
| 铁索 | 使用与重铸分开；调整授权与基础目标上限分开，保留目标唯一性及删后下限 |
| 借刀 | 增删完整目标组；额外武器持有者必须有武器，依赖的被杀角色必须满足该持有者的杀规则；不能把使用者对额外目标的距离豁免传递成被迫杀的无限距离 |
| 延时锦囊、装备 | 是否可调整由效果类别声明和适配能力共同决定；未授权不进入目标调整；使用禁令仍统一检查 |

卡牌先天禁止目标、自身限制、阵亡、既有目标转移规则以及其他技能施加的目标禁令不能被距离豁免一并移除。适配器应显式接收距离授权，不使用全局临时布尔开关。

## 使用禁令与各入口

采用一份基于 `CardActionType` 和有效牌种的规则查询，并让合法动作、服务端正式提交及 AI 共用它。仅从 UI 隐藏锦囊不是实现完成。

至少审计普通出牌、视为/转化、主动技能生成牌、替他人提供牌、无懈可击以及借刀被迫使用杀的入口。无懈可击属于使用锦囊；普通闪、决斗/南蛮要求打出的杀等响应不能因为持有原始锦囊实体就被误禁。具体入口按规则的使用/打出语义分类，不能按“是否出现在响应弹窗”分类。

Qice、Luanji、Zhangba、Fuhun、Jijiang 和技能程序转换都需要检查是否经过共同提交边界。不能只支持人类普通手牌入口而留下 AI、技能或多实体牌绕过。

回合效果在真正 `EndTurn` 清理，含额外阶段、跳过阶段和死亡导致的推进；新回合开始可做防御性核验。不能把“清理拥有者自己的回合”当作所有授予效果的期限。

## 实现顺序与文件归属

| 切片 | 交付与验收边界 |
| --- | --- |
| A：效果与回合状态 | 条件效果、类别查询、稳定授予身份、消费与过期；一个合成消费者证明无技能名字分支，覆盖禁令入口 |
| B：准备与最终计划 | 通用选择、最终目标组、一次提交/恢复；先贯通杀及一种普通锦囊，再补其余适配；未覆盖期间不注册简雍 |
| C：牌种与入口闭合 | 逐项完成上表和转化/生成牌入口，确认事件、真正效果和次数一致；不能把“帧列表已修改”作为通过 |
| D：拼点与真实消费者 | 烈刃接入共享拼点且正确恢复伤害父流程；巧说/纵适组合、真实 UI 和完整简雍内容验收后再注册 |

每个切片先有固定场景的局部验证，再进入下一个。允许基于真实依赖调整实现先后，但不得把未闭合能力标记为完成。执行任务是当前 Core/Content/WPF/测试产品文件的唯一修改者；架构和门禁任务审查期间只读，发现问题由执行任务统一修复，避免共享工作区互相覆盖。

复用现有引擎作为规则宿主，逐步把准备/执行游标和通用能力隔离出来。不要先做全量改写、创建第二套规则引擎，或为尚无消费者的任意脚本/插件系统扩大范围。

## 验收矩阵

| 机制验收 | 必须观察到的结果 |
| --- | --- |
| 赢、平、输；条件效果 | 条件只执行一次，拼点子帧恢复后游标继续；平点走未赢 |
| 保持、增、删；只剩保持 | 下一张合格牌各恰好消费一次；删除不低于下限；不合格牌/重铸/非法回答不消费 |
| 距离与禁令 | 原本超距离的额外目标可加入，仍被其他规则禁止的目标不可加入；借刀依赖目标不错误继承距离豁免 |
| 普通、转化、多实体、AI、嵌套入口 | 同一有效牌种遵守相同禁令和调整；原始实体类别不会误判；普通响应不受误伤 |
| 自身、群体、单目标转多目标、借刀 | 各组实际效果匹配最终计划，未选目标不结算；一次付费/声明/牌级触发，目标级触发按规则逐个执行 |
| 中途无懈、死亡、牌被移走 | 继续剩余目标或依法结束；本动作以外的牌不清理；无重复移动或悬挂帧 |
| 暂停、伪造、Replay、JSON | 每个新增暂停边界可由当前命令前缀重放；未授权玩家看不到私有选项；过期输入无副作用；帧往返保留身份和游标 |
| 多效果与回合结束 | 稳定顺序，无重复授予，期限正确；额外阶段不提前清理，所有受益者在正确期限失效 |
| 烈刃遇纵适 | 共享结果取牌可触发，已移动牌不重复清理，伤害/攻击父流程只恢复一次 |

机制级隐私、过期回答和续接测试建立一次供消费者复用，不要求每个后续技能重复整套模板。消费者只补自身条件、效果和特有交互；UI 只有新增交互形态才补通用交互测试。

迭代时使用名称过滤跑相关检查；公共机制切片完成时运行一轮完整 Core/WPF 和 Release 构建，记录命令、通过/失败/跳过数量与限制。不要并行启动多个全量构建。当前行为异常必须失败，不得按异常消息跳过整条测试。

模块语义修改提升其 Revision。既有命令、事件、帧或暂停点改变时按 [开发门禁](DEVELOPMENT_GATES.md)处理规则版本；普通内容注册不自动增加规则版本或制造历史版本测试矩阵。

## 验收后的自主迭代

在已验收能力范围内：选择内容 → 实现模块/规则组合 → 固定场景验证 → 必要的素材和通用 UI 检查 → 记录当前完成项 → 继续下一项。批次末集中全量回归。无需等架构任务逐武将审批，不因可预期的常规修复停工。

遇到能力缺口，执行任务先判断能否在既定职责内增加一个有边界、可复用的能力；可以则自行实现并验证。只有需要改变稳定身份、公开/私有边界、全局结算顺序或现有契约的规则含义时，向架构任务提供“当前代码证据、最小冲突例子、建议取舍”。等待期间可以做不依赖该决定的内容和测试，不能绕过规则注册半成品。

加速验收看内容是否能独立表达、公共机制是否有多个消费者、是否消除了重复流程，以及局部检查是否能给出可信反馈。不按新增文件数评价，也不以削弱规则或删掉当前行为断言换速度。提交、推送与发布沿用用户另行授权，不由架构验收自动授权。
