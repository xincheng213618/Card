# 经典曹丕迁移规格

状态：规则和场景已锁定，等待通用触发、死亡取牌、判定结果订阅和结构化主公技标签能力；未进入默认武将池。

## 1. 内容身份与目标版本

本块只定义身份模式的经典曹丕，不与界曹丕、国战曹丕、威曹丕或其他同名技能合并。

| 字段 | 目标值 |
| --- | --- |
| 武将 ID | `classic:cao-pi` |
| 技能顺序 | `classic:xingshang`、`classic:fangzhu`、`classic:songwei` |
| 势力／性别／体力 | 魏／男性／3；身份为主公时沿用模式规则增加体力上限和体力 |
| 来源包 | 神话再临·林 |
| 进入默认池 | 三项技能完整并通过场景后一次性加入，不发布半成品曹丕 |
| 目标结算版本 | 一将成名官网当前经典页与 BWIKI 经典定义：放逐先摸 X 张牌，然后翻面 |

技能文案锁定如下：

- 行殇：当其他角色死亡时，你可以获得其所有牌。
- 放逐：当你受到伤害后，你可以令一名其他角色摸 X 张牌（X 为你已损失的体力值），然后其翻面。
- 颂威：主公技，当其他魏势力角色的黑色判定牌生效后，其可以令你摸一张牌。

这里的“主公技”是结构化标签，不是独立执行枚举；颂威的主动决定者是完成判定的魏势力角色，不是曹丕。行殇、放逐和颂威均为可拒绝的触发技。此处采用 [BWIKI 技能概念介绍](https://wiki.biligame.com/sgs/%E6%8A%80%E8%83%BD%E6%A6%82%E5%BF%B5%E4%BB%8B%E7%BB%8D)对技能标签、状态技／触发技、翻面和判定时机的区分，不从中文文案反推运行时类型。

## 3. 通用能力依赖

本武将必须由通用规则能力组合，不新增曹丕专属 `SkillKind`、判定分支或死亡函数旁路。

### 3.1 放逐：伤害后顺序效果

建议绑定：

1. 在一次伤害结算完成后的 `AfterDamage` 窗口收集候选；`oncePerDamage`，不是按伤害点数逐次询问。
2. 发动时重检曹丕仍可发动技能，并选择一名其他存活角色；不能选择自己或已经死亡的角色。
3. 在效果开始执行时读取 `lostHp = max(0, maxHp - hp)`，不要冻结为受伤前或扣血前的值。
4. 目标摸 `lostHp` 张牌；摸牌及由牌堆耗尽引发的状态完整结束后，再对同一目标执行一次通用 `flip`。
5. `flip` 是切换正／背面，不是强制设为背面；背面目标会翻回正面。
6. 已发动效果依据触发运行时的 continuation policy 继续；不能因曹丕在摸牌子步骤期间失去技能而取消已经开始的翻面。若目标在子步骤期间死亡，则跳过无法对死亡角色执行的剩余翻面，不回滚已经摸到的牌。

已有 `IsFaceDown` 与回合开始前翻回正面并跳过回合的基础语义可以复用；缺口是通用 `flip` 效果、伤害后触发绑定和跨子步骤续接。

### 3.2 行殇：死亡清理前取得牌

行殇不能订阅现有 `PlayerDiedEvent`：当前死亡路径在发布该事件前已经把手牌、装备区和判定区全部移入弃牌堆。需要在角色确定死亡、身份信息按模式公开后，死亡牌区清理和击杀奖惩之前开放可暂停的死亡触发窗口。

建议基础能力：

- 冻结死亡事实：受害者、责任来源、父结算和进入窗口时各可取得区域的实体牌 ID；候选排序仍按规则集执行。
- `claimDeathCards(victim, zones)` 只取得结算时仍位于受害者手牌区、装备区和判定区的冻结实体牌；先前已被其他效果移动的牌不重复取得。
- 批量移动是同一受控操作，保留每张牌的原区域、所有者、获得者、技能原因和死亡帧因果关系。
- 受害者没有这些牌时仍可选择不发动；运行时不应生成无效果 Prompt。
- 多名拥有行殇的角色同时有资格时，按通用同一时机排序逐个询问；先结算者取得后，后续候选在发动前重检是否还有可取得牌。
- 不屈“创”、木牛流马粮等特殊牌区不得仅凭“所有牌”三个字自动并入。第一版仅覆盖普通手牌、装备区和判定区；特殊区需依据对应规则单独审定并在能力参数中显式列出。

死亡清理继续统一处理未被取得的牌、击杀反贼摸牌、主公误杀忠臣惩罚与胜负检查；行殇不得自行复制这些政策。

隐私边界：死亡角色暗手牌的具体牌面只发送给获得者和可信宿主；公开观察者看到受害者、获得者、总数量和公开区域牌。回放保存实体牌移动，但按观看者过滤快照与事件。

### 3.3 颂威：最终判定结果订阅

建议绑定在 `JudgmentFinalized`／“判定牌生效后且进入判定牌收尾前”的规则窗口，而不是订阅提交后的 `JudgmentResolvedEvent`：

1. 使用改判链完成后的最终实体判定牌颜色；中间被替换的黑牌不触发。
2. 判定角色必须仍为其他魏势力角色；曹丕自己的黑色判定不触发。
3. 曹丕必须仍存活、拥有颂威且当前身份为主公；标签检查由技能资格层完成。
4. Prompt 属于完成判定的魏势力角色，由其决定是否令曹丕摸一张牌；不能让曹丕代选。
5. 摸牌子步骤结束后再继续判定牌收尾和原父结算，不能提前把判定牌弃置或取得。
6. 多名曹丕／动态获得技能场景按冻结候选与发动前重检处理；通常身份局只有一个主公，但执行器不能把座位或技能名写死。

判定空牌堆、无最终牌、红色最终牌、非魏角色、曹丕已死或非主公均不建立颂威 Prompt。

## 4. 最小验收场景

### 4.1 放逐

- 曹丕从满体力受到 1 点伤害：选择其他存活角色，目标摸 1 后由正面翻为背面。
- 已损失 2 点体力后再受到一次 1 点伤害：X 在效果执行时为 3；一次伤害只产生一次选择。
- 目标原本背面：摸牌后翻回正面；后续回合不因旧背面状态再被跳过。
- 发动与跳过、无合法其他目标、目标在摸牌子步骤后死亡、牌堆补充／耗尽分别有确定结果。
- Checkpoint 分别停在候选 Prompt、选定目标后、摸牌子流程中；恢复后只摸一次、只翻一次，并回到正确父伤害帧。
- 类型化事件能区分伤害事实、放逐发动、技能摸牌和翻面；WPF 先显示私有目标选择，再公开结算结果。

### 4.2 行殇

- 死亡角色分别只持手牌、只装备、只挂延时锦囊以及三者混合；发动后实体牌全部进入曹丕手牌，原区域清空。
- 空牌死亡不询问；部分牌在死亡窗口内先被移动时，只取得仍在原区域的牌。
- 两名有资格的行殇拥有者按稳定规则次序结算，后者不复制先者已取得的牌。
- 曹丕自己死亡不触发自己的行殇；其他曹丕是否触发按“其他角色”与候选资格处理。
- 行殇与反贼击杀奖励、主公误杀忠臣、死亡装备离场效果、死亡胜负检查分别验证先后；不得漏掉或重复死亡政策。
- 暗手牌不出现在非获得者 Prompt／快照；公开装备和判定区保持可审计移动信息。
- Checkpoint 停在死亡触发排序和行殇发动 Prompt；恢复后死亡牌区、奖惩、胜负和父结算均只推进一次。

### 4.3 颂威

- 其他魏角色的最终判定牌为黑色时，由该魏角色选择发动／跳过；发动后曹丕精确摸一张。
- 最初黑色后被改为红色不触发；最初红色后被改为黑色触发；连续改判只读取最终牌。
- 曹丕自己的黑色判定、其他势力黑色判定、红色判定、无牌判定均不触发。
- 曹丕是主公／非主公、存活／死亡、拥有／失去颂威四组资格边界分别验证。
- 颂威 Prompt 位于最终判定生效后、判定牌收尾前；天妒等同窗口技能的顺序由通用规则选择，不按技能名硬编码。
- Checkpoint 停在颂威 Prompt；恢复后不重复判定、改判或摸牌，原延时锦囊／八卦／洛神等父流程正确续接。

### 4.4 整体与内容边界

- `classic:cao-pi` 三技能顺序、魏／男性／3 体力、身份主公加体力和当前经典池精确集合有回归。
- 新内容包和 rules 版本递增；旧 `standard-classic-generals@1.63.0`、rules v78 以及 `standard-composed-skills@1.0.0`／rules v79 的内容哈希、存档和回放仍可解析。
- AI 能基于公开关系选择放逐目标、决定行殇和颂威；AI 不读取对手暗手牌或未来牌堆。
- WPF 使用通用触发选择面，不新增曹丕专属窗口；技能标签、完整文案、翻面状态和死亡取牌反馈可见。
- 肖像作为后续独立视觉块接入；未选定资源前不复用其他武将肖像，也不改变玩家资料中的既有资源键。

## 5. 实施拆分与完成门槛

| 顺序 | 功能块 | 完成门槛 |
| --- | --- | --- |
| A50a | `AfterDamage` 触发、动态已损失体力、顺序 `draw → flip` | 放逐全场景只写配置；通用 `flip` 至少由放逐外的测试组合复用 |
| A50b | 死亡清理前触发窗口、`claimDeathCards`、隐私事件 | 行殇不改死亡专用分支，普通三牌区与多候选场景可暂停回放 |
| A50c | `JudgmentFinalized` 订阅、结构化 `lord` 标签、完整曹丕 | 颂威由判定角色决定；三技能一次性加入默认池并通过历史版本边界 |
| C19 | 独立肖像与卡面验收 | 资源来源、许可／生成路径、解码断言、1120×740 离屏视觉复核齐全 |

A50a～A50c 可以随通用运行时能力分块交付，但在 A50c 完成前不得将曹丕加入默认池。每个块都需要 Core/WPF 场景、Release 构建、Checkpoint/Replay、玩法哈希和旧版本读取验证；运行中的 WPF 若锁定默认输出，应使用隔离 `--artifacts-path`，不终止用户进程。

## 6. 当前代码差距核对

- 翻面持久状态和“背面角色回合开始前翻回正面并跳过该回合”已存在，可作为通用 `flip` 的基础。
- 判定有公开请求、替换和结果事件，但这些是宿主观测事件；尚缺可改变状态且能暂停恢复的最终结果规则窗口。
- `DeathFrame` 已存在，但当前 `FinalizePlayerDeath` 在 `PlayerDiedEvent` 前先弃置手牌、装备区、判定区和不屈牌；因此公开死亡事件不能实现行殇。
- 现有 v1 技能程序只覆盖查询修正、转换和主动步骤，不支持事件触发、判定订阅或死亡技能。曹丕应等待通用 v2 能力，不回退到新增技能名分支。

本文件是内容任务交给通用运行时任务的规则与场景契约。实现时若基础能力的最终名称变化，可更新绑定名称，但不得改变上述目标版本、选择主体、效果顺序、牌区隐私或旧内容边界。
