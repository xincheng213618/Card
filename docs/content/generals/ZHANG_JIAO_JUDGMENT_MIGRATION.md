## 3. 技能概念与执行形态

依据技能概念设计，标签和执行机制分开：

- 经典／界雷击和鬼道是一般技标签，但各自包含一个或多个可选触发绑定。
- 黄天带 `lord` 标签；真正的出牌阶段入口属于其他群势力角色，技能拥有者仍是当前存活且身份为主公的张角。
- “主公技”不等于主动技种类，也不自动获得结算优先级；它只增加身份、势力和提供者条件。
- 界雷击不是一个不可分割的专用流程。它至少拆成“闪／闪电动作后可发动一次自己判定”和“自己的任意判定完成后按最终花色处理”两个绑定。
- 技能名称和展示文本不执行规则；内容配置引用稳定的 SkillInstanceId／BindingId，多个版本可复用同一个 judge、replaceJudgment、damage、recover、draw 基础能力。

不能新增 `BoundaryLeiji`、`BoundaryGuidao` 专用引擎分支、专用 Prompt 或 WPF 页面。

## 4. 各版本精确规则

### 4.1 经典身份张角

经典雷击：

1. 张角每成功使用或打出一张有效【闪】后，可以选择另一名存活角色进行判定。
2. 最终判定为黑桃，张角对该角色造成 2 点雷电伤害；为梅花，张角先回复 1 点体力，再对该角色造成 1 点雷电伤害；其他花色无效果。
3. 回复在满体力时可以为零，但不能因此取消随后 1 点雷电伤害。
4. 八卦阵提供的有效【闪】、龙胆等合法转换得到的【闪】均按一次有效闪触发；无双要求的每一张成功闪各自触发。把两张【闪】经丈八蛇矛当【杀】不触发雷击。
5. 雷击完整结算后恢复原响应父帧；雷击伤害来源是张角，进入统一雷电伤害、连环、濒死、奖惩和伤害后技能链。

经典鬼道：

1. 一张公开判定牌生效前，张角可以打出自己手牌区或装备区的一张黑色实体牌替换它。
2. 被替换的当前判定牌进入该鬼道发动者手牌，而不是弃牌堆；替换牌经过 Processing 后成为新的公开当前判定牌。
3. 若当前装备的八卦阵正在提供本次八卦判定，不能同时把这张八卦阵作为该判定的鬼道支付牌；它在其他判定中仍是合法黑色装备候选。
4. 同一名拥有者在同一次判定中只有一次鬼道机会，跳过后不能因别人继续改判而再次加入。

经典黄天：

1. 仅当张角是存活主公且技能有效时，其他存活群势力角色在各自出牌阶段获得入口。
2. 每个提供者每个出牌阶段限一次，从自己手牌选择恰好一张【闪】或【闪电】，公开交给张角手牌；装备区牌、转换后有效牌名和他人提供的牌均不合格。
3. “每阶段一次”记在提供者的黄天绑定使用账本，不记成张角本人的一次主动技。

### 4.2 界张角

界雷击使用两个绑定：

1. 当界张角成功使用或打出【闪】，或使用【闪电】时，可以发起一次以自己为判定主体的技能判定；父牌 action 在完整判定和其后触发结算后继续。
2. 当界张角自己的任意判定完成后读取最终有效牌，不限于上一步产生的技能判定。八卦、闪电、乐不思蜀、兵粮寸断及其他规则产生的本人判定都能进入该绑定。
3. 最终为黑桃时，可以选择一名存活角色并对其造成 2 点雷电伤害；“一名角色”包含自己。
4. 最终为梅花时，先令界张角回复 1 点体力，再可以选择一名存活角色并对其造成 1 点雷电伤害。跳过伤害选择不撤销已经执行的回复；满体力时零回复也仍可选择伤害。
5. 其他花色不创建无效果伤害 Prompt。每个 JudgmentId 的判定后绑定只执行一次，不因多个观察事件重复触发。

界鬼道保留经典鬼道的黑色手牌／装备牌替换和取得原判定牌语义；此外，若本次实际打出的替换牌是黑桃 2～9，界张角立即摸一张牌。该摸牌属于这次替换动作，即使随后其他角色再次改判也不撤销；按最终判定牌是否为黑桃 2～9补摸是错误实现。

界黄天：其他群势力角色的出牌阶段限一次，可以交给主公界张角一张【闪】或一张黑桃手牌。这里是实体牌本身为【闪】或实体花色为黑桃；黑色梅花非闪手牌不合格，黑桃装备区牌也不合格。

### 4.3 国战张角

国战雷击仍在使用或打出有效【闪】后选择另一名角色判定，但仅黑桃造成 2 点雷电伤害；梅花不回复也不造成伤害。鬼道保留黑色牌改判和取得原判定牌。没有黄天。

暗置武将牌不能提供雷击／鬼道候选；明置或预亮、双将技能归属和 1.5 阴阳鱼体力换算由国战通用层决定。D3 只应保证配置可表达，不得在身份模式迁移时提前注册一个绕过明置规则的国战张角。

## 5. 通用判定上下文与窗口

`JudgmentFrame` 需要从当前“目标、原因、当前牌和候选座位”扩展为可订阅上下文，至少保存：

| 字段 | 用途 |
| --- | --- |
| `judgmentId`／`parentResolutionId` | 判定后技能精确去重并返回父结算 |
| `turnActorSeat`／`subjectSeat` | 改判从当前回合角色排序，不能误用判定对象作为起点 |
| `reasonId`／`initiatorBindingId` | 区分八卦、延时锦囊、雷击和其他技能判定 |
| `originalCardId`／`currentCardId` | 审计首次亮牌和每次替换后的当前牌 |
| `effectiveSuit`／`rank` | 所有改判完成后供雷击、天妒和原效果读取 |
| `replacementOccurrences` | 每个 SkillInstanceId／BindingId、发动者、旧牌、新牌、来源区和取得／弃置政策 |
| `candidateCursor`／`finalizedCursor` | Checkpoint 后不重复询问改判者或判定后订阅者 |
| `cleanupOwner`／`cleanupPolicy` | 天妒取得、鬼道交换和默认弃置不能双重移动 |

最小窗口：

1. `JudgmentRevealed`：牌堆顶实体牌进入公开判定区。
2. `JudgmentReplacing`：冻结本次改判候选，从当前回合角色开始按行动顺序逐一询问；每个绑定一次，跳过也推进游标。
3. `JudgmentFinalized`：全部改判结束，冻结最终牌、有效花色和点数；界雷击、天妒等订阅在此运行。
4. `JudgmentCleaningUp`：所有判定后订阅完成，再将仍在判定区的最终牌按取得或弃置政策移动。

多人改判不能只保存座位列表。候选身份至少包含 SkillInstanceId、BindingId 和 occurrenceId；同一座位通过不同合法技能改判时不能由 `Single(SkillKind.Guicai or Guidao)` 猜测。

每次替换执行该绑定自己的牌移动政策：鬼道令发动者取得当时的当前判定牌；鬼才等默认替换令旧牌进入弃牌堆。之后若还有改判者，继续针对新的当前牌。所有移动及装备离场产生的合法子结算完成后，才推进同一个候选游标。

## 6. 现有实现差异

当前类型化实现可作为场景基线，但不能直接包装后宣称完成：

- `CollectJudgmentReplacementCandidates` 以判定目标座位传入排序器；目标规则要求以当前回合角色为同时机起点。
- `ResolveGuicaiChoice` 对鬼才和鬼道都把旧判定牌送入弃牌堆；经典鬼道应把它收入发动者手牌。
- 候选帧只保存座位，恢复后再按 `SkillKind` 查找技能，不能表达同座位多绑定和界鬼道的替换后摸牌。
- `_pendingLeiji` 只续接一次【杀】的闪响应；界雷击需要监听闪、闪电用牌及自己的所有判定结果。
- `JudgmentContinuationKind.Leiji` 把判定原因和效果续接写死，不能复用为界雷击的“判定”和独立“判定后订阅”。
- 现有经典包黄天仍以 `UsedActiveSkillKinds` 记录旧枚举；schema 7 已提供按提供者、技能拥有者、阶段和绑定记录的迁移目标，A51／A52 需要分别配置经典／界候选并完成内容版本差分。

上述修正必须只在新规则版本生效；恢复旧 rules 和旧内容哈希时继续走原实现，不能让历史回放因修正后的移动语义漂移。

## 7. 最小验收矩阵

### 7.1 经典等价与修正

- 实体闪、龙胆闪、八卦闪和无双双闪分别触发正确次数；丈八用两闪当杀不触发。
- 黑桃、梅花、红桃、方块四种最终判定；梅花满血仍造成 1 点雷伤；连环雷伤及濒死后恢复父响应。
- 鬼道手牌黑牌、装备黑牌、非法红牌；正在提供本次八卦判定的八卦阵被排除。
- 鬼道发动后，旧判定牌进入发动者手牌、替换牌成为当前判定；鬼才对照仍弃置旧牌。
- 两名改判者从当前回合角色起依次获得一次机会；第一人跳过或发动后均不会在第二人改判后再次询问。
- 黄天仅其他群角色、仅闪／闪电手牌、每提供者每出牌阶段一次；张角非主公、阵亡或失技时无入口。

除“鬼道取得旧判定牌”和“改判起点”这两个明确修正场景外，经典新配置应与旧路径做同种子事件、牌区、AI、Checkpoint/Replay 差分；两项修正则用新旧 rules 对照证明只在新版本改变。

### 7.2 界张角

- 使用／打出闪和使用闪电可选择自己判定；跳过不判定，牌 action 正常继续。
- 技能判定、八卦、闪电、乐不思蜀、兵粮寸断等自己的最终判定都只产生一次判定后绑定。
- 黑桃可选任一角色 2 雷伤；梅花先回复再可选任一角色 1 雷伤；其他花色无伤害选择。
- 界鬼道以黑桃 2、9 各摸一，以黑桃 A、10、梅花牌不摸；随后被再次改判也不回滚已摸牌。
- 界黄天接受闪或黑桃手牌，拒绝梅花非闪和黑桃装备；使用账本仍属于提供者。

### 7.3 国战、隐私与恢复

- 国战雷击黑桃生效、梅花无效果且无黄天；暗置不发布技能候选，明置后才可用。
- 改判候选手牌仅对技能拥有者可见；装备和已亮判定牌公开。鬼道取得公开判定牌后，公开移动可被观察，但其余手牌仍不泄漏。
- Checkpoint 覆盖每个改判 Choice、界雷击发动 Choice、最终花色分支 Choice、替换后摸牌、判定牌 cleanup 及雷伤濒死；恢复后 JudgmentId、候选游标、牌区和随机位置一致。
- Replay 从命令前缀重建相同替换历史和最终牌；不能使用单个 `_pendingJudgment`／`_pendingLeiji` 覆盖嵌套父帧。

### 7.4 WPF 与素材

- WPF 复用通用触发、改判、选目标和公开判定反馈，显示判定原因、当前判定牌、技能拥有者与父效果；不新增张角专页。
- 经典张角现有资源键和旧原创肖像保持兼容。工作树中的 BWIKI 经典候选正式绑定前需验证清单、WPF 解码、选将裁切和 1120×740 离屏画面。
- 界张角没有已锁定的独立立绘，不得把经典张角肖像无标识复用后冒充完成；注册界版本时另行记录来源并做视觉验收。
