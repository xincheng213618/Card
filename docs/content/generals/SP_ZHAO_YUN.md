# SP 赵云迁移规格

状态：目标版本、对抗上下文与场景已锁定；等待 D2 通用 `conversionChain`、用牌／响应触发窗口和暗手牌取得能力。未注册正式武将。

## 1. 内容身份与目标版本

本块只定义身份模式的经典 SP 赵云，不替换标准赵云、界赵云、神赵云或 JSP 赵云。

| 字段 | 目标值 |
| --- | --- |
| 武将 ID | `sp:zhao-yun` |
| 技能顺序 | `sp:longdan`、`sp:chongzhen` |
| 势力／性别／体力 | 群／男性／3 |
| 来源包 | 荟萃·往者可谏 |
| 当前接入范围 | 经典身份；欢乐、斗地主等模式等各自规则可用后再注册 |
| 进入默认池 | 龙胆和冲阵完整通过场景后一次性加入，不发布只有龙胆的半成品 SP 赵云 |

锁定文案：

- 龙胆：你可以将一张【杀】当【闪】、【闪】当【杀】使用或打出。
- 冲阵：当你发动“龙胆”使用或打出一张手牌时，你可以立即获得对方的一张手牌。

“龙胆”是可选的牌转换来源；“冲阵”是由一次已成立的龙胆动作触发、可拒绝的触发技。不能因为最终有效牌型是【杀】或【闪】就反推发动过龙胆，也不能把冲阵合并进龙胆的 `viewAs` 定义。

## 3. 统一牌动作上下文

D2 不能只在现有 `CardUseFrame` 或 `CardRespondedEvent` 上再加一个布尔值。每次使用／打出应提供稳定的 `CardActionContext`，至少包含：

| 字段 | SP 赵云用途 |
| --- | --- |
| `actionId`／`parentActionId` | 区分同一决斗、无双或青龙刀链中的多次独立动作 |
| `physicalCardIds` | 保留支付的原始手牌；冲阵要求本次龙胆确实使用或打出一张手牌 |
| `physicalKind`／`effectiveKind` | 杀→闪或闪→杀后仍能审计原牌种 |
| `conversionChain` | 明确包含 `sp:longdan` 的技能实例和转换节点；朱雀羽扇等后续转换继续追加而不覆盖 |
| `actorSeat` | 实际使用／打出有效牌的 SP 赵云 |
| `providerSeat` | 支付实体牌的角色；普通 SP 龙胆与 actor 相同，但不能据此删除字段 |
| `requesterSeat`／`responderSeat` | 保留护驾、激将及响应请求语义，不能把提供者误作有效使用者 |
| `opponentSeat` | 响应路径中由当前对抗上下文规范化的“对方” |
| `currentTargets` | 主动用牌经过目标变更后的最终目标快照 |
| `useOrResponse` | 区分主动使用、作为使用的响应和单纯打出，但三者均可被冲阵绑定 |

`conversionChain` 使用稳定 SkillId／SkillInstanceId；标准赵云的 `classic:longdan` 与 SP 赵云的 `sp:longdan` 必须不同。旧 `SkillKind.Longdan` 可以继续服务历史包，但不能让冲阵监听所有最终为杀／闪的动作。

## 4. “对方”映射

### 4.1 主动使用闪转化的杀

当 SP 赵云把一张手牌【闪】作为【杀】使用时，冲阵在目标最终确定后对每个仍存活且有手牌的最终目标分别建立候选：

- 单目标杀：对方是该最终目标。
- 流离改变目标：对方是流离后的目标，不是原目标。
- 方天画戟、天义等多目标杀：按规则确定的目标顺序逐个询问；每个目标至多一次，可分别发动或跳过。
- 借刀杀人要求 SP 赵云出杀：对方是该嵌套杀的最终目标，不是借刀杀人的使用者。
- 青龙偃月刀追加的新杀是新的 action；若也由 SP 龙胆转换，可再次产生冲阵。

触发顺序采用官方 FAQ：目标成为杀目标时的流离、享乐等先完整结算，目标集合稳定后再结算冲阵；即使享乐令该杀无效，已经成立的龙胆用牌仍可冲阵。冲阵完成后才进入雌雄双股剑等后续“指定目标后”效果及目标的闪响应。

若同一目标因非法重复输入在目标列表中出现多次，基础用牌校验应先拒绝；冲阵不承担目标列表去重。

### 4.2 打出闪转化的杀

SP 赵云以手牌【闪】经龙胆打出【杀】时，对方由当前响应请求确定：

| 响应原因 | `opponentSeat` |
| --- | --- |
| 南蛮入侵 | 该南蛮入侵的有效使用者，不是祸首重写后的伤害来源 |
| 决斗 | 本轮与 SP 赵云相互打出杀的另一方 |
| 离间创建的虚拟决斗 | 决斗的另一方，不是发动离间的貂蝉 |
| 其他正式“要求打出杀”窗口 | 由该窗口显式提供的对立角色；不存在对立角色时不产生冲阵候选 |

无双要求连续打出两张杀时，每一张由龙胆转换并成功接受的杀都是独立 action，各自可冲阵一次；第一张冲阵可能取空对方手牌，第二张应在发动前重检。

### 4.3 使用或打出杀转化的闪

SP 赵云以手牌【杀】经龙胆作为【闪】使用或打出时：

| 响应原因 | `opponentSeat` |
| --- | --- |
| 响应一张杀 | 该杀的有效使用者；提供实体牌的人、激将请求者和伤害来源字段不可混用 |
| 万箭齐发 | 该万箭齐发的有效使用者 |
| 其他正式“要求闪”窗口 | 该请求的明确引发者；没有引发者时不触发冲阵 |

冲阵在转化闪被接受后立即插入，在杀被闪抵消、猛进、雷击及原牌效果继续之前完成。无双要求两张闪时，每张经龙胆转换的闪分别产生一次候选。

## 5. 冲阵执行契约

1. 只有 `conversionChain` 明确包含当前 SP 赵云技能实例的 `sp:longdan`，且本次动作支付恰好一张其手牌时，才收集候选。
2. 发动前重检 SP 赵云仍具备发动资格、对方仍存活且仍有手牌；无牌时不创建无效果 Prompt。
3. Prompt 属于 SP 赵云。其可以跳过，或从仅包含不透明手牌槽位的私有候选中选择恰好一张。
4. 选中的实体牌从对方手牌区经受控移动进入 SP 赵云手牌区；移动原因、actionId、技能实例和双方座位进入可信账本。
5. 公开事件只包含发动与否、双方座位和数量；牌面只对原持有者、获得者与可信宿主可见。其他观察者不得从候选顺序、日志或回放快照恢复牌面。
6. 取得牌及其安全边界触发完整结束后，恢复原用牌／响应 action；不重复消费龙胆实体牌，不提前结算杀、闪或锦囊效果。
7. 候选已开始后 SP 赵云失去技能的处理服从通用 continuation policy；已发动并选牌的移动不因随后失技回滚。

人类界面可以把“发动／跳过”和不透明手牌槽位合成一个原子 Choice，但运行时仍需保存候选 action、opponent、是否已提交和所选实体牌。过期、伪造对方、伪造槽位和重复回答必须原子拒绝。

## 6. 最小验收矩阵

### 6.1 来源识别

- SP 赵云闪转杀、杀转闪均触发；自然杀／闪不触发。
- 标准赵云 `classic:longdan`、其他配置技能的杀闪转换、倾国、武圣、丈八蛇矛、八卦阵及无实体杀都不误触发。
- 闪经 SP 龙胆转普通杀后再由朱雀羽扇转火杀，仍因转换链包含 `sp:longdan` 触发一次；不能因链中两次转换触发两次。
- 只有手牌可作 SP 龙胆输入；装备区杀／闪和他人提供的实体牌不被配置偷偷放宽。

### 6.2 主动用牌

- 单目标转化杀：冲阵在目标响应闪和伤害前取得手牌。
- 流离：只从重定向后的最终目标取得；原目标不出现 Prompt。
- 享乐：先支付／拒绝基本牌，再冲阵；即使杀无效也保留冲阵资格。
- 雌雄双股剑：冲阵先取得牌，随后目标的弃牌／令来源摸牌选择按冲阵后的实时手牌继续。
- 方天画戟或天义多目标：按目标顺序分别发动／跳过；前一目标的取得不会污染后一目标候选。
- 借刀嵌套杀与青龙刀追加杀分别保持自己的 actionId、对方和父结算。

### 6.3 响应

- 南蛮入侵：对方是锦囊使用者；孟获祸首只改伤害来源，不改变冲阵对方。
- 普通决斗和离间决斗：对方均为当前决斗另一方；多轮龙胆杀逐次触发。
- 响应普通杀的龙胆闪：对方是杀使用者；冲阵先于杀被闪抵消后的猛进等效果。
- 万箭齐发：对方是锦囊使用者。
- 无双双杀／双闪：每个成功接受的转化响应各触发一次，且第二次读取实时手牌。
- 响应失败、卡牌未被接受或 Prompt 已过期时，不产生冲阵和牌移动。

### 6.4 隐私、AI 与恢复

- 有多张暗手牌时仅 SP 赵云看到不透明槽位；其他玩家快照、事件和日志不含牌面。
- 对方无手牌时不建立 Prompt；仅一张手牌仍保持统一私有选择语义。
- AI 只能依据公开阵营、公开手牌数和 action 上下文决定发动，再用确定性随机／不透明槽位选择，不能读取真实牌面。
- Checkpoint 分别停在每个冲阵发动 Choice、暗手牌 Choice 和牌移动后的父 action；恢复后每个 opponent 只结算一次，随机位置、移动账本和下一响应一致。
- 多目标、无双和决斗多轮场景保存 actionId、候选游标与 opponent，不以单个全局 `_pendingChongzhen` 覆盖嵌套状态。

### 6.5 内容与界面

- `sp:zhao-yun` 精确为群／男性／3 体力，技能顺序龙胆、冲阵；不改变 `classic:zhao-yun` 的定义或旧内容哈希。
- 新规则和内容包版本保留 rules v79／`standard-composed-skills@1.0.0` 及经典包历史版本的读取路径。
- WPF 使用通用触发／暗牌选择面，清楚显示当前对方和父牌效果；战场公开反馈不显示所得暗牌牌面。
- 工作树已有 `sp-zhao-yun` 的 BWIKI 经典形象候选；正式绑定前验证资源清单、WPF 解码、选将卡裁切和 1120×740 离屏画面。技能未完成前不单独把肖像对应的半成品武将加入池。

## 7. 实施拆分与完成门槛

| 顺序 | 通用功能块 | 完成门槛 |
| --- | --- | --- |
| D2a | `CardActionContext`、稳定 actionId、`conversionChain`、actor/provider/requester/responder/opponent | 普通/SP 龙胆、武圣、倾国、激将／护驾提供者在测试中不混淆 |
| D2b | `CardUseTargetsFinalized`／`CardResponseAccepted` 可暂停窗口、同一时机优先级和多目标游标 | 流离／享乐先于冲阵，冲阵先于武器与原效果；无双、决斗可嵌套恢复 |
| D2c | 通用 `obtainOpponentHandCard` 与脱敏事件 | 不透明槽位、原子移动、AI、Checkpoint/Replay 全部通过；至少再有一个非冲阵测试组合复用 |
| A50 | `sp:longdan`／`sp:chongzhen` 配置与完整 SP 赵云 | 不新增 SP 赵云专属 `SkillKind`、引擎分支或 WPF 页面，完整武将才进入当前池 |
| C20 | 经典肖像正式绑定 | 来源记录、解码断言、卡面裁切和离屏视觉复核齐全 |

当前 `CardUseFrame` 只有来源、有效牌型、目标和实体牌列表；`ResponseWindowFrame` 只有来源、响应者和所需牌型；`CardRespondedEvent` 也只带实体牌、响应者、来源和最终有效牌型。这些字段不足以辨认 `sp:longdan`、流离后的每个对方或决斗／南蛮中的规范化 opponent。D2 应补通用 action 上下文，不在既有各条杀／闪分支中逐处调用冲阵。

本文件是内容任务交给通用运行时任务的可执行规则与场景契约。最终基础能力名称可以调整，但目标版本、选择主体、多目标次数、先后顺序、暗牌隐私与旧内容边界不得改变。
