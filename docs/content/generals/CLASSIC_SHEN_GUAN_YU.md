# 经典神关羽迁移规格

状态：目标版本、技能标签、梦魇标记、死亡窗口和直接死亡语义已锁定；rules v90～v93 已完成 D4a～D4c 的合成运行时验证。武神、武魂正式配置及整将注册仍未完成，不把半成品神关羽加入当前经典身份池。

## 1. 内容身份与版本边界

本仓库目标是 BWIKI 记录的“正式服 I 版”，内容 ID 和稳定顺序如下：

| 项目 | 锁定值 |
| --- | --- |
| 武将 | `classic:shen-guan-yu`／神关羽 |
| 势力／性别／体力 | 神／男性／5 |
| 武将包 | 神话再临·风 |
| 技能顺序 | `classic:wushen` 武神、`classic:wuhun` 武魂 |
| 适用规则集 | 经典身份；欢乐、自走棋、国战等产品线不由本定义外推 |

目标文案：

- 武神（锁定技）：你的红桃手牌均视为【杀】；你使用红桃【杀】无距离限制。
- 武魂（锁定技）：当你受到 1 点伤害后，你令伤害来源获得 1 枚“梦魇”标记；当你死亡时，你令“梦魇”标记最多的一名角色进行判定，若结果不为【桃】或【桃园结义】，该角色死亡。

不能混入以下后续版本：

- 三国杀 OL 当前页所载武神还有“无次数限制且不能被抵消”；BWIKI 当前版本另有红桃杀造成伤害后摸牌。正式服 I 版两者都没有，仍受通常出杀次数限制，也保留通常的响应和防具链。
- BWIKI 当前版本武魂在神关羽造成伤害时也给受伤角色梦魇。正式服 I 版只处理神关羽受到的伤害。

“神”是印刷势力；若经典身份规则要求神武将在开局选择魏／蜀／吴／群作为本局势力，该选择应由通用开局势力能力实现并写入规则指纹，不能把神关羽硬编码成某一势力，也不能令旧存档的势力字段漂移。完成该模式规则核对前，神关羽只用于受控 D4 场景，不进入默认随机池。

## 2. 规则来源与证据等级

主要依据：

- [BWIKI 神关羽](https://wiki.biligame.com/sgs/%E7%A5%9E%E5%85%B3%E7%BE%BD)、[武神](https://wiki.biligame.com/sgs/%E6%AD%A6%E7%A5%9E)与[武魂](https://wiki.biligame.com/sgs/%E6%AD%A6%E9%AD%82)保存正式服 I 版文本和规则集问答，是本次旧版本目标的主要结构化来源；BWIKI 是社区维护资料，不冒充官方发布物。
- [BWIKI 技能概念介绍](https://wiki.biligame.com/sgs/%E6%8A%80%E8%83%BD%E6%A6%82%E5%BF%B5%E4%BB%8B%E7%BB%8D)用于约束“锁定技”标签与状态技／触发技执行形态分开建模。锁定技标签本身不授予优先级，也不能替代发动时机和强制性定义。
- [三国杀 OL 当前神关羽页](https://www.sanguosha.com/hero/201)是当前官方文本，只用于证明当前版与目标旧版不同，不作为正式服 I 版增补规则的依据。
- [QSanguosha-v2 神关羽实现](https://github.com/Mogara/QSanguosha-v2/blob/master/src/package/god.cpp)用作可检查的早期实现交叉核对：红桃手牌过滤为普通杀、红桃杀放宽距离、致死前按实际伤害点数加梦魇、自伤和无来源伤害不加标记、零标记不发动、并列由死者选择、普通判定可改判、失败后无伤害原因直接死亡、结算后清空梦魇。它不是所有官方版本的统一规则依据。
- QSanguosha-v2 的 [Room::killPlayer](https://github.com/Mogara/QSanguosha-v2/blob/master/src/server/room.cpp)和[身份模式 GameRule](https://github.com/Mogara/QSanguosha-v2/blob/master/src/server/gamerule.cpp)仅用于核对可实现顺序：角色先被标记死亡并进行胜负检查，未结束才发布 Death，随后才 BuryVictim 和奖惩。这与 BWIKI“已经符合游戏结束条件则武魂不发动”的问答一致。

## 3. 技能标签与执行形态

武神和武魂都带 `locked` 标签，但执行机制不同：

- 武神包含持续生效的手牌牌名修正和红桃杀距离修正，是状态技绑定；没有“发动／跳过”提示。
- 武魂包含“实际伤害提交后加标记”和“拥有者死亡时复仇”两个强制触发绑定；并列选人仍是规则要求的选择，不把整个锁定技错误做成可跳过。
- `locked` 只进入技能标签集合。候选冻结、同时机排序、失技后的 continuation policy 和是否发布 Choice 均由各绑定明确定义。

不能新增 `WushenFrame`、`WuhunFrame`、神关羽专属 Prompt 或 WPF 页面。内容配置应复用通用 `transformCardIdentity`、`modifySlashDistance`、`addMark`、`selectMaxMarkHolder`、`judge`、`causeDeath` 和 `clearMark` 能力。

## 4. 武神精确规则

### 4.1 红桃手牌牌名修正

1. 神关羽手牌区内每一张实体红桃牌均持续视为普通【杀】，不是玩家可选的转换入口。
2. 原牌可以是基本牌、锦囊牌、装备牌、普通杀、火杀或雷杀；成为有效牌后统一是普通杀。红桃火杀对藤甲不产生火焰伤害。
3. 修正只在神关羽自己的手牌区生效。已经位于装备区、判定区、牌堆、弃牌堆或他人区域的红桃牌保持原牌名。
4. 红桃【赤兔】在神关羽手牌中只能按杀使用，不能从手牌执行装备动作；若其他合法效果把它直接置入神关羽装备区，它仍是赤兔。
5. 红桃【桃】在神关羽手牌中也不是桃，不能在出牌阶段回复或在濒死救援中使用。离开其手牌区并由其他角色取得后，恢复物理牌原名。
6. 选择动作时先在手牌区计算并冻结有效牌名、花色、点数、物理牌 ID 和 `classic:wushen` 修正 occurrence，再把实体牌移入 Processing。不能因为移出手牌后修正条件消失而让同一次 action 途中变回原牌。

物理牌信息必须保留：花色、点数和原牌名用于审计、移动、展示及只读取实体属性的规则；用牌合法性、目标、响应和伤害则读取冻结后的普通杀身份。事件和回放同时记录物理牌 ID、物理牌名、有效牌名与修正绑定，不能只覆盖卡牌对象。

### 4.2 红桃杀距离修正

1. 神关羽使用由自己红桃手牌形成的有效杀时忽略距离限制；自然红桃杀也属于该范围。
2. 该修正只改变 `distanceLimit`。正式服 I 版仍受出牌阶段每回合通常一次的杀次数限制，仍能被【闪】响应，并照常经过仁王盾、藤甲、八卦阵、青釭剑等目标效果。
3. 距离修正不改变目标数量、是否计入次数、是否可响应、是否可抵消或伤害属性。通用修正器必须分别表达这些规则项。
4. 非红桃杀和其他来源的无实体杀不获得武神距离放宽。已经被合法转换为普通红桃杀的 action 以冻结的有效花色和修正来源判定，不能仅凭最终牌名猜测武神。

## 5. 武魂伤害标记

### 5.1 绑定时机

武魂的加标记绑定订阅 `DamageCommittedBeforeDying`：实际伤害已确定并扣减，伤害来源、目标、属性和实际点数已经冻结，但尚未进入本次伤害造成的濒死救援。

1. 只处理目标为该武魂拥有者且实际伤害点数大于零的 Damage。
2. 每 1 点实际伤害令伤害来源获得 1 枚梦魇；一次 2 点伤害连续发布计数 1→2 的两个稳定事件，便于逐点审计与确定性重放。
3. 致死伤害也先加标记再进入濒死，因此最终杀死神关羽的来源参与武魂最大值比较。
4. 防止到 0 的伤害、失去体力、体力上限变化和 `causeDeath` 都不是 Damage，不加梦魇。
5. 没有来源的伤害不加标记；伤害来源就是神关羽本人时也不加标记。后者是正式服 I 版实现目标选择，依据早期开源实现交叉核对并由独立场景锁定，不能从现行版“造成／受到伤害”文本反推。
6. 加标记是强制绑定，不询问拥有者；即使本次伤害随后令其死亡，已经提交的增量也不能回滚。

### 5.2 梦魇标记定义

`classic:nightmare` 使用通用 `MarkStore`，定义至少包含：

| 属性 | 值 |
| --- | --- |
| 数据类型 | 非负整数 |
| 持有者 | 玩家座位；存活和死亡状态都可保存 |
| 可见性 | 对所有玩家公开，WPF 显示名称和数量 |
| 作用域 | 对外显示本局同名标记合计；可信运行时按武魂拥有者座位分桶 |
| 增量来源 | DamageId、武魂 binding occurrence、伤害来源／目标和实际点数 |
| 清理 | 一次已开始的武魂复仇链完成后，只从所有玩家合计中扣除该武魂拥有者贡献的来源计数；若更早的模式胜负检查已经终局，则不再开启复仇链 |

公开合计沿用同名梦魇的桌面表现，来源分桶则避免多个武魂实例互相借用或提前清除对方标记。普通玩家快照不公开来源分桶，只有可信规则在死亡候选与清理时读取；受控嵌套场景验证内外两名武魂拥有者分别使用自己的来源账本。

## 6. 武魂死亡复仇

### 6.1 死亡窗口顺序

经典身份的目标顺序为：

1. 濒死救援全部失败，提交死亡；受害者 `IsAlive=false`、体力归零并公开身份，完成区域清理和身份模式奖惩。
2. 模式规则立即执行胜负判定。若主公死亡、最后胜负阵营已经确定或其他经典身份终局条件成立，发布胜者并终止后续死亡技能，武魂不发动。
3. 未终局且存在合法来源候选时，压入 `DeathSkillFrame`；武魂拥有者保留技能身份和控制者，不能因 `IsAlive=false` 丢失已冻结候选。
4. 死亡技能判定、可能的嵌套直接死亡和来源标记清理全部完成后，弹出死亡技能与死亡帧并恢复父结算。

rules v92 保留既有普通死亡的区域清理、奖惩与胜负顺序，只把仍未终局的死亡技能续接改为可暂停帧；旧 rules 不创建该帧。

### 6.2 候选、选择与判定

1. 候选只包含神关羽以外仍存活且该神关羽来源梦魇大于零的角色。已经死亡的角色不参与最大值比较。
2. 读取可信来源分桶，保留该来源梦魇最大值的全部角色；普通快照仍只显示合计。所有人都是 0 或候选为空时，不发布 Choice、不进行判定，也不建立无效果子帧。
3. 已死神关羽的可信控制者从冻结候选中选择一人；即使只有一个候选，真人仍收到只有一个合法答案的私有 Prompt，AI 按稳定座位选择。提交沿普通 Choice 防伪和恢复边界。
4. 对选中角色发起原因 `skill.wuhun.death` 的普通判定。判定对象是被选角色；鬼才、鬼道及后续通用改判绑定可以按 D3 同时机规则参与。
5. 所有改判完成后读取最终有效牌名。最终为【桃】或【桃园结义】则目标存活；其他任何牌名均执行 `causeDeath`。
6. 判定牌按通用 D3 cleanup policy 移动；武魂不能自行复制、弃置或取得判定牌。
7. 判定存活或直接死亡的嵌套死亡链完成后，从所有玩家的公开合计中扣除本次神关羽来源的梦魇，再继续原死亡链。Checkpoint 恢复不能重复选人、重复判定、重复直接死亡或重复清标记。

### 6.3 `causeDeath` 契约

`causeDeath` 是通用生命周期能力，不得用 999 点伤害或把体力改为极小值模拟：

- 不生成 Damage，不触发伤害防止、伤害后技能、连环传导或梦魇增量。
- 不进入普通濒死和桃／酒救援；目标直接进入与模式相符的死亡提交、终局检查、死亡技能和清理链。
- 保存 `causeId`、父 resolutionId、技能实例、施加者座位和目标座位用于审计；但武魂直接死亡没有 Damage killer。经典身份不因此发放击杀反贼三牌，也不执行主公误杀忠臣惩罚。
- 被直接死亡的角色仍可拥有自己的合法死亡技能；嵌套 `DeathFrame` 必须压栈并在完成后返回武魂复仇游标。
- 若嵌套死亡触发模式终局，立即完成对局，不再为了清标记或原受害者奖惩创建玩家可见的新动作。终局快照仍应保持已经提交的牌区、判定和死亡事实一致。

## 7. 通用 D4 上下文

### 7.1 Damage 上下文

`DamageContext` 至少保存：

| 字段 | 用途 |
| --- | --- |
| `damageId`／`parentResolutionId` | 标记增量去重并恢复父牌效果 |
| `sourceSeat`／`targetSeat` | 区分无来源、自伤和正常来源 |
| `declaredAmount`／`actualAmount` | 只按防止和修正后的实际点数加标记 |
| `nature`／`cardActionId` | 审计属性伤害、连环和来源牌 |
| `committed`／`dyingStarted` | 保证标记位于伤害提交后、濒死前且只执行一次 |
| `triggerCursor` | 多个技能实例及同一窗口候选的确定性顺序 |

### 7.2 Death 上下文

`DeathContext`／`DeathFrame` 至少保存：

| 字段 | 用途 |
| --- | --- |
| `deathId`／`parentResolutionId` | 嵌套死亡和返回点 |
| `victimSeat` | 当前死亡角色 |
| `damageId`／`killerSeat`／`causeId` | 区分伤害死亡、无来源死亡和直接死亡；奖惩只读合法 killer |
| `modeGameOverChecked`／`gameOverResult` | 经典身份先于死亡技能的终局门 |
| `frozenSkillOccurrences`／`triggerCursor` | 已死拥有者资格、同时机排序和恢复去重 |
| `cleanupCursor` | 分区弃牌、技能注销、奖惩及父帧恢复 |
| `continuationPolicy` | 候选冻结后失技／死亡是否继续；武魂为 `continueOnceStarted` |

公开事件至少区分 `MarkChanged`、`DeathCommitted`、`DeathSkillTargetChosen`、`CauseDeathCommitted`、`DeathCleaningUp` 和 `NightmareMarksCleared`。私有 Choice 只向已死拥有者的可信控制端公开候选提交能力；所有候选座位和标记数量本身是公开信息。

## 8. 最小验收矩阵

### 8.1 武神

- 红桃杀、桃、桃园结义、赤兔、火杀、雷杀分别从手牌形成普通杀；黑桃杀保持原样。
- 红桃火杀对藤甲不造成火焰伤害；物理牌仍记录原名、红桃和点数。
- 手牌赤兔不能装备；被其他合法效果直接置入装备区后作为赤兔生效。
- 红桃桃不能用于正常回复或濒死救援；转移给其他角色后恢复为桃。
- 红桃杀跨距离合法，但同一出牌阶段第二张杀仍被次数限制拒绝；目标仍能以闪、八卦等响应。
- 在实体牌移入 Processing 后恢复 Checkpoint，有效普通杀和武神 occurrence 不丢失、不回退成原牌。

### 8.2 梦魇

- 1 点和 2 点实际伤害分别增加 1／2；致死 2 点在进入濒死前已经增加 2。
- 被防止伤害、失去体力、无来源伤害、自伤和 `causeDeath` 均不增加。
- 连环伤害分别按各自 DamageId 和实际来源处理，不因父牌相同合并。
- 标记数量、增量和持有者公开；Checkpoint/Replay 恢复后不重复增加。

### 8.3 死亡复仇

- 全场零梦魇不发动；单一最高值自动选；多人并列由已死神关羽选择。
- 最终判定为桃、桃园结义、其他牌三类；鬼才／鬼道可改判且只读取最终牌名。
- 致死伤害来源因最后一击新增梦魇后成为最高值，必须进入候选。
- 神关羽作为主公死亡，以及无内奸时最后一名反贼死亡等已经满足终局条件的场景，均先结束游戏且不发动武魂。
- 直接死亡不进入濒死、不触发伤害类技能、无击杀奖惩；目标自己的死亡技能可以嵌套执行。
- 武魂目标直接死亡但游戏继续时，嵌套死亡完成后只清除当前拥有者来源的梦魇，再完成原神关羽死亡帧。
- 两个受控武魂实例对外共享梦魇合计、内部来源独立；内层完整复仇并清理自己的来源后，外层仍能恢复并只清理外层来源。

### 8.4 隐私、AI、恢复和界面

- 梦魇和最大值候选公开；并列选择提交只属于神关羽控制者。AI 只按公开身份关系、胜负目标和梦魇值决定并列目标。
