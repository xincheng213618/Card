# 技能程序 schema 54：实体牌条件、伤害牌选项与摸牌计划

本批对应 rules 164、`standard-classic-generals@1.139.0`，Checkpoint schema 仍为 3。朱桓（2014 诱敌版）、界曹操（2014 选择版）、界张辽（2018 版）是首批消费者。护驾复用通用 `SkillKind.Hujia`，不计为全程序迁移。三人进入普通五／八人身份池和对应图鉴；界张角试验池保持原范围。

## 公共条件与选择

`boundCardsMatchKinds` 读取一个更早的实体牌绑定，要求绑定非空且全部物理 CardKind 都属于给定集合；支持 all／any／not 递归。`cardKinds` 必须非空、互异、已知，来源绑定须通过资源校验。它检查物理牌型，不以基本牌类别或后来获得的有效牌身份替代。诱敌据此区分普通杀、火杀、雷杀与其他牌，两个角色的暗手选择沿用私有程序提示。

`hasClaimableDamageCards` 仅用于 afterDamageApplied 中由拥有者选择的选项条件，不可冒用为主动、摸牌或其他入口的事实。选项生成、提交和 claimDamageCards 共用同一查询：程序必须属于当前父伤害窗口，候选只含该伤害实体牌中仍在 Processing 的牌。提交失效选项在改变命令日志、绑定和牌区之前返回 InvalidChoice，实际领取再次确认。移动之前冻结父伤害引用，避免嵌套事件改变 pending 上下文后错误归属。

伤害技能的启动预检只提前求值无需程序帧的公开拥有者条件。choiceIs、绑定牌条件、布尔状态等需要帧的条件留到指令执行时处理；不能用“包含 choiceIs”这一特例代替依赖判断。无条件领取保留原有可领取牌预检。

## 摸牌计划与目标集合

`selectTargets.numberExpression: plannedNormalDrawCount` 读取当前正常摸牌计划，包括更早的加减摸牌；可选数同时受配置上限和实际合法目标数约束。该表达式需要 DrawPlan 上下文。新使用者冻结基础摸牌数，后续继续累加公共调整；此前 replacement 已取代摸牌时不再开放这个选择。旧图不使用新表达式时仍保持原有路径。

`otherLivingHandAtLeastOwner` 只按公开手牌数量选取其他存活且非空手的角色，人数资格在选择开始时固定。逐人取得手牌时只重验存活及可取牌，不因先取一张后拥有者手牌数增加而取消后续目标；已经无牌或死亡者跳过，事件只列实际取得牌的目标。

`adjustNormalDraw.numberExpression: selectedTargetCount` 减少已选目标数对应的普通摸牌，不能同时指定固定 amount。它读取一个更早的目标集合；扣数依据选择人数，不因随后实际取牌减少而返还。目标谓词、动态上限、扣数分别验证资源与入口；不要求固定“三节点配方”，也不要求后面必须有取牌操作。

## 版本、AI 与验收

新字段在 schema 53 及更早版本拒绝。既有枚举值不重排，schema 54 最低引擎能力为 164；新三人的注册门槛固定为 1.139.0，不绑定会变化的 CurrentVersion。

公共 AI 以公开目标数量估计所选集合和摸牌扣数；暗手牌不泄露到评分。参与者相对的“从选中目标取一张牌到拥有者手中”现在同时计入拥有者收益和目标损失，这也修正已有拒战的评分。由于同一旧内容和命令的 AI 决策会改变，本批提升 rules 164；增加三名武将本身不是升版理由。内容哈希继续隔离新增定义，存档要求规则版本、Checkpoint schema、包签名和内容哈希全部精确匹配。

实际验收和耗时见 [第三批记录](../../benchmarks/2026-09-26-capability-generals.md)。独立工作进程、父审补验和整批回归分别计时；定向通过、离屏图与整批验收分别记录，不把它们当作实机或多 DPI 验证。
