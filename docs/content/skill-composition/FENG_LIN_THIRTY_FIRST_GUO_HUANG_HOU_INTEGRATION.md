# 界郭皇后：当前规则与静态接入记录

当前 726 武将及矫诏、殚心已按完整能力接入，使用当前主文本及匹配的官方公告来源。规则包含真实使用历史驱动的牌名、分层转换、共享轮次限额、殚心实际摸牌子结算后升级，以及最高层零实体牌的基本牌和普通锦囊使用。这里记录源码接入与交叉静态复核；本批未编译、未加载规则、未运行 Core/WPF 检查或游戏，尚无运行验收结论。

## 规则边界

- 低层转换实际支付自己的实体牌；最高层使用公开标记的零实体动作，保留原牌种、转换来源、实际使用主体及原续接归属。没有伪造实体牌 0 或虚假牌移动。
- 零实体牌使用覆盖现有十八种基本牌和普通锦囊输出；无懈、闪、自救、借刀及青龙强制使用沿实际提示和原结算父窗口续行。仅“打出”的提供牌不冒充一次真实使用。
- 殚心先按已经完成的修改数确定 X，完成实际摸牌及其子结算，再进行允许的升级。X 为 0 不产生虚假摸牌或移动事件；失去原来源时不撤销已经付出的真实摸牌。
- HE 材料、杀家族牌名归一、永久层数、重授及额外回合共享轮次限额、两次修改上限及最高层行为属于明确记录的工程默认值，不能当作已取得的官方 FAQ 或运行验证。
- 玩家视图继续使用按观看者准备的快照；诊断结算栈不作为公开 UI 数据源。原版本、存储兼容性和旧实体使用路径保持原边界。

## 续接修正与界面

完整动作值比较保留原动作身份、来源、材料和有序目标。先前审查曾推测 checkpoint JSON 会分别反序列化 pending action 并造成引用别名失败，这个因果判断已撤回：checkpoint 保存已接受命令，恢复会重放实际 producer。本批的完整值比较是返回契约修正，没有复现该冷恢复别名故障。

实际已生效的转火杀策略按其原政策和真实事实证明转换，保留原付款及限额记录。闪及无懈的未完成转换收据在所属父结算上验证，完成后按真实返回点退休，不能仅靠任意同 ID 窗口通过校验。

奔袭和原目标追加的四处实际目标修改同步同一个已签发零实体锦囊的窗口动作；同步保留候选、上下文、游标和原锦囊返回，只对这项新能力生效。普通锦囊实际返回继续验证完整动作值。

WPF 使用已有公开动作按钮展示零实体动作，复验当前合法动作后选择目标、取消或确认。确认沿原 `PlayCardCommand` 提交牌种、目标牌、有序目标和全部转换来源，不创建实体牌 0 的牌面。已有响应提示按钮继续按原 ChoiceId 回答。

UI 原检查稿误写了不存在的 `CardZone` 枚举名，交叉源码审查定位后按当前 API 改为 `CardZoneKind`。原冻结交付保留，主区采用独立的小修正版；这项静态修正不表示编译已经通过。
