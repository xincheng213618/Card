# 牌绑定、移动与拥有牌区

实体位置由牌区存储和统一移动入口维护。内容侧通用边界见[卡牌移动契约](../CARD_MOVEMENT_CONTRACT.md)，程序入口见[运行时](RUNTIME.md)。

## 具名绑定

`captureSelectedCards`、区域捕获、亮牌、私有看牌、判定结果及实际摸牌可通过 `resultBind` 产生牌集合。绑定保存真实实体与声明时的来源，不用数量替代牌。`sourceBind` 引用已有结果，`exceptBind` 等集合操作只能组合合法来源。

`selectCardSubset` 从绑定中选择子集；`allowFewerWhenInsufficient` 是显式的来源不足策略，默认不会自动放宽其他技能的最低数量。完整排列、私有顺序选择与普通无序子集分开校验，不能含重复或漏牌。

`boundCardsMatchKinds`、类别/花色过滤、同色及绑定数量都使用对应的实体事实与有效牌面规则。绑定有效不意味着实体永久留在原区域；消费时复验真实当前位置和已消费身份。

## 移动与付款

`moveBoundCards` 将允许的实体移到明确目的地；实际移动先整体验证来源、目标、重复 ID 和装备槽位，再整体生效。`awaitMovementTriggers` 为受支持的目的地声明等待移牌后子结算，完成后返回原程序帧。不同操作的目的地与可等待组合由描述符限制。

`selectAndMoveOwnedCard` 明确 `cardOwnerRef`、`zones`、牌型/花色过滤、目的地及接收者。自己的精确手牌和他人的不透明手牌位使用不同私有投影。手牌观察不自动授权移动；公开装备/判定牌的精确 ID 也不授权读取其他区域。

`selectedTargetCorrespondingZone` 把判定区牌放入接收者判定区，或装备牌置入其对应装备槽；`targetRef` 必填。装备/判定区是其基础来源；允许手牌来源时，必须仅筛选装备类别并声明 `prohibitReplacingEquipment: true`，例如直谏。槽位合法性、已有装备处理与离场后果由原生规则负责。置入不是一次使用装备牌，不能伪造装备使用触发。

实际弃置、处理中转、整区弃牌调用、装备替换和特殊牌区清理各有语义。按“弃置”触发的技能不能把相邻的获得或木牛粮自动清理拼进同一弃置；按“获得装备”触发也不能仅匹配手牌目的区。

## 公开与私有牌堆

Authority、Field、创、PrivateReserve 等拥有区域按已注册能力管理，数量公开程度、牌面可见者、清理与返还分别声明。不能凭技能文案中的“所有牌”把这些区域自动并入普通手牌/装备/判定区集合。

牌堆顶/底的私有看牌与重排保存实际租约、顺序和来源。`drawPileBottom` 需要准确剩余集合及完整排列；牌源不足按明确配置处理。私有牌面只投影给有权角色，公开移动只发布允许的数量或牌面。

七星、谦逊的查看与选择界面见[私有牌堆交互](PRIVATE_RESERVE_INTERACTION.md)。只读查看不提交规则命令，已提交的部分选择通过原 Prompt 恢复，本地预览不能改变实体位置。

## 死亡、失源与恢复

死亡牌清理申领、原用牌材料领取和装备转交都要保留精确父动作/移动批次/来源区。另一批次恰好涉及同一实体，不证明本次费用已经支付。

已经完成的移动和其收据保存在拥有帧。装备离场的回复、获牌的后续窗口、濒死与死亡结束后沿原生类型化返回继续；不重复选择、移动、收费或把失源当作回滚理由。

玩家快照、事件与 AI 候选各自按权限投影。玩家快照和提交事件的嵌套集合在投影与提交准备阶段冻结；帧内集合由对应机制按具体合同管理，`IReadOnlyList` 或 record 本身不保证复制冻结。`ResolutionStack` 是可信诊断，Checkpoint 通过命令前缀重放重建状态，不直接从诊断帧 JSON 恢复。
