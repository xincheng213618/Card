# 规则修正、状态与真实时间边界

查询、状态、触发和主动入口分别声明，不能从“锁定技”等标签生成执行行为。入口见[运行时](RUNTIME.md)，元数据见[技能标签与状态](SKILL_METADATA_V1.md)。

## 查询与持续规则

`modifiers` 声明 `query`、`operation`、数值/表达式、条件和必要来源。常见查询包括摸牌数、手牌上限、杀次数、双向距离、杀/用牌距离、攻击范围及目标数。`add`、`set`、`unlimited` 的允许范围由对应查询约束；无限距离不自动等于无限次数。

解析器校验纯查询依赖，查询过程不推进规则、不消耗随机数、不修改状态。动态数值可读取允许的公开角色事实、拥有区域数量、标记或真实使用账本。多个修正的确定顺序由当前查询归约器维护。

`damageModifiers` 与临时伤害授予明确牌种、来源作用域、条件和金额。`cardPolicies` 声明响应限制、防具忽略、救援及目标等特定策略，不能用一项策略偷带另一项语义。

## 额度与状态

次数账本按明确用途及事件、实际阶段、实际回合、轮或整局作用域维护。额外阶段具有独立阶段身份；额外回合不自动推进真正的新轮。技能实例变化是否刷新额度由该能力的身份合同决定，不能用新实例绕过稳定技能额度。

`states` 保存转换面、布尔状态等明确规则状态。技能重置只修改声明的状态和额度；失去、重获、派生授予、永久成长和已发行义务各自保存其来源及期限。

`changeAttributedMarker` 等归属标记保留拥有者/施加者来源，公开快照可只显示合计。候选选择、到期和清理读取对应来源，多个同名技能不会互相覆盖或清除。

## 摸牌计划与选择组

`DrawPhaseStarting` 相关触发可选择加量计划或替代正常摸牌。成功替代终止相应后续候选并跳过普通摸牌，跳过替代继续剩余候选与一次正常摸牌。动态数值、亮牌、私有子集及牌堆顺序都属于原计划帧。

`choiceGroup` 表达互斥方案，例如将驰选择多摸并禁杀，或少摸并放宽杀。`orderGroup` 用于受支持的结束阶段可选触发顺序：同拥有者、同优先级、连续且仍可执行的成员可任选先发动，剩余成员保留后续机会。它不表示互斥。

## 跳过、插入阶段与额外回合

`skipTurnPhases` 仅在受支持窗口接受允许的阶段值。当前阶段跳过、额外阶段、正常流程恢复与额外回合分别保留实际帧和游标；不靠 UI 阶段文案推断真实边界。

巧变配置使用的判定/摸牌跳过入口及出牌后续点见[当前规则文件](../../../src/Characters/zhang-he/classic/Skills/classic-zhang-he.rules.json)。这种窗口选择的实现时点需要按实际配置描述，不能从官方“阶段开始”文字推定引擎在同一时点询问。

`pendExtraTurn` 之类操作把额外回合排入原生调度，来源、待执行顺序及已发行身份保存在所属结算。翻面跳过、终局和拥有者死亡按调度合同处理，不能复制一份独立 pending 队列。

## 精确期限与债务

`roundEnding` 在旧轮最后一个实际回合的 `afterTurnEnded` 及其子结算结束后、实际回合游标归还前打开。原生调度已有存活的待执行额外回合时，先执行该回合；下一普通回合将重复进入本轮已行动座位时才结束旧轮，死亡和翻面跳过按实际调度位置判断。

`RoundEndingBoundaryFrame` 保留旧轮号、实际回合身份和精确子窗。旧轮扣留牌的真实返还先结算，再执行冻结的轮末候选；牌移动、体力变化和濒死等子流程沿自己的父帧返回。完成后依次记录 `RoundEnded`、归还实际回合游标，再由下个普通回合推进新轮及重置轮额度。`roundEnding` 只提供通用回合效果资源，不继承 `roundStarting` 特有的虚拟用杀资源。

若轮末子结算新发行额外回合，调度保留最新的原生声明，旧轮仍只关闭一次；新轮号由下个普通回合推进。这是本项目对轮末再发行额外回合的明确顺序约定。终局后不发行新的可选轮末效果，已支付的子结算仍按其原生合同收尾。

`currentTurnEnd` 与 `nextOwnerTurnStart` 是不同期限。后者绑定下个本人实际回合开始，额外回合与翻面跳过按实际开始边界消费，不能退化成当前回合号。距离规则、伤害/回复修正、手限豁免和布尔收益只有在对应能力声明时才使用该期限。

阶段结束偿还、回合结束返还、请求用牌和公开赠牌后的动作都需要保存原拥有者、受益者、阶段/回合实例以及实际支付收据。失源可以取消尚未发行的收益，却不能丢掉已经发行的返还或偿还义务。

例如战意的当前配置在弃牌类别后明确授予回复加成与下个本人实际回合开始到期，见[朱灵规则](../../../src/Characters/zhu-ling/ol/Skills/ol-zhu-ling.rules.json)。其他技能是否具有相同生命周期，应读取其各自配置。
