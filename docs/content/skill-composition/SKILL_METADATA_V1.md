# 结构化技能元数据 v1：标签、执行形态与运行状态

D5a 在 `standard-classic-generals@1.68.0`／rules v96 建立首个可执行边界。它不是新的 skill-program schema；现有 schema 1～10、程序规范化 JSON 和旧内容指纹保持不变。

规则语义以 [BWIKI 技能概念介绍](https://wiki.biligame.com/sgs/%E6%8A%80%E8%83%BD%E6%A6%82%E5%BF%B5%E4%BB%8B%E7%BB%8D) revision 78953（页面更新日期 2026-07-11）为当前资料快照：

- 主公技、锁定技、限定技、觉醒技和转换技是技能标签；
- 锁定技标签不等于强制发动，也不具有优先级特权；
- 觉醒技满足条件时必须执行，并视为同时带有锁定与限定标签；
- 转换技拥有阳／阴状态，通常从阳开始，执行当前形态后切换；
- 状态技表示无需玩家确认且持续生效的技能部分，触发技表示需要玩家确认发动的技能部分；它们与上述标签是不同维度；
- 重置／复原技能会恢复开局状态并清除对应记录。

## 内容契约

`ContentSkillDefinition` 现有三组彼此独立的显式字段：

- `Tags`：`Lord`、`Locked`、`Limited`、`Awakening`、`Conversion`，允许组合；
- `ExecutionForms`：`State`、`Trigger`，一个复杂技能可同时具有两种部分。
- `ActionForms`：当前只有 `Active`，表示本应用需要提供玩家主动选择的技能动作入口；它是客户端／命令交互维度，不是 BWIKI 所列的第三种次要技能类型。

加载器只读取结构化字段，不扫描技能名或中文描述。未知位会被拒绝；`Awakening` 会规范化补齐 `Locked | Limited`。标签不参与触发候选排序，也不会自动生成状态效果、询问或优先级；`Active` 只陈述已有主动实现的入口形态，不会凭空注册实现或改变发动时机。

只要 Registry 中存在一项标签或执行形态元数据，内容玩法哈希就在既有规范化内容外包一层 `HashSchema: 9` 与按技能 ID 排序的 `SkillMetadata`。动作元数据非空时再追加 `HashSchema: 10` 与排序后的 `SkillActionForms`；完全没有对应元数据的旧 Registry 不追加该层，继续使用原字节和原哈希。经典包 1.67.0 因而保持旧定义，1.68.0 才启用前两轴，1.75.0 首次启用动作入口轴。

首批正式映射为：

| 技能 | 标签 | 执行形态 |
| --- | --- | --- |
| 护驾、激将、经典／界黄天 | 主公 | 触发 |
| 救援、血裔 | 主公、锁定 | 状态 |
| 涅槃 | 限定 | 触发 |
| 武神、武魂 | 锁定 | 状态 |

这只是已验证的第一批，不代表其他未迁移技能没有标签。WPF 对带结构化元数据的技能显示准确的状态技／触发技和标签；未迁移技能暂时保留旧兼容文案，避免从说明文字猜测。

## 运行状态

`SkillRuntimeStateStore` 以拥有者座位、稳定技能内容 ID、用途 ID 和作用域记录次数。v1 支持阶段、回合、轮和整局作用域：

- 新阶段清除所有拥有者的阶段记录；
- 新回合清除所有拥有者的回合及阶段记录，使回合外触发也得到新的限次窗口；
- 新一轮清除轮、回合及阶段记录；当前没有正式按轮消费者，具体轮边界接入留给其首个真实技能；
- 整局记录不被上述边界清除，仅在技能重置时清除。

转换状态按拥有者和技能 ID 注册初始阳／阴面，执行后切换；技能重置会清除该技能所有次数并恢复注册的开局面。没有特殊声明时初始面为阳。D5a 只建立并验证通用状态原语，尚未用一个正式转换技占用内容池。

rules v96 的正式涅槃是第一个整局消费者：成功选择后消费 `classic:niepan`／`activation` 的一次额度。可信 Checkpoint 仍只保存不可变设置与已接受命令前缀，Restore 通过同一命令重新构建账本；测试同时证明第二次额度不可用。rules v95 继续写入历史 `UsedLimitedSkillKinds`，包 1.67.0 不带结构化元数据。

## 主公技拥有资格

rules v97 将 `Lord` 标签接入印刷技能的通用拥有资格：角色身份不是主公时，不拥有武将牌上带该标签的技能。资格过滤发生在旧式被动技能、配置程序、旧式转化来源、玩家快照和 WPF 对局技能栏的共同入口，因此不是只隐藏显示，也不需要护驾、激将、救援、黄天、血裔分别复制一套身份判断。

Registry 与武将图鉴继续保存并展示武将牌印刷的完整技能列表；过滤只作用于具体对局中的角色拥有状态。BWIKI 所述“游戏开始时没有此技能则不受主公身份限制”的例外对应未来的动态技能授予来源，本块只过滤武将牌印刷技能，不会把该限制复用于后续获得的技能。rules v96 及更早回放继续保留历史全印刷技能投影和发现路径。

当前验收以孙权为正式内容样本：主公仍拥有制衡／救援，反贼只拥有制衡；rules v96 以相同命令前缀恢复时仍投影两项技能。另一个受控武将同时印有带 `Lord` 标签的旧式主动技、配置程序和旧式杀闪转化，非主公在 rules v97 三类入口均不存在，而 rules v96 保留全部旧入口。WPF 的反贼孙权技能栏只显示制衡；武将定义本身仍保持完整两技能。

## 正式觉醒与动态获得技能

rules v98／`standard-classic-generals@1.69.0` 以 OL 版 `sp:guan-yu` 的【单骑】作为第一个正式觉醒消费者。准备阶段同时满足“手牌数大于体力值”与“主公不为刘备”时，不发布可跳过询问，而是按觉醒技规则强制执行：消费 `sp:danji`／`awakening` 的整局一次记录，减 1 点体力上限，并按稳定顺序获得 `sp:guan-yu-mashu`、`sp:nuzhan`。

获得技能保存在玩家运行状态而不修改 Registry 或武将牌印刷定义。旧式被动技能、配置程序、转化来源和玩家快照都读取同一 `EnabledContentSkillIds` 集合；获得的技能不重新经过“武将牌印刷主公技”资格过滤。公开快照为每项当前拥有技能投影 `IsAcquired`、命名次数记录和可选转换状态，WPF 因而能把【单骑】显示为“等待觉醒条件／已觉醒”，并把【马术】、【怒斩】标为“觉醒获得”。

【怒斩】不靠实体牌种或中文文案猜测武圣来源：只有 `CardActionContext.ConversionChain` 中精确绑定 `sp:guan-yu-wusheng` 时才生效。锦囊牌转化的杀不增加通常出杀计数，并在额度耗尽后仍由合法动作生成器开放；装备牌转化的杀在伤害帧建立前增加 1 点伤害。SP【武圣】的方块杀无距离限制属于该印刷技能的独立规则，仍受通常出杀次数约束。

Checkpoint 继续只保存不可变设置与已接受命令前缀；Restore 通过准备阶段与用牌命令确定性重建觉醒、获得技能和怒斩事件。相同命令前缀在 rules v97 不觉醒、不获得技能，也不投影运行状态。来源与版本排除见 `docs/content/sources/sp-guan-yu-d5b2a-2026-09-21.json`。

## 正式转换技与每目标回合账本

rules v99／`standard-classic-generals@1.70.0` 以 2018 版 `classic:yan-yan` 的【拒战】作为第一个正式转换消费者。技能以结构化 `Conversion` 标签和 `Trigger` 执行形态注册，初始为阳；跳过不切换，只有当前一面实际发动后才发布类型化转换事件并切换到另一面。

阳面在严颜成为其他角色【杀】的目标后询问；发动后双方各摸一张，并以稳定 `source-target` 用途 ID 在严颜自己的技能账本中记录“该来源本回合不能再对严颜使用牌”。阴面在严颜使用【杀】完成全部目标指定后只询问一次，可从任一目标取得一张牌，再记录“严颜本回合不能再对该目标使用牌”。手牌只给严颜显示不透明牌位，装备区和判定区才公开实体 ID；限制统一进入普通牌、转换牌、虚拟杀、全体锦囊与多目标组合的合法动作过滤，不限制技能本身。

所有玩家的回合记录在新回合边界一起刷新，因此回合外阳面发动也持续到当前回合结束。Checkpoint 仍只保存命令前缀：暂停在阳／阴私有 Choice 和完成后均由 Replay 重建相同转换面、目标账本、事件与可用动作。rules v98 读取同一 1.70 内容时不注册拒战状态或窗口；包 1.69.0 则根本不含严颜。来源与版本排除见 `docs/content/sources/yan-yan-d5b2b1-2026-09-21.json`。

## 锁定状态技首批迁移

`standard-classic-generals@1.71.0` 在不增加规则版本的前提下，把当前经典包中 13 项已完成规则验收、且执行时不要求技能拥有者确认的锁定技显式标为 `Locked + State`：狂骨、无双、咆哮、谦逊、八阵、红颜、不屈、耀武、义从、祸首、巨象、毅重、无言。

这里的两项字段仍各自独立：`Locked` 只描述印刷标签，`State` 才表示这批技能的自动或持续执行部分。耀武虽然会让伤害来源选择回复或摸牌，但技能拥有者不确认是否发动，因此仍是状态技；选择效果不是把技能本身改成触发技。引擎既不因这些标签重复执行效果，也不改变原有触发次序、优先级或合法动作。

迁移只在包 1.71.0 生效并进入内容指纹；显式加载 1.70.0 时这 13 项仍保持 `None + None`，玩法和旧技能栏兼容文案不变。当前 WPF 技能栏读取新元数据，例如张飞【咆哮】显示“状态技 · 锁定技／规则自动生效”；`167-locked-state-skill-metadata.png` 已在 1120×740 验证单技能卡和六张手牌均无裁切。来源与逐项映射见 `docs/content/sources/locked-state-skill-metadata-d5b2b2a-2026-09-21.json`。

## 经典纯可选触发技迁移

`standard-classic-generals@1.73.0` 把当前包中已有明确发动／跳过交互的 27 项纯可选触发技显式标为 `None + Trigger`：反馈、天妒、观星、克己、突袭、裸衣、洛神、集智、铁骑、烈弓、流离、闭月、枭姬、连营、猛进、据守、天香、神速、经典／界鬼道、经典／界雷击、英魂、再起、烈刃、举荐和 SP 冲阵。

本次分类依据“是否需要技能拥有者主动确认发动”，而不是运行时扫描技能说明中的“可以”。发动之后由目标选择效果、由判定或伤害子流程继续，均不把技能本身改成状态技；相反，主动技能、杀闪转化和会在发动后产生回合持续修正的双雄／天义仍留待独立建模，避免把复合执行形态压成单一类型。

迁移不增加 rules 版本，不创建新的 Prompt、事件或规则分支；1.72.0 的同一 27 项仍保持 `None + None`，内容签名与玩法指纹阻止旧存档静默套用新展示语义。WPF 实战技能栏已验证【集智】与【铁骑】显示“触发技／等待触发时机”，同时【奇才】和【马术】继续显示“状态技 · 锁定技／规则自动生效”；`169-classic-optional-trigger-metadata.png` 在 1120×740 覆盖真实集智 Choice、双技能卡与五张手牌。来源与逐项边界见 `docs/content/sources/classic-optional-trigger-metadata-d5b2b2c-2026-09-21.json`。

## 经典持续牌转化状态技迁移

`standard-classic-generals@1.74.0` 把当前包中持续提供牌身份或牌转化合法动作的 11 项既有技能显式标为 `None + State`：奇袭、断粮、倾国、经典龙胆、经典武圣、国色、火计、看破、连环、乱击与 SP 龙胆。

这些技能不是在一个触发时点发布“发动／跳过”询问，而是只要技能有效，就持续让符合花色、牌名、区域和响应类型的实体牌产生额外合法动作。玩家最终选择使用某个转化动作，不会把技能本身变成触发技。这里的“牌转化”也不等于 `Conversion` 标签；该标签仍只描述具有阳／阴状态的正式转换技。

## 经典纯主动操作入口迁移

`standard-classic-generals@1.75.0` 为已有独立主动实现的 5 项纯主动技能增加 `ActionForms.Active`：反间、强袭、离间、结姻、驱虎。它们在出牌阶段由玩家选择动作入口，但不包含等待特定时机确认发动的触发部分，也不靠持续规则修正生效，因此 `Tags` 与 `ExecutionForms` 均保持 `None`。

`ActionForms` 是项目的交互元数据轴，不把“主动技”伪装成 BWIKI 的状态技或触发技。内容哈希只在至少一项技能具有动作元数据时追加 schema 10 层，因此此前没有 `ActionForms` 的历史包保持原指纹；回归检查同时验证这 5 项对应的 `SkillKind` 确实注册了主动实现。1.74.0 的同一 5 项继续为 `ActionForms.None`，Checkpoint schema、rules v99、命令、技能效果和玩家资料均未改变。

WPF 已在周瑜【反间】真实选目标边界验证“主动技／当前可发动”，`171-classic-active-action-metadata.png` 在 1120×740 覆盖技能栏、六名目标、操作区和手牌且无裁切。激将、乱击、天义、双雄等同时涉及主动／触发／后续状态的技能保留给复合迁移，避免用单轴标签压平语义。来源与逐项边界见 `docs/content/sources/classic-active-action-metadata-d5b2b2e-2026-09-21.json`。

## 经典复合技能元数据迁移

`standard-classic-generals@1.76.0` 首次用三条独立轴表达同一个技能中的不同部分：激将为 `Lord + Trigger + Active`，乱击为 `State + Active`，天义为 `State + Active`，双雄为 `State + Trigger`。其中激将既可在出牌阶段通过应用的技能按钮发起，也会在需要打出【杀】的响应时机确认；乱击持续提供同花色双牌转【万箭齐发】的合法性，同时由已有主动草稿收集两张实体牌；天义由主动拼点进入本回合杀次数、距离、目标数或禁杀状态；双雄在摸牌阶段确认是否改判定，并在成功后持续提供本回合异色牌转【决斗】。

本批只补充既有执行结构的描述，不增加 rules 版本，也不改变主动技能实现、转换来源、拼点、判定、回合状态、AI、Prompt 或 Replay。1.75.0 仍保留激将 `Lord + Trigger`、乱击 `State`，且天义和双雄没有复合元数据；内容签名与玩法指纹阻止两版静默互换。

WPF 已分别验证激将显示“主动技 · 触发技 · 主公技”和双雄显示“状态技 · 触发技”；`172-classic-jijiang-compound-metadata.png` 与 `173-classic-shuangxiong-compound-metadata.png` 在 1120×740 覆盖真实主动入口／摸牌阶段 Choice、技能栏、操作区和手牌且无裁切。来源与逐项边界见 `docs/content/sources/classic-compound-skill-metadata-d5b2b2f-2026-09-21.json`。

1.76.0 及更早经典包仍引用 `standard:` ID，因而旧内容签名、玩法指纹和 Checkpoint 恢复路径不变。新 `classic:` 定义让技能栏和后续规则迁移不再依赖演示扩展包元数据，同时完整保留既有主动命令、实体牌移动、濒死续接、AI、Prompt 与 Replay。

1.77.0 只迁移技能身份而不改玩法：当时仁德仍保留一次交牌、每回合一次的早期切片。WPF 的刘备技能栏和黄盖选将卡分别由 `174-classic-shared-active-metadata.png`、`175-classic-kujin-card.png` 在 1120×740 复核。该历史边界见 `docs/content/sources/classic-shared-active-skill-metadata-d5b2b2g-2026-09-21.json`。

## 当前经典仁德与阶段累计账本

rules v100／`standard-classic-generals@1.78.0` 按当前官网补全 `classic:rende`：每次仍通过统一主动草稿选择至少一张自己的手牌和一名其他存活角色，但完成一次交牌后不消费回合限次，因此可在同一出牌阶段再次选择相同或不同目标。每张实体牌仍经 `Hand → Processing → Hand(target)` 移动；`classic:rende`／`cards-given` 的 `Phase` 用途记录累计本阶段给出的实体牌数。

只有累计数量第一次从少于 2 跨到 2 或更多时建立回复帧，回复目标是技能拥有者刘备而不是收牌角色，回复量固定为 1。满体力时该时点的回复没有效果，也不会在本阶段后续给牌时再次触发；阶段边界按既有通用状态仓清除累计记录。该记录是运行时派生状态，不改变仁德的 `ActionForms.Active` 元数据，也不把主动操作入口误标为 BWIKI 的状态技或触发技。

Checkpoint 继续只保存内容包签名、rules 版本和已接受命令前缀：恢复第一次一张给牌后会重建 `count=1`，再执行第二次给牌时以相同玩家快照和事件跨越阈值。rules v99 或包 1.77.0 任一边界都保留旧限次、旧回复对象和旧结算序号；`standard-active-skills@1.0.0` 的演示仁德也不变。AI 对回复收益改为读取刘备自己的伤势。`176-classic-rende-repeat-entry.png` 在 1120×740 验证第一次给牌后仁德与激将仍是两个可见入口。来源与边界见 `docs/content/sources/classic-rende-formal-d5b2b2h-2026-09-21.json`。

## 其余经典共享技能独立身份

`standard-classic-generals@1.79.0` 为此前仍借用基础／救援包定义的七项技能建立独立身份：`classic:guicai`、`classic:ganglie`、`classic:jijiu`、`classic:yiji`、`classic:yingzi`、`classic:jianxiong`、`classic:jieming`。当前经典司马懿、夏侯惇、华佗、郭嘉、周瑜、曹操和荀彧切换到这些 ID；1.78.0 及稳定基础／救援包继续引用原 `standard:` ID。

鬼才、刚烈、遗计、英姿、奸雄和节命均在明确时机询问技能拥有者是否发动，因此投影为 `Trigger`。急救在拥有者回合外持续为红色实体牌提供【桃】身份，选择该响应动作不构成独立的技能发动／跳过窗口，因此投影为 `State`。七项都继续复用对应 `SkillKind` 和既有被动规则实现，不创建新结算分支，不提高 rules v100，也不改变 Prompt、事件、AI、Replay、Checkpoint schema 或玩家资料。

WPF 技能栏已验证郭嘉的遗计显示“触发技／等待触发时机”，华佗的急救显示“状态技／规则自动生效”且青囊仍显示“主动技”；`177-classic-shared-trigger-skills.png` 和 `178-classic-shared-jijiu-state.png` 在 1120×740 经人工复核无裁切。来源、逐项分类和版本边界见 `docs/content/sources/classic-shared-skill-metadata-d5b2b2i-2026-09-21.json`。
