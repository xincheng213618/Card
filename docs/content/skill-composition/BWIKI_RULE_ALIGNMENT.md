# BWIKI 资料与技能执行模型对齐

项目将参考资料、选用版本、可执行规则与展示文本分别维护。BWIKI 抓取结果用于核对来源；正式内容由人物资料、当前技能规则及内容注册表决定。当前配置入口见 [技能运行配置](RUNTIME.md)，人物目录与扩展入口见 [人物模块与注册](../../CHARACTER_MODULES.md)。

## 资料进入游戏

资料采集保留站点、页面、revision、模式和技能版本；同名技能及同页的不同版本分别核对。选定文本经规则配置和独立展示文件接入，加载器检查格式、操作、上下文和资源关系，行为场景检查实际效果与命令重放。

资料库见 [BWIKI 参考数据](../BWIKI_REFERENCE_DATA.md)，具体来源缺口见 [BWIKI 内容清单](../BWIKI_CONTENT_BACKLOG.md)。`/sgs/`、`/sgsol/`、`/msgs/` 属于不同资料范围，文本冲突按选用产品和版本记录。页面分类、下载图片或保存文本本身不改变正式选将池。

## 概念与当前契约

[技能概念介绍的固定 revision](https://wiki.biligame.com/sgs/index.php?title=技能概念介绍&oldid=78953)用于术语映射；当前实现分别表达下列内容：

| 资料概念 | 当前模型 |
| --- | --- |
| 主公、锁定、限定、觉醒、转换标签 | `SkillTag` 元数据，拥有者资格、发动条件、优先级与使用账本各自校验 |
| 状态技、触发技、主动入口 | `SkillExecutionForm`、`SkillActionForm` 与 Program 修正/触发/激活定义分别声明 |
| 限定、觉醒和次数 | `SkillRuntimeStateStore` 的事件、阶段、回合、轮及整局作用域 |
| 阴阳转换 | 当前状态、提交翻转与分支；实体牌转换由 `viewAs` 单独表达 |
| 正常摸牌数量 | 摸牌计划、普通摸牌调整和替代政策；技能直接摸牌使用独立操作 |
| 使用、打出和供牌 | `CardActionContext` 与原生用途保存实际使用者、提供者、有效身份、实体材料和转换来源 |
| 判定 | 原生判定帧、改判候选、冻结最终结果、结果收益和实体收尾 |
| 技能获得、失去、抑制 | 带来源及实例的授予记录和有效资格查询 |
| 死亡与已开始效果 | 当前拥有帧、已支付凭据、死亡窗口及按机制注册的继续权限 |

## 执行和可见性

窗口冻结技能候选、条件事实和游标。真正发动或恢复时复查当前资格，子程序通过类型化结果返回所属父帧，已完成费用保留原收据。技能失效、角色死亡和终局分别按具体操作的有限返回规则处理。

`ProgramEntryCapabilities` 决定入口的实际上下文，操作 descriptor 和 `ProgramCompositionValidator` 决定可执行组合。命令校验、实体移动、私有提示、嵌套集合冻结和命令重放由公共机制提供。需要新增能力时，按上下文、费用、状态拥有者、期限和父返回扩展。

普通玩家只读取 `CreateSnapshot(viewerSeat)`；完整命令前缀、牌区诊断和 `ResolutionStack` 属于可信宿主数据。AI 使用其合法选项和允许的公开/本人事实。

## 来源和素材

来源档案分别标明正式文本、补充说明和工程默认；旧公告可用于说明明确选择的规则版本，不能自动覆盖项目选定文本。具体版本取舍保存在人物来源及对应能力/口径文档。

头像和经典形象依据见 [立绘目录](../bwiki-portraits.json)，保留文件页、原图地址、下载时间、尺寸和 SHA-256。普通赵云与 SP 赵云分别使用自己的资源身份。
