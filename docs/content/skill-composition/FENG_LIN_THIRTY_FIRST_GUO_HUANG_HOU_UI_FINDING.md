## 确证P2：主动零实体动作在WPF不可到达

作者NEW GameEngine.TieredRoundZeroUses.cs的TieredRoundZeroPlayActions发布真实LegalAction：CardId=0，Kind仍为Slash/Peach/Alcohol或具体锦囊，保留PlayedCardKind、ConversionSource及ordered TargetSeats；nullable TieredRoundZeroUse是公开opt-in marker。shared-wiring把这些动作加入BuildLegalActions，TrySubmitTieredRoundZeroPlay在通常实体付款前接真实PlayCardCommand。原01/02/03跟进没有改变这项公开身份，也没有WPF接线。

当前GetViewLegalActions通过GetHumanActionView取得这些公开动作。但MainViewModel.Presentation.cs HumanActiveSkillActions只保留UseEquipmentEffect/UseProgramSkill；MainViewModel.TableSurface.cs补充动作与技能按钮也只消费这个列表，所以零实体动作没有按钮。普通RequestHumanPlay无SkillPrompt，MainViewModel.cs SkillChoices分派也不包含PlayCard，因此prompt里有同一动作也不会进入普通技能选项列表。

实体牌入口SelectCard仅接真实CardViewModel；没有CardSnapshot/HandCardViewModel0可选。即使外部把选中ID设为0，PlaySelectedAction仍在构造命令之前对本人Hand/Grain/Equipment.Single(id==0)，必然失败。PublicTargetChoices/TargetCombinationChoices也以选中的真实卡ID作为进入条件。由此已静态证明新主动零实体动作不能通过现有WPF正常展示、选择并提交。

建议仅以TieredRoundZeroUse marker opt-in接公开动作入口，保留原Kind与exact command身份；不要伪造CardViewModel0，也不要改为UseProgramSkill。可复用active action展示/目标选择，但确认应直接以原LegalAction的CardId0、PlayedCardKind、TargetCardId、ordered targets、ConversionSource及AdditionalConversionSources构造PlayCardCommand，并以当前合法动作重新复验选择。

## 响应提示链静态可复用

TieredRoundZeroResponseChoices发布Cards=[]/Targets=[]、exact ChoiceId和完整conversion参数。零实体借刀/青龙选择同样保存真实固定目标及参数。WPF把RescueDying、Nullification、RespondDodge/RespondSlash、QinglongCrescentBlade分别加入DyingChoices、NullificationChoices、ResponseChoices、SkillChoices。MainWindow.xaml相关模板均是Description文本按钮，不要求实体卡面或非空Cards。

SelectDyingChoice/SelectNullificationChoice/SelectResponseChoice/SelectSkillChoice原样提交AnswerPromptCommand(actor,promptId,choice.Id,revision)，没有查找自有实体；Core的新response dispatch再由原冻结choice重验source/target/producer。因此提示列表路径未发现同样的CardId0卡口，毋须新增响应UI。手牌快速响应快捷键不保证选择这项转换，不影响完整公开提示按钮路径。
