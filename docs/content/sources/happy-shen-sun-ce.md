## 逐技执行对照

以下按同产品二级全文整理规则要点，避免将另一产品的公告当作欢乐官方全文。当前正文没有测试服旧版的平定回收上限、对平定角色不限次数等设计。

| 项目 | 欢乐规则与现有移动版共同的执行要求 |
| --- | --- |
| 初始属性 | 男、神势力，初始1点体力、上限6；不把6上限误作满体力开局。 |
| 英霸发动 | 每个实际出牌阶段至多一次，无牌成本；选择另一名仍存活且体力上限大于1的角色。 |
| 英霸支付与标记 | 先令目标减少1上限并获得1枚平定，再减少自己1上限；不回复体力，不移除已有平定。自身上限减至零按原生死亡处理。 |
| 英霸距离 | 自己对平定角色使用牌不受距离限制；不改变真实座次、攻击范围或该牌使用次数。 |
| 覆海响应 | 平定角色不能响应自己对其使用的牌；仅限制该牌实际指定的目标，不把旁观的平定角色一并禁响应。 |
| 覆海用牌收益 | 自己真实使用牌，目标中有平定角色时摸1；同一次多目标用牌只有这一次摸牌收益。按本实际回合已经以此法获得的数量封顶2，不以发动次数替代实际获得量。 |
| 覆海死亡收益 | 平定角色真正死亡时，按其平定总数增加自己的体力上限并摸等量牌；此收益独立于用牌摸2的回合限额，不要求自己击杀该角色。 |
| 冯河手牌上限 | 将手牌上限的基础值设为已损失体力，即当前上限减当前体力；不是增加等量上限，也不是直接按最大体力存牌。 |
| 冯河防伤 | 锁定：自己有手牌且上限大于1时，防止其他角色造成的该次伤害；减自己1上限，再向一名其他角色交出1张真实手牌。不是按每点伤害重复支付，也不处理自身来源、无来源伤害或失去体力。 |
| 冯河后续平定 | 实际交牌完成后，若自己此时仍有英霸，则令伤害来源获得1枚平定；受赠者可以不是伤害来源，不额外要求受赠者已有平定。 |

欢乐现行二级正文仍写覆海“为目标时”，移动版公告写“为目标后”。本次没有找到欢乐独立的细时序FAQ或改变目标／次数／收益的修订，故不据这一旧措辞另造玩法。合并实现沿用实际目标已经确定的原生用牌窗口，避免按候选目标或每个目标重复发行摸牌；这里不冒称欢乐官方已逐项确认重定向等细时序。

## 仓库运行边界核对

- `src/Characters/sun-ce/mobile-god/Content/mobile-shen-sun-ce.character.json` 已定义1初始体力／6基础上限、男性、神势力；`Skills/mobile-shen-sun-ce.rules.json` 已以 `usesPerPhase:1` 限制英霸，并在 `cardUseTargetsFinalized`、`characterDied` 和 `beforeDamageApplied` 接入三个真实窗口。
- `Runtime/GameEngine.ShenSunCe.cs` 的 `ShenSunCeTriggerLegal` 从原生Use的实际指定目标读取平定；用 `ShenSunCeDrawReturnedEvent.Actual` 累计本实际回合收益。借刀的受牌目标与受迫出杀者分开，不将后者冒作该锦囊的平定目标。
- 同文件的 `ShenSunCeCardDistance`／`ShenSunCeSlashDistance` 只提供对平定目标的使用距离豁免；`ShenSunCeCannotRespond` 接入 `GameEngine.ProgramCardPolicies.cs` 的既有响应禁止查询，保留原牌、原目标和响应者关系。
- 冯河的触发资格显式检查 `BeforeDamageHasNoSource`，区分其他角色造成的伤害与SourceLess攻击；防伤、减少上限、原帧私有交牌、真实移动子窗以及随后标记按顺序续接。`ShenSunCeReceipt` 保存在原 `ProgramSkillFrame`，恢复不重新付款。
- 覆海摸牌使用 `BeginOperationProgramDraw` 和类型化 `NativeDrawOutcome` 返回；死亡收益绑定原 `DeathFrame`／死亡候选和当时冻结的平定数。死亡清理保留平定来源，供真实死亡窗口读取。
- 现有 `ShenSunCeChecks.NativeYingbaFuhaiAndDeathGrowth` 已覆盖定向距离、每阶段限次、多目标一次收益、两张实际收益封顶、禁响应和死亡成长；`NativeFenghePaidGiftColdRestore` 已覆盖原帧交牌、真实支付子窗冷恢复，以及自身／无来源伤害和失去体力的排除。本次只读核对这些既有行为，不声称本轮另行执行了检查，也不添加重复人物测试。
