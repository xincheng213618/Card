## 规则与实现

雄莽允许将非空、花色各不相同的手牌作为一张杀的实际材料，可选择的目标数上限等于材料花色数量。杀完整结算后，以整张牌是否实际造成伤害决定后果：未造成伤害减一点体力上限；造成过伤害则增加本阶段的一次杀使用额度。

仓库采用以下实现解释和边界，并与上面的官方文字分开：

- 选牌在原技能帧内完成，材料须仍属于实际手牌，每种实际有效花色至多一张（包括红颜等既有花色重写）；不将无花色实体计算为新的花色。材料数量自然为一至四张，可选一个至相同数量的合法目标。付款前按当前有效花色核对，发行时冻结各材料的有效花色，后续技能失效或花色规则变化不重新解释已经支付的材料。转化的杀仍受原生距离、禁止、当前用牌次数及合法目标检查。
- 主动发动在付款前公开确认已选择的目标组；卡牌付款、逐目标响应、伤害和材料收尾复用真实原生杀流程。没有用直接伤害替代杀，也没有缩减为单目标。
- 既有固定材料数量的 viewAs 支持原生使用入口与合法的请求式使用。它们不开放纯打出路径。最终使用事实须为真实 Use，杀族识别沿用引擎的 `IsSlashCard`，不会因原生杀族变化而漏掉结算后果。
- 后果属于已发行的整牌使用，使用完成后恰结算一次；伤害分支不是按伤害点或目标数重复奖励。原技能随后失效不会取消已经发行的这张牌的后果。
- 增加次数的事实绑定该次原生 Use 的实际阶段 token。规则查询仅在同一实际阶段内提供相应增量，阶段离开或插入新阶段后不带入，原阶段恢复仍沿用其原 token；不将其扩大为整个回合或永久额度。
- 无伤后果通过既有体力上限修改方法执行，保留健康变化等原生子窗。待选材料、目标组、已付款的原生杀和返回收尾均保留在原帧，并沿用有类型的原生返回、冷恢复与命令重放边界。

本条目不调整全局规则 epoch、回放格式、技能 JSON schema 或内容包版本。
