# 内容能力入口与边界

内容实现先查当前技能程序、正式消费者和已注册运行时能力。只有具体规则确实缺少表达或原生入口时，才提出新的共享能力请求。当前配置与注册入口见[运行时](skill-composition/RUNTIME.md)和[人物模块说明](../CHARACTER_MODULES.md)。

## 当前可复用能力

| 规则范围 | 能力与定位 |
| --- | --- |
| 命令与选择 | Revision/Prompt/Choice 校验、私有材料、有序目标、帧内多步选择及现有选择注册协议 |
| 内容 | 人物资料自动发现、包依赖、嵌入程序、规范化内容指纹和只读 Registry |
| 用牌/打出 | 原生实体、多实体转换、持续身份、特定零实体入口、供牌、请求用牌、无懈及精确完成返回 |
| 判定 | 主体/发起者区分、原子改判、最终有效花色和点数、结果绑定、后续效果与直接死亡 |
| 伤害/体力 | 伤害前修正/替代/防止、逐次/逐点伤害后窗口、回复修正、HP/上限变化、濒死救援及死亡 |
| 移动 | 原子批次、具名实体绑定、私有看牌、实际弃置/获牌语义、装备进入、死亡遗留牌申领 |
| 状态 | 作用域额度、归属标记、转换状态、技能授予/失效、拥有牌区、临时规则及精确期限 |
| 流程 | 实际阶段/回合/轮、跳过/插入阶段、额外回合、原生子窗等待与已支付义务续接 |
| AI/UI | 私有合法动作、能力 AI 与交互适配、通用技能草稿/选择器及公开事件反馈 |

各项能力的组合有严格白名单与资源合同；“已有此节点”不等于它可以出现在任意窗口或指向任意主体。完整合法形状取当前解析器、操作描述符和正式规则文件。

管亥的诱阙为原生拼点提供已发行的公开牌堆实体来源：保留原技能实例、最小点数实体和付款前移动序号，原牌直接从饵牌堆进入原生拼点处理区，仍要求双方有手牌。卸尾则将两张手牌作为一次真实置入饵的成本，输出杀或闪另行保留无花色、无点数的属性；已置入的成本凭原付款记录完成响应，不再伪装成处理区实体。两项入口只接受其已验证的规则合同，不开放任意牌堆用牌。

## 战意使用的共享收益

OL 朱灵的[当前规则](../../src/Characters/zhu-ling/ol/Skills/ol-zhu-ling.rules.json)已经声明：

- 装备进入通过实际目的区的逐牌 `cardsGained` 观察，包括技能直接置入及正常装备使用。
- 基本牌收益包含普通、转换和零实体用牌的回复加成；按真实用牌者冻结回复收据，濒死酒按实际饮酒者归属。
- 规则修正、伤害/回复收益、锦囊手限豁免和布尔状态可按其显式策略持续到下个本人实际回合开始，正确区分额外回合与当前回合结束。

实现分别位于朱灵的注册运行时与 Core 的回复、规则修正及时间边界能力。是否完整符合其他人物的类似文案，仍须逐条核对来源、主体、牌种和期限。

## 摸牌前替代的接入边界

`NativeDrawStarting` 由真实摸牌请求在牌堆实体移动前发出。请求帧保留原生产者、请求数量、原因、实际阶段和精确返回游标；普通摸牌返回原生产者执行，继续沿用其原生移动归属和 DrawPile 材料证明。替代获得的实体单列为 `ReplacementGainedIds`，不能写入 `ActualDrawIds`、摸牌结果绑定或实际摸牌数量。

当前接入通用 Draw 指令、有类型化回调的技能操作、普通和额外摸牌阶段，以及原生【无中生有】。无中在其真实无懈窗口返回后发起请求，等待实际获牌子流程；同一次用牌的后续目标或重复效果各用独立请求，原牌只支付及收尾一次。其他直接调用 `DrawCards` 的原生结算、自有摸牌生产者、读取实际摸牌结果的旧技能操作仍需逐类迁移。同步调用之后还有伤害、死亡、结算收尾或下一收件者时，必须先冻结其拥有帧的游标，再通过实际子返回续接，不能以空列表冒充暂停。

孙弘尚不进入当前武将池：全路径接入、无实际阶段时的次数口径，以及武将牌技能禁用在各类目标入口的覆盖仍未闭合。人物来源档应保留这些缺口，不将阶段内局部实现称为完整“当你摸牌时”。

## 李丰的原牌来源与完成回收

普通 OL [李丰](https://www.sanguosha.com/hero/693)的集运、输粮已实现并注册为当前可选武将。[正式公告](https://www.sanguosha.com/news/20251104_5570_1514)对应 2025 年 11 月 8 日开放的版本。

输粮需要独立的公开牌堆原牌授权：保留真实 Kind、Suit、Rank、来源位置与供牌者，分别覆盖主动使用、闪／无懈／救援、决斗／群体锦囊打出及主公技供牌。Use 与 Played 共用本人每个实际回合的一次额度，只在签发真实付款时消耗。当前 `OwnPublicPileConversions` 只支持指定杀／闪转换，不能据此放行任意原牌；也不能将粮全局拼入 `GetPlayableCards`，使其进入丈八、重铸或其他手牌成本。

集运的准备阶段可复用逐收件者的原生摸牌返回，只为 `ActualDrawIds` 发行原获牌者手牌驻留租约。整次真实 Use 完成后，只回收真实成本与有效原实体租约的交集，检索当时的装备区或弃牌堆；无标记材料与判定区牌不跟随回收。真闪／无懈走现有响应使用完成返回，决斗／群体锦囊的纯打出不触发集运。回收保存实际来源、移动序号与拥有帧，排完装备移除、回复、濒死和移动子窗，再正常返回原 Completed 窗口；完成后的材料区域校验只接受该次已发行回收证明。

准备阶段冻结人数上限、有序不同收件者，逐人完成真实摸牌及其子窗后再推进。结束分配冻结实际粮实体、任意子集和分配游标，允许多张交同一人。不得套用要求四花色及全量分配的现有操作。多枚标记实体在同次 Use 完成时按租约发行顺序逐枚重验当前粮数小于三，达到三后停止回收，这是正文与同品攻略的组合解释；尚无专属 FAQ 或服务器包证明。客户端能展示超过三张，不构成允许突破容量的规则证据。

## 提出能力请求

每项请求应写清：

1. 产品线、稳定内容 ID、选定规则来源及官方 FAQ；没有 FAQ 的解释明确标为工程默认。
2. 当前最接近的能力与具体不满足条件，例如缺失窗口、主体、材料、目的区、额度、实际用牌分类或到期时点。
3. 触发事实、发动/支付主体、牌区与原生动作、暂停点、失源/死亡/终局后的已付与未付处理。
4. 需要的描述符、解析验证、资源/查询依赖、类型化帧返回、隐私投影及 AI/UI 适配。
5. 最小真实场景与拒绝边界；新行为或修复使用既有名称过滤检查，纯配置复用共享覆盖。

请求以当前源码核实的缺口为准。来源尚未证明的随机池、派生技能版本或时点不能通过同名内容自动补齐；实现选定的工程默认必须保存在对应人物合同中。

## 开发约束

人物目录可独立并行，中央 Core 和共享协议需统一协调。状态保存在其拥有帧，已支付原生子链按精确收据返回；公开集合在提交准备时冻结。规则事件使用 `AdvanceEventRulesAndQueueFact`，状态推进使用 `AdvanceRulesAndPublishState`。

普通内容变化通过内容指纹区分；格式版本来自 `SkillPrograms.cs` 和 `Replay.cs`，包版本来自各包 `CurrentVersion`。开发使用相关过滤，批次运行规定例行范围；完整验证仅在用户明确请求时运行。详见[场景与验证边界](SCENARIO_MATRIX.md)。
