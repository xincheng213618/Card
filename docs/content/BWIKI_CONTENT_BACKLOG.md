# BWIKI 武将与技能迁移清单

状态：2026-09-20 首批。此清单负责**具体武将、版本证据、素材和场景验收**；通用技能运行时由 `SKILL_COMPOSITION_DESIGN.md` 及其实现维护。本文件不把页面收录数量当成仓库已实现数量，也不要求为每名武将增加专属 `SkillKind` 或 `GameEngine` 分支。

## 1. 证据与更新规则

来源优先级：

1. 选定产品线和日期对应的官方武将页、公告、FAQ；
2. [BWIKI 武将图鉴](https://wiki.biligame.com/sgs/%E6%AD%A6%E5%B0%86%E5%9B%BE%E9%89%B4)用于发现页面、区分普通／界／SP／神／模式版本和记录页面修订；
3. [BWIKI 技能概念介绍](https://wiki.biligame.com/sgs/%E6%8A%80%E8%83%BD%E6%A6%82%E5%BF%B5%E4%BB%8B%E7%BB%8D)用于术语：主公技、锁定技、限定技、觉醒技、转换技是标签，状态技／触发技是执行形态；
4. 开源实现只用于检查时序与边界，不能替代所选官方版本。

每个正式条目必须保存：稳定内容 ID、产品线、版本／日期、来源 URL、技能原文摘要、体力／势力／性别、标签、规则能力依赖、头像来源与哈希、最小场景矩阵。页面更新后先新增版本差异，不直接改写已经用于存档的定义。

可重复抓取的本地参考数据、分页范围与刷新命令见 [`BWIKI_REFERENCE_DATA.md`](BWIKI_REFERENCE_DATA.md)。数据集用于发现和对照，不会把分类页数量或抓取成功自动升级为“已实现”。

状态词：

- `implemented-legacy`：当前类型化旧路径已实现并有场景；不代表已迁入组合运行时。
- `implemented-program`：已以版本化技能程序注册，并有正式内容、存档边界和场景验收。
- `expressible-v1`：现有配置 v1 可完整表达。
- `partial-v1`：只能表达一部分，不能以此注册正式武将。
- `needs-capability`：需要通用能力后才能配置。
- `rules-review`：来源存在版本冲突或关键时点尚未锁定。
- `portrait-downloaded`：素材和来源元数据已在工作树，但尚未证明已经接入 WPF／内容包。
- `portrait-wired`：现有武将的资源键已接入 WPF；素材状态不等同于技能组合迁移完成。

## 3. 优先武将拆解

### 3.1 SP 赵云：龙胆／冲阵

规则锁定：

- [官网 SP 赵云](https://www.sanguosha.com/hero/108)与[BWIKI SP 赵云](https://wiki.biligame.com/sgs/SP%E8%B5%B5%E4%BA%91)均给出杀／闪互换以及发动龙胆后可获得“对方”一张手牌。
- [官方冲阵 FAQ](https://www.sanguosha.com/news/20161215_4752_4616)进一步规定：转化杀在目标最终确定后插入；南蛮、决斗、万箭、杀响应等场景的“对方”来自当前对抗上下文，不等同于伤害来源；取得牌发生在原牌效果继续前；冲阵可跳过，对方无手牌时取得零张。

复用与缺口：

- 复用 `viewAs` 的杀／闪双向转换、实体牌支付、已有普通赵云合法动作与响应场景。
- 通用运行时需要输出 `conversionChain` 或等价稳定来源 ID，并开放 `CardUseTargetsFinalized` 与 `CardResponseAccepted` 订阅。
- 触发绑定必须取得规范化 opponent；不能根据最终有效牌型推断龙胆，也不能固定取当前回合角色或 `damage.source`。
- 取得暗手牌必须复用不透明候选／宿主随机或选择机制，不向 SP 赵云以外的视图发布牌面。

最小场景：主动闪转杀、借刀产生的杀、南蛮杀响应、决斗多轮杀、杀／万箭闪响应、无双连续响应、流离改目标后仍取锁定目标、对方空手、跳过、暂停 Checkpoint/Replay。每个场景断言冲阵先于原牌效果，且每次实际龙胆动作至多触发一次。

### 3.2 普通／界／国战张角

版本锁定：

- [官网普通张角](https://www.sanguosha.com/hero/212)和[BWIKI 张角](https://wiki.biligame.com/sgs/%E5%BC%A0%E8%A7%92)身份版：使用或打出闪后选择其他角色判定；黑桃造成 2 点雷伤，梅花先回复自己 1 点再造成 1 点雷伤；鬼道用黑色牌改判；黄天允许其他群角色交闪或闪电。
- [官网界张角](https://www.sanguosha.com/hero/448)：使用／打出闪或使用闪电后由自己判定；自己的任意判定后再按黑桃／梅花选择伤害目标；鬼道以黑桃 2～9 替换时额外摸一；黄天接受闪或黑桃手牌。它是独立定义，不是普通张角加数值。
- BWIKI 同页国战版只保留雷击／鬼道，且雷击只有黑桃 2 雷伤；不得带入身份版梅花分支或黄天。

普通张角已在 1.65.0 完成配置迁移，界张角已在 1.66.0 以独立 ID 和独立模式完成注册；经典模式仍只含经典张角。国战张角又在独立的 `standard-national-zhang-jiao@1.0.0` 中完成，依赖 rules v89 的双将多技能明置边界，未把界版直接放进国战池。

需要的通用能力：

- 判定开始、替换、生效、结果订阅和收尾四类可暂停窗口；
- `JudgmentReason` 与因果来源，避免界雷击只监听自己创建的判定或误监听禁用原因；
- 原子改判，替换牌来源区与旧判定牌去向显式化；
- 判定后黑桃／梅花分支，满血零回复仍继续后续伤害；
- 主公技标签、势力筛选、每阶段每来源角色限次。

已完成场景覆盖普通张角雷击／鬼道／黄天、界张角的闪后自身判定、黑桃雷伤、黑桃 2～9 鬼道弃旧牌并摸牌、界黄天并集过滤，以及国战张角暗置无技能、明置双程序、只含黑桃 2 雷伤、鬼道旧牌入手和无黄天差分。三版均有 Checkpoint/Replay；经典、界、国战卡面分别使用独立内容 ID，国战模式另覆盖四技能双将栏与旧组合存档恢复。

### 3.3 神关羽：武神／武魂

版本锁定：

- [BWIKI 神关羽](https://wiki.biligame.com/sgs/%E7%A5%9E%E5%85%B3%E7%BE%BD)经典正式服 I 版记录：红桃手牌视为杀、红桃杀无距离；受到每点伤害后给来源梦魇；死亡时选择梦魇最多者判定，非桃／桃园则令其死亡。页面 FAQ 还明确全零不发动、最高并列由神关羽选、致死伤害也计标记、可被鬼才／鬼道改判，以及已满足游戏结束条件时不再执行武魂。
- [官网当前神关羽](https://www.sanguosha.com/hero/201)在武神上增加红桃杀无次数且不能被抵消。BWIKI 页面还展示了另一当前描述，包含造成伤害也加梦魇和红桃杀伤害后摸牌。三者必须使用独立版本 ID；正式实现前需再次确认目标产品线，不能拼接。

复用与缺口：

- rules v94／schema 10 已以强制 `cardIdentities` 完成红桃手牌持续化普通杀，并以来源限定的 `slashDistanceLimit` 单独完成距离放宽；它不再借用 v1 可选 `viewAs`，也不把距离无限误作次数无限或不可响应。A53b2 已以 `classic:wushen` 正式配置显式要求 rules v95，并用真实红桃桃验证使用与濒死边界。
- rules v95 已按技能概念页把神势力选择放在身份模式私有选将完成、统一亮将之前：真人从魏／蜀／吴／群选择，AI 稳定选择；内容 `god` 与本局有效势力分离，亮将前不向其他视角泄漏。A53b2 注册的正式神关羽直接复用该通用开局能力。
- 武魂的公开整数标记、每点实际伤害触发和致死伤害前记账已由 rules v90 的 D4a 完成；rules v91／v92 又完成来源归属、死亡拥有者继续资格、最高值并列选择、可改判判定、来源标记清理、嵌套死亡和模式胜负时点；rules v93／schema 9 把绕过濒死救援的直接死亡提升为可审计、可重放的通用效果。A53b2 已以 `classic:wuhun` 声明通用消费者所有权，并用真实经典牌堆的完整死亡链与 Replay 验收正式内容。
- `causeDeath` 必须进入统一死亡清理和奖惩政策，但不能伪造成巨大伤害。

最小场景：1 次 2 点伤害与 2 次 1 点伤害、无来源／被防止／失去体力、致死伤害、全零、并列选择、桃／桃园及其他牌、鬼才／鬼道改判、主公／反贼等已经结束游戏的边界、多名神关羽和嵌套死亡。历史 I 版另验证没有无次数／不可抵消；当前官网版另验证对应能力，不共享期望。

## 6. 后续条目模板

每次从图鉴挑选新武将，只追加一个版本明确的条目：

```text
分类 / ContentId / 产品线与版本日期
体力、势力、性别、模式、技能顺序、结构化标签
官方来源 / BWIKI 页面及 oldid / 规则差异说明
```
