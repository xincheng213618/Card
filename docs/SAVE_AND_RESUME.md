# 本地存档与恢复

牌局现在可以关闭后继续。首次启动只展示开局面板，不覆盖已有存档；有自动存档时显示“继续上次对局”，手动存档有独立的读取入口。

规则行为版本 5 引入的兼容边界继续保留：若恢复点停在致命伤害的伤害后触发窗口，命令前缀会保留 `DamageTriggerWindowFrame`/`DamageSkillFrame` 的游标，恢复后完成触发再进入 `DyingFrame`；旧 v1–v4 回放仍按历史事件顺序重放。

## 使用方式

- 每次已接受的游戏操作都进入命令记录。界面合并最多约一秒内的连续操作后自动保存，AI 连续行动也不会令保存一直推迟。
- 顶部“保存”或 F5 将当前局面写入手动存档。自动存档不会覆盖手动存档。
- “战报 / 存档”中可以读取手动存档、恢复自动存档，或再次手动保存。
- 读取会替换当前牌局，恢复身份、弃牌设置、自动推进和对局速度，手牌与目标的未提交高亮会清空。声音和动画保持已有本机设置；仅在没有偏好时导入旧档字段。旧声音停止，不重播历史提示。详见 [`PLAYER_PREFERENCES.md`](PLAYER_PREFERENCES.md)。
- 正常关闭窗口前同步保存尚未落盘的操作。若保存失败，窗口会说明原因并让玩家选择返回重试或继续退出。
- 自动保存有短暂合并窗口；异常终止时只能恢复到最近成功落盘的边界。

默认目录为 `%LOCALAPPDATA%\CardGame\Saves`：

| 文件 | 用途 |
| --- | --- |
| `autosave.json` | 最新自动存档 |
| `manual.json` | 玩家主动保存的存档 |
| `*.json.previous` | 上一次成功替换前的文件，保留作恢复参考 |

程序先在同目录写完整临时文件并刷新到磁盘，再替换正式文件；失败时保留旧文件并清理临时文件。上一份文件不自动代替当前存档，界面也暂未提供备份管理器。

## 核心与界面边界

`MainViewModel` 的开局、选将、出牌、技能转化、精确目标牌、响应、弃牌和 AI 推进全部通过 `Submit(GameCommand)`。`AdvanceOneStepCommand` 记录每个实际状态机步骤；`GameOptions.AdvanceAfterHumanCommands = false` 让人类命令提交后交回界面，由计时器继续推进。该设置随 Checkpoint 保存，恢复采用相同的推进边界。原有调用者默认保持自动推进至人类边界的行为。

存档外层为 `GameSaveFile`（FormatVersion 1），包含时间、自动推进设置、可选的 `MotionEnabled` 动画偏好和可信宿主 Checkpoint。首次迁移且缺少动画字段的既有存档沿用系统动画偏好；不需要升级存档版本。已开始或已恢复牌局中的开关变化会排队保存，首次启动设置开关不会覆盖旧对局。Checkpoint SchemaVersion 仍为 3，包含 seed、规则选项、完整已接受命令前缀、Revision、模式、内容包签名、内容指纹及 `RulesVersion` 行为版本；不是脱敏玩家快照。旧于 SchemaVersion 3 的存档被显式拒绝。缺少 `RulesVersion` 的旧 JSON 按 v1 恢复并继续保留旧事件语义；新 Checkpoint 使用当前规则版本；规则版本 4 的目标手牌选择只保存可重放的 `TargetCardSelectionFrame` 与命令前缀，不保存目标暗牌面。

音频新增可选 `SoundEnabled` 与 `SoundVolume`，保持 FormatVersion 1 / SchemaVersion 3；首次迁移且缺少字段的旧文件默认开启音效、音量 40%。音量必须为 0–1 的有限数。文件内容校验产生的 `InvalidDataException` 也进入统一错误提示，非法设置不会逃出读取命令或替换当前牌局。

规则选项新增 `AiPolicyVersion`，同样保持 SchemaVersion 3。缺少字段的旧存档使用 v1，WPF 新开局显式使用 v3；读取和再次保存旧局仍保留存档中的 v1/v2。v3 在身份局把火攻纳入公开攻击证据，同时保留 v2 的既有战术与国战证据语义；未知策略版本会被拒绝，当前牌局不受影响。兼容性测试使用四份升级前捕获的状态/事件哈希，以及实际缺少版本字段的 WPF JSON 文件，详见 [`TACTICAL_AI.md`](TACTICAL_AI.md)。

读取时先创建独立引擎并重放、验证所有命令，再替换活动引擎。损坏、缺失、错误版本或不兼容模式不会更改当前牌局。普通错误提示保留到玩家主动操作，后台自动保存不会擦掉读取失败的信息。替换引擎时注销旧事件订阅，并重新构建公开战报与牌桌。

响应 `ChoiceId` 显式指定 JSON 构造函数，保证候选 ID 读回后保留；出牌目标、回合末弃牌集合以及制衡/青囊主动技能选牌集合及回春牌/目标集合在命令提交前复制、记录后只读，观察者修改调用者数组也不能污染回放。规则 v17 的经典制衡命令可同时记录手牌与公开装备 ID，恢复时仍按各自来源牌区重放；v1–v16 保留手牌限定。规则 v18 的兵粮寸断按战斗距离 1 选目标并允许奇才豁免，即使目标在无懈链中用尽手牌仍置入判定区；v1–v17 的同一命令前缀继续按“目标有手牌”、结算时空手则跳过效果的历史语义重放。规则 v19 的火攻允许自选目标，展示牌通过待结算帧恢复公开状态但仍位于目标手牌；v1–v18 按他人目标及展示牌处理区/弃牌区历史路径恢复。规则 v20 从命令前缀重建当前回合是否已在出牌阶段使用酒，即使酒效随后被杀消费也继续过滤第二张酒；v1–v19 保留消费后可再次使用的历史合法动作。暂停在主动技能或急救濒死 Prompt 时，Checkpoint 保留当前命令前缀和私有选牌候选，恢复后仍由同一玩家提交；急救转化牌恢复后继续用有效 `Peach` 结算、用 `UsedPeachPhysicalCardKind` 和移动账本保留原始实体牌型。
