# 本地存档与恢复

## 使用方式

首次启动展示开局面板；有自动存档时可以选择“继续上次对局”，也可从“战报 / 存档”读取独立的手动存档。

- 已接受的操作进入命令记录，自动保存合并最多约一秒内的连续操作；连续 AI 行动也会按该节奏落盘。
- 顶部“保存”或 F5 写入手动存档，自动保存使用独立槽位。
- 成功读取后恢复牌局、弃牌设置、自动推进和对局速度，清空未提交的手牌与目标选择。
- 声音和动画由 [本机偏好](PLAYER_PREFERENCES.md) 独立保存，读取牌局时保持本机设置；历史音效不会重新播放。
- 正常关闭窗口前刷新待保存操作；保存失败时可以返回重试或继续退出。
- 教学局面不写入正式存档。

自动保存存在短暂合并窗口，异常终止只能恢复至最近成功落盘的边界。

## 文件结构与写入

默认目录为 `%LOCALAPPDATA%\CardGame\Saves`：

| 文件 | 用途 |
| --- | --- |
| `autosave.json` | 最新自动存档 |
| `manual.json` | 玩家主动保存的存档 |
| `*.json.previous` | 正式文件成功替换前的一份备份 |

[GameSaveFile](../src/CardGame.Wpf/Persistence/GameSaveStore.cs) 保存格式版本、UTC 保存时间、自动推进开关、可选的对局速度 ID 和可信宿主 Checkpoint。格式版本以其 `CurrentFormatVersion` 为准；缺少速度 ID 时使用标准速度。读取和写入校验文件格式、命令记录长度与速度选项，并限制文件大小。

写入先在同目录生成完整临时文件并刷新到磁盘，再替换正式文件，保留上一份备份；失败时清理临时文件。备份用于恢复参考，当前读取入口仍明确指向所选自动或手动槽位。

## Checkpoint 与回放

[GameCheckpoint](../src/CardGame.Core/Replay.cs) 包含：

| 字段 | 用途 |
| --- | --- |
| `SchemaVersion` | Checkpoint 结构格式 |
| `Options` | 种子、座位、模式选项、AI 策略及推进设置 |
| `Commands` | 按顺序接受的完整命令前缀 |
| `Revision` | 提交次数，必须与命令条数一致 |
| `ModeId` | 当前模式 |
| `ContentPackages` | 有序内容包 ID 与版本签名 |
| `ContentHash` | 内容定义的规范化指纹 |

结构版本以 `GameCheckpoint.CurrentSchemaVersion` 为准。`GameReplay.Restore` 先检查元数据完整性、结构版本、包签名和内容指纹，再创建独立引擎，按当前实现逐条提交命令。每条命令重新检查行动者、Revision、PromptId 和合法候选；回放结束还需匹配记录中的模式与 Revision。

随机序列、询问、候选、牌区、程序帧和父子结算由命令前缀确定性重建。存档保存的是可重放输入，运行中的结算栈不作为独立恢复入口。命令集合在接受时复制冻结，调用者或观察者不能事后污染已记录的选择。

`CreateCheckpoint` 要求健康会话全部由 `Submit` 驱动，且 Revision 与命令记录一致。直接通过兼容适配 API 推进的混合状态不能捕获为 Checkpoint。可信存档包含种子与私有命令，不属于可发送给其他玩家的快照。

## 桌面加载与失败保护

[MainViewModel.Persistence.cs](../src/CardGame.Wpf/ViewModels/MainViewModel.Persistence.cs) 根据存档的内容包签名选择受支持的 Registry，并检查本地座位、模式、人数和速度选项。先完整恢复独立引擎，成功后才接入活动界面、重建战报和牌桌，并注销旧引擎订阅。

读取、校验或回放失败时，桌面初始化新牌局并暂停自动推进，显示“读取失败”及原因。初始化不排队自动保存，直接关闭也不会立即覆盖读取失败的源文件；玩家后续实际操作按正常保存流程处理。

规则执行异常会停止会话。普通保存拒绝故障牌局，已有槽位保持原内容；诊断报告在独立目录保存最后可信命令前缀和失败命令，参见 [异常日志与复现材料](EXCEPTION_REPORTS.md)。

本地文件替换和备份不能提供跨进程共同写入同一槽位或断电后的文件系统保证；当前恢复以实际通过结构、内容和命令校验为准。
