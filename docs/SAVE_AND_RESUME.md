# 本地存档与恢复

牌局现在可以关闭后继续。首次启动只展示开局面板，不覆盖已有存档；有自动存档时显示“继续上次对局”，手动存档有独立的读取入口。

rules 143 后续残留清理已移除权计、自立、排异、单骑、英魂、潜袭、仁心、峻刑、御策、父魂、奇策、智愚、武魂、醇醪、弓骑、解烦和贞烈的旧专属执行链；当前追忆与武魂都已绑定通用拥有者死亡窗口，醇醪、弓骑、解烦和贞烈也只从公共程序进入。保留历史包定义/指纹不意味着旧执行器会自动绑定当前程序；历史身份仍只服务其明确包边界。

当前开发边界为 rules v164／技能 schema 54／`standard-classic-generals@1.139.0`，Checkpoint schema 仍为 3。命令前缀恢复顾雍的目标集合与公开手牌、李典的私密四选二及置底顺序、逐点伤害选择；致命伤害先完成濒死，再开启伤害后收益窗口，武魂标记例外地在受限的前置窗口记录。嵌套刚烈、伤害程序引发的失去体力／濒死及冻结距离须精确重建。疠火连续转化、贞烈、解烦和秘计等既有约束继续保留。恢复要求当前 rules、Checkpoint schema、包签名和内容 hash 全部精确匹配，不迁移旧开发存档。

本批 schema 54 另增精确实体牌型条件、伤害牌可领取选项与按正常摸牌计划选择／扣数，接入朱桓、界曹操、界张辽；公共 AI 评分变化统一以 rules 164 隔离。契约见 [schema 54](content/skill-composition/RUNTIME_V54.md)。

历史规则行为版本 5 曾将致命伤害的伤害后触发置于濒死之前；该顺序不是当前语义。rules 163 的前置标记、濒死、后置收益分别恢复各自父帧与游标，不能从历史描述推断当前仍可在濒死前靠忘隙等技能摸牌。

历史交付快照（v127，非当前门禁）。v115 的共享拼点子帧改变了既有拼点事件与暂停点；v116 把当先、伏枥、称象迁入通用生命周期程序；v117 把距离、攻击范围、摸牌数、杀次数和手牌上限统一为可组合、可解释的 schema 12 规则查询；v118 加入 schema 13 的冻结触发事实、`PlayEnding`／`TurnEnding` 生命周期窗口、可序列化结束阶段父游标和精确武将正反面状态原语，并将精策、据守、闭月迁入通用程序；v119 加入 schema 14 `CardsMoved`、可序列化的原子移动批次／嵌套父批次上下文以及逐牌／逐批出现策略，并将枭姬、连营迁入通用程序；v120 加入 schema 15 `AfterDamageApplied`、每次／每点伤害候选、绑定牌来源位置、通用伤害牌／来源牌选择和动态补牌表达式，并将标准／经典奸雄、反馈、遗计、节命迁入通用程序；v121 加入 schema 16 `DrawPhaseStarting`、摸牌后继续点与跳过出牌阶段标记，并将标准／经典英姿迁入通用程序；v122 再以 schema 17 加入加量／替代模式、通用多目标选择与随机暗手牌转移，并将经典突袭迁入同一窗口；v123 以 schema 18 加入动态亮牌数量、花色过滤、绑定牌分流与按牌数回复，并将经典再起迁入同一窗口；v124 以 schema 19 加入普通摸牌调整及带来源、牌型和回合期限的用牌伤害修正，并将经典裸衣迁入同一窗口；v125 以 schema 20 加入互斥分支、动态势力数摸牌和类型化回合动作／规则／目标策略，并将经典将驰与自守迁入同一窗口；v126 以 schema 21 加入共享判定结果绑定和按最终判定牌颜色授予的回合牌转换，并将经典双雄迁入同一窗口；v127 以 schema 22 加入受控濒死状态下的拥有者牌区清理、连环状态设置与固定值回复，并将经典涅槃迁入通用程序。项目尚未发布，恢复时只接受 schema、当前 rules v127、内容包签名和内容哈希全部精确匹配的 Checkpoint；其他开发期存档直接判为过期，不做迁移或版本规范化。对应当前内容批次为 `standard@1.14.0`、`standard-active-skills@1.1.0`、`standard-classic-generals@1.108.0`；1.13.0／1.0.0／1.107.0 定义和指纹仅保留给现有历史构造。完整边界见 [`DEVELOPMENT_GATES.md`](DEVELOPMENT_GATES.md)。下文关于 v102–v114 的段落保留为历史交付记录，其中“旧规则 + 新内容包”的双门禁描述已不再适用。

开发期兼容验证只覆盖当前组合：存档记录的规则版本、内容包签名与内容哈希必须共同精确匹配。人为改写 `RulesVersion` 或使用旧开发存档都会被拒绝，不要求逐技能关闭新功能。

rules v120 的伤害后程序不增加 Checkpoint 顶层字段。`DamageTriggerWindowFrame` 与 `ProgramSkillFrame` 中的伤害来源、目标、实际点数、实体伤害牌、出现序号、选择游标、绑定牌 ID 及其冻结来源位置，都由内容签名、内容 hash 和已接受命令前缀确定性重建；暂停在反馈发动、经典反馈来源牌、遗计交牌或节命目标 Choice 时恢复，必须得到相同私有投影、牌区移动、事件与父伤害继续点。1.12.0／1.100.0 Registry 只保留历史定义与指纹，不会使已移除的专属伤害执行器重新生效。

rules v121 的摸牌开始程序同样不增加 Checkpoint 顶层字段。`ProgramLifecycleTriggerWindowFrame` 保存 `CompleteDrawPhase` 继续点、候选游标和延后的 `SkipPlayPhaseAfterDraw`；通用程序帧保存当前英姿候选及选择。暂停在经典英姿发动／跳过 Choice 时恢复，会先完成剩余加量程序，再恰好执行一次正常摸牌并进入相同后续阶段。1.13.0／1.101.0 Registry 只保留历史定义与指纹，不会复活已移除的专属英姿决策或被动摸牌 modifier。

rules v122 的替代摸牌程序仍不增加 Checkpoint 顶层字段。父帧新增 `NormalDrawReplaced`，突袭程序帧保存已选目标集合；暂停在发动 Choice 或一至两目标组合 Choice 时恢复，均会复验当前合法目标。成功完成替代后终止本窗口剩余候选并跳过正常摸牌；跳过突袭则继续后续加量程序与一次正常摸牌。1.102.0 Registry 只保留历史定义与指纹，不会复活已移除的 `DecisionKind.Tuxi`、专属 AI/WPF 路由或被动替代钩子。

rules v123 的亮牌替代同样沿用现有程序帧：再起按发动时已损失体力亮出牌堆顶牌，按红桃与非红桃过滤为两个绑定集合，红桃进入弃牌堆、其余牌进入拥有者手牌，并按红桃数量回复。发动 Choice、冻结亮牌集合、分流移动、回复和完成游标均由已接受命令前缀重建；1.103.0 Registry 只保留历史定义与指纹，不会复活已移除的 `DecisionKind.Zaiqi`、专属 AI/WPF 路由或旧执行器。对局内技能绑定索引不进入 Checkpoint：它在恢复后的首次读取按技能授权 revision 与国战主副将选择／显隐状态惰性重建，HP、手牌、装备及其他实时条件仍在执行时求值。

rules v124 的摸牌调整继续复用同一父帧，新增的 `NormalDrawAdjustment` 与候选游标一起由命令前缀重建。裸衣发动时先写入 -1 调整，再向通用回合卡牌效果存储授予带稳定帧／指令键的伤害修正；恢复不会重复授予，回合结束会统一清理。伤害结算仍以原始用牌者与实际来源同时匹配，所以恢复后的直接杀加伤、决斗反向负例、连环负例与类型化事件保持一致。1.104.0 Registry 只保留历史定义与指纹；旧 `DecisionKind.Luoyi` 和事件 DTO 仍可反序列化为数据契约，但专属回合标记与执行路径不再可达。

rules v125 的互斥分支仍复用 `ProgramLifecycleTriggerWindowFrame` 和 `ProgramSkillFrame`，父窗口以组后候选游标保证一次选择只推进整个组；已选择分支由接受的通用 `ProgramTrigger` 命令重建，未选分支只产生可审计的跳过结果。将驰与自守授予的动作禁止、规则修正和目标限制都带稳定帧／指令身份写入同一回合策略存储，重复恢复不会重复授予，回合结束统一清理。`ProgramExecutionPlan` 只缓存不可变定义指令，不进入 Checkpoint，也不缓存当前对局状态。1.105.0 Registry 保留历史定义和指纹，不会重新接通已删除的专属将驰／自守路径。

rules v126 的判定摸牌程序沿用现有 `JudgmentFrame`、`ProgramLifecycleTriggerWindowFrame` 与 `ProgramSkillFrame`，不新增 Checkpoint 顶层字段。`ProgramSkill` 判定继续点保存父程序帧、结果绑定名及公开可见性；最终判定牌经过改判和可选天妒后，以同一实体牌身份重建公开绑定。按颜色授予的回合转换以技能、帧和指令身份写入通用回合存储，不单独序列化；恢复 accepted command 前缀会重建相同的异色【决斗】合法动作并在回合结束统一清理。1.106.0 Registry 保留历史双雄定义和指纹，不会与当前 schema 21 路径混用。

rules v127 的濒死状态程序同样不增加 Checkpoint 顶层字段。暂停时由现有 `DyingResolution`、`ProgramSkillWindowContext` 和 `ProgramSkillFrame` 保存父濒死帧、候选技能实例、绑定 ID 及指令游标；接受发动后，三区逐牌移动、连环状态、回复帧、摸牌和实例化整局限次均由命令前缀确定性重建。1.107.0 Registry 仍发布带 `SkillKind.Niepan` 的历史定义，只有 1.108.0 使用 schema 22，不允许交叉恢复。

## 使用方式

- 每次已接受的游戏操作都进入命令记录。界面合并最多约一秒内的连续操作后自动保存，AI 连续行动也不会令保存一直推迟。
- 顶部“保存”或 F5 将当前局面写入手动存档。自动存档不会覆盖手动存档。
- “战报 / 存档”中可以读取手动存档、恢复自动存档，或再次手动保存。
- 读取会替换当前牌局，恢复身份、弃牌设置、自动推进和对局速度，手牌与目标的未提交高亮会清空。声音和动画保持已有本机设置；仅在没有偏好时导入旧档字段。旧声音停止，不重播历史提示。详见 [`PLAYER_PREFERENCES.md`](PLAYER_PREFERENCES.md)。
- 正常关闭窗口前同步保存尚未落盘的操作。若保存失败，窗口会说明原因并让玩家选择返回重试或继续退出。
- 自动保存有短暂合并窗口；异常终止时只能恢复到最近成功落盘的边界。

默认目录为 `%LOCALAPPDATA%\CardGame\Saves`：

| 文件 | 用途 |
| --- | --- |
| `autosave.json` | 最新自动存档 |
| `manual.json` | 玩家主动保存的存档 |
| `*.json.previous` | 上一次成功替换前的文件，保留作恢复参考 |

程序先在同目录写完整临时文件并刷新到磁盘，再替换正式文件；失败时保留旧文件并清理临时文件。上一份文件不自动代替当前存档，界面也暂未提供备份管理器。

## 核心与界面边界

`MainViewModel` 的开局、选将、出牌、技能转化、精确目标牌、响应、弃牌和 AI 推进全部通过 `Submit(GameCommand)`。`AdvanceOneStepCommand` 记录每个实际状态机步骤；`GameOptions.AdvanceAfterHumanCommands = false` 让人类命令提交后交回界面，由计时器继续推进。该设置随 Checkpoint 保存，恢复采用相同的推进边界。原有调用者默认保持自动推进至人类边界的行为。

存档外层为 `GameSaveFile`（FormatVersion 1），包含时间、自动推进设置、可选的 `MotionEnabled` 动画偏好和可信宿主 Checkpoint。首次迁移且缺少动画字段的既有存档沿用系统动画偏好；不需要升级存档版本。已开始或已恢复牌局中的开关变化会排队保存，首次启动设置开关不会覆盖旧对局。Checkpoint SchemaVersion 仍为 3，包含 seed、规则选项、完整已接受命令前缀、Revision、模式、内容包签名、内容指纹及 `RulesVersion` 行为版本；不是脱敏玩家快照。旧于 SchemaVersion 3 的存档被显式拒绝。缺少 `RulesVersion` 的旧 JSON 按 v1 恢复并继续保留旧事件语义；新 Checkpoint 使用当前规则版本；规则版本 4 的目标手牌选择只保存可重放的 `TargetCardSelectionFrame` 与命令前缀，不保存目标暗牌面。

音频新增可选 `SoundEnabled` 与 `SoundVolume`，保持 FormatVersion 1 / SchemaVersion 3；首次迁移且缺少字段的旧文件默认开启音效、音量 40%。音量必须为 0–1 的有限数。文件内容校验产生的 `InvalidDataException` 也进入统一错误提示，非法设置不会逃出读取命令或替换当前牌局。

规则选项新增 `AiPolicyVersion`，同样保持 SchemaVersion 3。缺少字段的旧存档使用 v1，WPF 新开局显式使用 v3；读取和再次保存旧局仍保留存档中的 v1/v2。v3 在身份局把火攻纳入公开攻击证据，同时保留 v2 的既有战术与国战证据语义；未知策略版本会被拒绝，当前牌局不受影响。兼容性测试使用四份升级前捕获的状态/事件哈希，以及实际缺少版本字段的 WPF JSON 文件，详见 [`TACTICAL_AI.md`](TACTICAL_AI.md)。

读取时先创建独立引擎并重放、验证所有命令，再替换活动引擎。损坏、缺失、错误版本或不兼容模式不会更改当前牌局。普通错误提示保留到玩家主动操作，后台自动保存不会擦掉读取失败的信息。替换引擎时注销旧事件订阅，并重新构建公开战报与牌桌。

响应 `ChoiceId` 显式指定 JSON 构造函数，保证候选 ID 读回后保留；出牌目标、回合末弃牌集合以及制衡/青囊主动技能选牌集合及回春牌/目标集合在命令提交前复制、记录后只读，观察者修改调用者数组也不能污染回放。规则 v17 的经典制衡命令可同时记录手牌与公开装备 ID，恢复时仍按各自来源牌区重放；v1–v16 保留手牌限定。规则 v18 的兵粮寸断按战斗距离 1 选目标并允许奇才豁免，即使目标在无懈链中用尽手牌仍置入判定区；v1–v17 的同一命令前缀继续按“目标有手牌”、结算时空手则跳过效果的历史语义重放。规则 v19 的火攻允许自选目标，展示牌通过待结算帧恢复公开状态但仍位于目标手牌；v1–v18 按他人目标及展示牌处理区/弃牌区历史路径恢复。规则 v20 从命令前缀重建当前回合是否已在出牌阶段使用酒，即使酒效随后被杀消费也继续过滤第二张酒；v1–v19 保留消费后可再次使用的历史合法动作。暂停在主动技能或急救濒死 Prompt 时，Checkpoint 保留当前命令前缀和私有选牌候选，恢复后仍由同一玩家提交；急救转化牌恢复后继续用有效 `Peach` 结算、用 `UsedPeachPhysicalCardKind` 和移动账本保留原始实体牌型。

规则 v21 曾为经典英姿引入专属发动/跳过 Prompt，v1–v20 曾保留自动多摸一张的历史语义；当前 v121 已删除两条专属执行路线并改由 schema 16 通用程序恢复，历史内容定义不复活旧运行器。

规则 v22 的经典天妒由命令前缀重建“判定结果已生效、判定牌仍在 `Judgment(owner)`”的发动/跳过 Prompt；答复后将牌移入手牌或弃牌堆，再恢复原判定父结算。`standard-classic-generals@1.0.0` 的旧郭嘉武将池仍按原内容指纹加载，v1–v21 不创建天妒窗口。

规则 v23 的经典反间由命令前缀重建目标侧四花色 Prompt；恢复时仍未抽取或投影周瑜手牌，答复后才用同一随机状态选择并转移实体牌，花色不同分支继续恢复普通伤害链。经典包 1.1.0 恢复旧单技能周瑜，1.0.0 同时恢复旧周瑜与旧郭嘉；v1–v22 不发布反间动作。
规则 v24 的经典观星由命令前缀重建发动/跳过和逐张顶/底排序 Prompt；恢复后的私有牌面、剩余候选、已选顺序与牌堆顶切片完全一致，完成后再继续延时判定与摸牌。经典包 1.2.0 恢复旧单技能诸葛亮，1.1.0/1.0.0 再按各自历史池恢复周瑜与郭嘉；v1–v23 不发布观星选择。
