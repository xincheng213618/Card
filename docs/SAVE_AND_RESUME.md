# 本地存档与恢复

牌局现在可以关闭后继续。首次启动只展示开局面板，不覆盖已有存档；有自动存档时显示“继续上次对局”，手动存档有独立的读取入口。

规则行为版本 5 引入的兼容边界继续保留：若恢复点停在致命伤害的伤害后触发窗口，命令前缀会保留 `DamageTriggerWindowFrame`/`DamageSkillFrame` 的游标，恢复后完成触发再进入 `DyingFrame`；旧 v1–v4 回放仍按历史事件顺序重放。

## 使用方式

- 每次已接受的游戏操作都进入命令记录。界面合并最多约一秒内的连续操作后自动保存，AI 连续行动也不会令保存一直推迟。
- 顶部“保存”或 F5 将当前局面写入手动存档。自动存档不会覆盖手动存档。
- “战报 / 存档”中可以读取手动存档、恢复自动存档，或再次手动保存。
- 读取会替换当前牌局，恢复身份、弃牌设置、自动推进和对局速度，手牌与目标的未提交高亮会清空。声音和动画保持已有本机设置；仅在没有偏好时导入旧档字段。旧声音停止，不重播历史提示。详见 [`PLAYER_PREFERENCES.md`](PLAYER_PREFERENCES.md)。
- 正常关闭窗口前同步保存尚未落盘的操作。若保存失败，窗口会说明原因并让玩家选择返回重试或继续退出。
- 自动保存有短暂合并窗口；异常终止时只能恢复到最近成功落盘的边界。

默认目录为 `%LOCALAPPDATA%\CardGame\Saves`：

| 文件 | 用途 |
| --- | --- |
| `autosave.json` | 最新自动存档 |
| `manual.json` | 玩家主动保存的存档 |
| `*.json.previous` | 上一次成功替换前的文件，保留作恢复参考 |

程序先在同目录写完整临时文件并刷新到磁盘，再替换正式文件；失败时保留旧文件并清理临时文件。上一份文件不自动代替当前存档，界面也暂未提供备份管理器。

## 核心与界面边界

`MainViewModel` 的开局、选将、出牌、技能转化、精确目标牌、响应、弃牌和 AI 推进全部通过 `Submit(GameCommand)`。`AdvanceOneStepCommand` 记录每个实际状态机步骤；`GameOptions.AdvanceAfterHumanCommands = false` 让人类命令提交后交回界面，由计时器继续推进。该设置随 Checkpoint 保存，恢复采用相同的推进边界。原有调用者默认保持自动推进至人类边界的行为。

存档外层为 `GameSaveFile`（FormatVersion 1），包含时间、自动推进设置、可选的 `MotionEnabled` 动画偏好和可信宿主 Checkpoint。首次迁移且缺少动画字段的既有存档沿用系统动画偏好；不需要升级存档版本。已开始或已恢复牌局中的开关变化会排队保存，首次启动设置开关不会覆盖旧对局。Checkpoint SchemaVersion 仍为 3，包含 seed、规则选项、完整已接受命令前缀、Revision、模式、内容包签名、内容指纹及 `RulesVersion` 行为版本；不是脱敏玩家快照。旧于 SchemaVersion 3 的存档被显式拒绝。缺少 `RulesVersion` 的旧 JSON 按 v1 恢复并继续保留旧事件语义；新 Checkpoint 使用当前规则版本；规则版本 4 的目标手牌选择只保存可重放的 `TargetCardSelectionFrame` 与命令前缀，不保存目标暗牌面。

音频新增可选 `SoundEnabled` 与 `SoundVolume`，保持 FormatVersion 1 / SchemaVersion 3；首次迁移且缺少字段的旧文件默认开启音效、音量 40%。音量必须为 0–1 的有限数。文件内容校验产生的 `InvalidDataException` 也进入统一错误提示，非法设置不会逃出读取命令或替换当前牌局。

规则选项新增 `AiPolicyVersion`，同样保持 SchemaVersion 3。缺少字段的旧存档使用 v1，WPF 新开局显式使用 v3；读取和再次保存旧局仍保留存档中的 v1/v2。v3 在身份局把火攻纳入公开攻击证据，同时保留 v2 的既有战术与国战证据语义；未知策略版本会被拒绝，当前牌局不受影响。兼容性测试使用四份升级前捕获的状态/事件哈希，以及实际缺少版本字段的 WPF JSON 文件，详见 [`TACTICAL_AI.md`](TACTICAL_AI.md)。

读取时先创建独立引擎并重放、验证所有命令，再替换活动引擎。损坏、缺失、错误版本或不兼容模式不会更改当前牌局。普通错误提示保留到玩家主动操作，后台自动保存不会擦掉读取失败的信息。替换引擎时注销旧事件订阅，并重新构建公开战报与牌桌。

响应 `ChoiceId` 显式指定 JSON 构造函数，保证候选 ID 读回后保留；出牌目标、回合末弃牌集合以及制衡/青囊主动技能选牌集合及回春牌/目标集合在命令提交前复制、记录后只读，观察者修改调用者数组也不能污染回放。规则 v17 的经典制衡命令可同时记录手牌与公开装备 ID，恢复时仍按各自来源牌区重放；v1–v16 保留手牌限定。规则 v18 的兵粮寸断按战斗距离 1 选目标并允许奇才豁免，即使目标在无懈链中用尽手牌仍置入判定区；v1–v17 的同一命令前缀继续按“目标有手牌”、结算时空手则跳过效果的历史语义重放。规则 v19 的火攻允许自选目标，展示牌通过待结算帧恢复公开状态但仍位于目标手牌；v1–v18 按他人目标及展示牌处理区/弃牌区历史路径恢复。规则 v20 从命令前缀重建当前回合是否已在出牌阶段使用酒，即使酒效随后被杀消费也继续过滤第二张酒；v1–v19 保留消费后可再次使用的历史合法动作。暂停在主动技能或急救濒死 Prompt 时，Checkpoint 保留当前命令前缀和私有选牌候选，恢复后仍由同一玩家提交；急救转化牌恢复后继续用有效 `Peach` 结算、用 `UsedPeachPhysicalCardKind` 和移动账本保留原始实体牌型。

规则 v21 的经典英姿同样由命令前缀重建摸牌阶段的发动/跳过 Prompt，答复后继续原回合；v1–v20 保留自动多摸一张的历史语义。

规则 v22 的经典天妒由命令前缀重建“判定结果已生效、判定牌仍在 `Judgment(owner)`”的发动/跳过 Prompt；答复后将牌移入手牌或弃牌堆，再恢复原判定父结算。`standard-classic-generals@1.0.0` 的旧郭嘉武将池仍按原内容指纹加载，v1–v21 不创建天妒窗口。

规则 v23 的经典反间由命令前缀重建目标侧四花色 Prompt；恢复时仍未抽取或投影周瑜手牌，答复后才用同一随机状态选择并转移实体牌，花色不同分支继续恢复普通伤害链。经典包 1.1.0 恢复旧单技能周瑜，1.0.0 同时恢复旧周瑜与旧郭嘉；v1–v22 不发布反间动作。
规则 v24 的经典观星由命令前缀重建发动/跳过和逐张顶/底排序 Prompt；恢复后的私有牌面、剩余候选、已选顺序与牌堆顶切片完全一致，完成后再继续延时判定与摸牌。经典包 1.2.0 恢复旧单技能诸葛亮，1.1.0/1.0.0 再按各自历史池恢复周瑜与郭嘉；v1–v23 不发布观星选择。

规则 v25 的经典护驾由命令前缀重建曹操的发动 Choice、当前魏势力候选游标和提供者自己的闪/转化牌/八卦阵 Choice；恢复后仍只向当前 responder 投影私有候选。实体闪由提供者支付，但有效响应者仍是曹操；提供者八卦失败只推进护驾游标，全部失败再回到曹操原响应窗。经典包 1.3.0 恢复旧单技能曹操，v1–v24 不发布护驾选择。

规则 v26 的经典激将由命令前缀重建刘备的主动目标或杀响应上下文、当前蜀势力候选游标，以及提供者自己的实体杀/转化牌 Choice；恢复后仍只向当前 responder 投影私有候选。成功时实体牌来源与刘备的有效使用/响应身份分别保留，主动杀继续恢复目标的闪、伤害、濒死与收尾链；全部失败不消耗刘备出杀次数，响应分支恢复刘备自己的杀或放弃候选。经典包 1.4.0 恢复不含激将的刘备，v1–v25 不发布该动作。

规则 v27 的经典救援不增加新的暂停态：恢复命令前缀重建同一濒死者、当前 responder、实体桃和恢复帧后，再按规则版本、主公技能、提供者吴势力及非本人条件确定回复量。v27 命中时发布 `JiuyuanAppliedEvent` 和 2 点 `RecoveryAppliedEvent`；v1–v26 或经典包 1.5.0 保持 1 点且不发布救援事件。

规则 v28 的奇袭会在 Checkpoint 中通过原始 `PlayCardCommand.CardId`、`PlayedCardKind=Dismantlement`、目标与公开目标牌 ID 重建。恢复到无懈或暗手牌选择暂停点时，实体牌仍位于 Processing，公开帧保存有效牌型过河拆桥，而移动前缀保留其来自 Hand 或 Equipment 的真实来源；v27 不产生奇袭合法动作。

规则 v29 的克己把 Play 阶段实际使用或打出杀的历史由已接受命令重放重建；暂停在 Discard 阶段的 `DecisionKind.Keji` 时，Checkpoint 保存同一 PromptId 与发动/跳过 Choice。恢复后发动仍直接结束回合并保留超上限手牌，跳过仍进入普通弃牌；rules v28 不产生该暂停点。

规则 v30 的突袭在 Draw 阶段冻结有手牌的公开候选座位，并把全部一人/两人组合与普通摸牌写入 `DecisionKind.Tuxi` Prompt。Checkpoint 恢复后使用同一命令和确定性随机状态挑选目标暗手牌，因此暂停与完成分支的私有手牌、移动账本和事件序列一致；rules v29 不产生该暂停点。

规则 v31 的裸衣在 Draw 阶段把发动/跳过写入 `DecisionKind.Luoyi` 私有 Prompt，并在发动后保存仅本回合有效的标记。Checkpoint 恢复后，少摸一张、杀/决斗基础伤害 +1、回合结束清除标记以及决斗反向伤害的实际来源保持一致；`AttackResolution.CardUserSeat` 与可变的实际 `SourceSeat` 分离，确保许褚应战失败时对方造成的伤害不被误加成。rules v30 不产生该暂停点并保留旧归因。

规则 v32 的强袭把 0–1 张武器牌、一个攻击范围内目标和每阶段限次状态写入主动技命令/帧。空牌分支的体力成本、手牌或装备区武器的统一弃置链、`SourceSkill=Qiangxi` 且来源牌为空的伤害帧，以及伤害后技能游标都可由 Checkpoint 精确恢复；若体力成本先令典韦濒死，暂停存档保留主动技帧与其上的濒死帧，桃救回后继续原目标伤害。rules v31 不发布该动作。

规则 v33 的断粮在命令中继续记录实体牌 ID 与有效 `SupplyShortage` 牌型，并由命令前缀重建判定区内的有效牌型映射。恢复后公开快照、同名延时牌去重、观星用途、无懈和判定结算仍把该牌视为兵粮寸断，牌区诊断、移动账本和最终弃置仍保留黑色基本牌/装备牌的原始身份；映射只随牌留在判定区。rules v32 不发布该转化或距离 2 动作。

规则 v34 的洛神把初次/重复标记和私有 `DecisionKind.Luoshen` 一并保存在宿主帧状态中；恢复后仍能从同一发动/停止边界继续，黑色判定牌只进入甄姬手牌一次，红色结果只弃置一次。倾国沿用响应命令中的实体牌 ID 与有效 `Dodge` 牌型，恢复和重放不会把黑色物理牌伪装成闪。rules v33 不发布甄姬或两项技能。

规则 v35 的集智把待恢复的普通锦囊牌型、来源座位和原父结算位置保存在 Checkpoint 中：初始普通锦囊暂停时恢复同一 `CardUseFrame` 声明边界，无懈可击触发时恢复同一 `NullificationWindowFrame` 反制游标。发动只产生一次 `DrawPile → Hand(owner)` 的 `skill.jizhi.draw` 移动，跳过不摸牌；恢复后选择不会重复使用锦囊或重开已经完成的窗口。rules v34 与经典包 1.14.0 不发布集智 Choice。

规则 v36 的铁骑把待恢复的杀来源/目标、发动状态和当前 `AttackResolution` 保存在 Checkpoint 中：杀指定目标后先恢复同一私有铁骑 Choice，发动后恢复共享 `JudgmentFrame` 与鬼才替换游标。红色结果只给当前杀记录禁止闪响应，完成或恢复后都不会再发布实体闪、倾国、八卦阵或护驾入口；黑色结果或跳过只发布一次普通响应。rules v35 与经典包 1.15.0 不发布铁骑 Choice。

规则 v37 的烈弓把待恢复的杀来源/目标、已核验的公开手牌计数边界和当前 `AttackResolution` 保存在 Checkpoint 中：出牌阶段的杀指定满足体力或攻击范围条件的目标后，恢复同一私有烈弓 Choice。发动只给当前杀记录禁止闪响应，完成或恢复后都不会再发布实体闪、倾国、八卦阵或护驾入口；跳过或双条件均不满足只发布一次普通响应。rules v36 与经典包 1.16.0 不发布烈弓 Choice。

规则 v38 的旧版狂骨不新增暂停点：Checkpoint 仍只保存已接受命令，恢复时由同一伤害命令重建 `DamageTriggerWindowFrame`，以实际伤害来源、结算时公开战斗距离和伤害量确定锁定恢复；`RecoveryAppliedEvent` 与 `KuangguRecoveredEvent` 的顺序和实际回复量必须一致。rules v37 与经典包 1.17.0 不生成狂骨候选或恢复事件。

规则 v39 的无双会新增连续响应暂停点，但不引入新的私有数据结构：第一张闪或杀完成后，同一 `CardUseFrame` 重新压入下一张牌的 `ResponseWindowFrame`；恢复仍由已接受的玩家响应或宿主步进命令重建，实体牌、八卦阵、护驾、激将与转换牌各自沿原路径支付。`RequiredResponseProgressEvent` 只公开当前次数和总次数。rules v38 与经典包 1.18.0 保留单次响应。
