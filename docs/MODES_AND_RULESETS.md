# 模式、选将与发牌设计

本文件规定项目采用的模式规则。部分现实产品存在多个 2v2/国战版本；这里明确选择项目自己的 v1 规则，避免实现时混用不同版本。

主动技能扩展模式当前使用 21 名共享武将池，其中五项主动技能、`standard:mashu` 和 `standard:qicai` 两项被动技能均由 Registry 映射；马术通过 Core 的公开 `GetCombatDistance` 统一影响杀与顺手牵羊的合法性，奇才通过 Core 的公开合法动作查询解除距离型锦囊限制，AI 和 WPF 都只消费这些公开结果。

可抵消的锦囊效果在实际结算前会进入固定座次的有限无懈窗口；当前 responder 只收到自己的私有 `DecisionKind.Nullification` Prompt，无懈之间可以继续互相抵消，`NullificationWindowFrame`、响应事件和处理区移动共同记录链条，普通快照不泄漏其他玩家的牌面或牌 ID。复杂响应时机、多伤害嵌套和复杂改判仍未开放；鬼才的基础判定替换窗口已在 K7 切片中开放。

铁索连环使用时只允许精确的一名或两名其他存活角色；目标状态以公开 `PlayerSnapshot.IsChained` 和 `IronChainStateChangedEvent` 表示，使用牌在 `Processing` 中等待有限无懈窗口。火杀或雷杀对连环目标造成伤害后，Core 按固定目标顺序清除连环并以同额、同属性生成传导伤害；普通杀不触发传导，复杂属性抗性和更深层多伤害嵌套仍未开放。

本阶段新增 `standard:yuanhu`/“援护者”作为受约束的非受伤者触发示例：其他角色受到正伤害后，援护者通过 `DamageTriggerScope.OtherLivingPlayer` 在私有 Prompt 中弃置一张自己的手牌，使固定受伤目标回复 1 点体力。刚烈则由受伤者候选触发，红色判定后向伤害来源发布仅其可见的弃两张手牌/承受 1 点伤害 Choice；两者都沿同一伤害触发游标、`DamageSkillFrame` 与牌区/事件契约完成，具体技能效果和更复杂跨座位触发仍需各自的类型化入口。

过河拆桥与顺手牵羊的单目标效果还支持公开装备和公开判定区牌分支：当前规则版本的手牌效果由使用者在私有 Prompt 中选择不透明牌位，公开区域牌由带 `TargetCardId` 的精确 Choice 逐张选择；公开区域身份只沿已经公开的装备区/判定区和事件投影传播，隐藏手牌继续脱敏。v1–v3 回放保留历史确定性盲弃/盲取语义。

## 1. 通用模式契约

```csharp
record GameModeDefinition(
    ModeId Id,
    string Name,
    PlayerCountRange Players,
    ISeatPolicy Seats,
    ICampPolicy Camps,
    IGeneralSelectionPolicy GeneralSelection,
    IInitialStatePolicy InitialState,
    IFirstPlayerPolicy FirstPlayer,
    IDeathRewardPolicy DeathReward,
    IVictoryPolicy Victory,
    IAiModePolicy AiPolicy);
```

模式只能通过策略和类型化模式事件改变流程；禁止在 `GameEngine` 中写 `if (mode == "guozhan")`。

共同流程：座次 → 阵营/身份 → 选将 → 初始化体力/技能 → 构造牌堆 → 洗牌 → 逐轮发牌 → 游戏开始事件 → 首回合。

## 2. 选将系统

### 通用对象

```text
GeneralPool：本模式允许的武将和剩余副本
GeneralOffer：只对一个玩家可见的候选
GeneralSelection：一名或多名已选择武将
GeneralConflictPolicy：是否允许重复、冲突如何重发
GeneralRevealPolicy：开局是否公开
```

### 单将身份模式

- 主公先选；候选数量由模式配置，当前 Standard 演示为 3；
- 其他玩家获得互不泄漏的候选，当前 Standard 演示为每人 3；
- MVP 顺序选择，后续可改为同时选择；
- 被选武将从共享池移除，不允许重复；
- AI 只根据自身身份、候选武将标签和公开主公武将评分；
- 选将结果在全部完成后一次公开。

### 国战双将

- 候选只包含可组成同势力组合的武将；
- 每人选择主将和副将，不能是同一实例；
- 两名武将及技能开局均为暗置；
- 主/副将顺序影响体力计算、部分技能和后续副将替换；
- AI 评分维度包括势力、技能互补、体力、珠联璧合标签和明置时机。

## 3. 洗牌和发牌

`DeckRecipe` 必须列出每个实体牌的 DefinitionId、花色、点数和可选版本标签。数量配方只适合临时 Demo，不作为完整标准牌堆的最终格式。

洗牌使用引擎注入的确定性随机源。发牌采用逐轮顺时针：每轮每名玩家得到一张，直到达到模式初始手牌数。每次牌移动产生内部完整事件；玩家视图只能看到自己收到的牌定义，其他人只看到数量。

发牌不足必须在开局验证阶段失败，不能发到一半才报错。

| 主忠胜利 | 主公存活且反贼、内奸全部死亡 |
| 反贼胜利 | 主公死亡，且不满足内奸唯一存活条件 |
| 内奸胜利 | 主公死亡时内奸为唯一存活角色 |

当前 Standard WPF 默认使用 `GameOptions.UseInteractiveSetup = true` 的私有单将选将流程；传入 `false` 才使用旧固定构造兼容路径。

## 5. 五人身份局

项目采用以下明确配置：

| 项目 | 规则 |
| --- | --- |
| 人数 | 5 |
| 身份 | 1 主公、1 忠臣、2 反贼、1 内奸 |
| 公开/选将/体力 | 与八人身份局相同 |
| 初始手牌 | 每人 4 |
| 首行动者 | 主公 |
| 死亡奖惩与胜利 | 复用身份模式策略 |

实现必须只替换玩家数量和 RoleDistribution，不复制一套五人状态机。当前 Core 已用同一状态机支持 `PlayerCount = 5` 的 1/1/2/1 分布和交互式选将；测试已覆盖固定 seed 的 5 人全 AI 选将/整局终止。更大规模的 1000-seed 场景矩阵和所有身份坐在人类座位的批量覆盖仍是 K4 扩展验证项。

## 6. 2v2 v1

本项目先采用简洁、公开阵营的教学规则；不声称等同于任何商业客户端的特定赛制。

| 项目 | 规则 |
| --- | --- |
| 人数 | 4 |
| 阵营 | 青队 2 人、赤队 2 人，开局公开 |
| 座次 | A1、B1、A2、B2 交错 |
| 选将 | 每人单将；候选私有；结果同时公开 |
| 体力 | 武将基础体力，无主公加成 |
| 初始手牌 | 每人 4；先手首个摸牌阶段少摸 1，作为先手补偿 |
| 首行动者 | seed 确定的队伍一号位，录像记录结果 |
| 队友信息 | 阵营和角色状态公开，手牌仍隐藏 |
| 死亡奖惩 | v1 不设置身份局式摸三/弃牌；死亡者牌进入弃牌堆 |
| 胜利 | 对方两名角色全部死亡 |

AI 的敌我关系来自公开 TeamId，不使用身份嫌疑模型；目标分数仍复用生存、击杀、牌值和技能协同模块。

后续若增加其他 2v2 规则，创建新的 ModeId，不在 v1 上堆配置开关。

## 7. 国战 Lite

先完成能验证双将与暗将框架的 Lite 版本：

| 项目 | 规则 |
| --- | --- |
| 人数 | 4–8 |
| 身份 | 无主忠反内；阵营来自已明置武将势力 |
| 武将 | 两名同势力武将，主将+副将，开局暗置 |
| 技能 | 对应武将明置后才可用；锁定技按技能声明处理 |
| 体力 | 由双将体力规则计算，计算策略独立可测试 |
| 初始手牌 | 每人 4 |
| 首行动者 | 随机座次一号位 |
| 明置 | 主将、副将可分别明置；明置事件公开势力和相应技能；在【决斗】或群体牌的【杀】响应窗口内也可明置，并只刷新该 responder 的私有响应候选 |
| 胜利 | 最后仍有存活成员的势力获胜；Lite 暂不含野心家 |

Lite 阶段不实现阵法、围攻、队列、珠联璧合奖励、野心家、变更副将和完整国战专属牌堆。文档和 UI 必须明确标识 “国战 Lite”。

当前实现：`standard-national-war-lite@1.1.0` 已注册 `national:lite-4`，Core 通过 `FactionCounts`、专属势力武将池、双将私有选将、独立明置事件和势力胜负复用既有状态机；WPF 已接入模式设置、双肖像、关系标签、指南、存档与历史结算。规则版本 7/8/9 分别覆盖双将技能、平均体力和国战武圣响应；完整国战 M3 仍未完成。

### 7.1 六人独立势力试验

`standard-national-war-ambitious@1.0.0` 在不改变四人 Lite 内容指纹的前提下注册 `national:ambitious-6`：魏 3 人、蜀 2 人、野心家 1 人。每个席位仍从自己的势力池选择两名武将；普通视图只公开已经明置的标签，AI 只读取本座视图，终局公开全部双将和势力。`SoloFactionIds` 会校验独立势力存在且恰好只有一个席位，并参与新内容哈希。

该模式明确是 M3 的人数/独立势力实验：没有珠联璧合、阵法、围攻、变更副将、专属牌堆或完整野心家单独胜利条件。若继续扩展，必须新增类型化状态和固定场景，不在该实验模式上堆隐式开关。

## 8. 完整国战

在 Lite 稳定后分批加入：

1. 势力人数上限与野心家判定；
2. 首次明置、珠联璧合和相应奖励询问；
3. 主副将体力阴阳鱼细节；
4. 队列、围攻关系及阵法技查询；
5. 变更副将；
6. 国战专属牌堆、装备与锦囊；
7. 暗将条件下的玩家视图、观战和 AI 知识模型；
8. 完整势力胜负与野心家单独胜利。

每项必须通过固定场景测试后再进入下一项。国战不得复用身份 `Role` 表达阵营；使用独立 `FactionState` 和 `RevealState`。

## 9. 模式测试矩阵

每个模式至少验证：

- 最小/最大合法人数和非法人数拒绝；
- 座次、身份/阵营数量和首行动者；
- 候选只对本人可见，选择冲突按策略处理；
- 初始体力、技能、手牌数与发牌顺序；
- 每个阵营的最小胜利场景；
- 击杀奖惩不会串用其他模式规则；
- 真人位于任意座位均可推进；
- 同 seed/同选择得到相同开局和事件流；
- 1000 个以上固定种子完整对局无卡死；
- 游戏结束时无 PendingPrompt、Processing 为空、牌实例守恒。
