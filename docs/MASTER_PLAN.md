# Card 当前实现与开发边界

Card 是本地 WPF 卡牌游戏。Core 提供确定性命令、规则结算、牌区、玩家视图和回放；Standard 内容包提供牌、装备、武将和模式；WPF 负责交互、呈现及本机持久化。

## 当前工程

| 位置 | 职责 |
| --- | --- |
| `src/CardGame.Core/` | 命令会话、结算帧、规则查询、可注册能力、事件投影、AI、Checkpoint/Replay |
| `src/CardGame.Content.Standard/` | 内容包、Registry 组合入口、模式和牌堆定义 |
| `src/Characters/` | 按人物和规则版本组织的资料、技能 JSON 与需要的运行时模块 |
| `src/CardGame.Wpf/` | 本地牌桌、选将、响应、图鉴、指南、战绩、存档与公开反馈 |
| `tests/CardGame.Core.Tests/`、`tests/CardGame.Wpf.Tests/` | 使用名称过滤的现有检查程序 |

人物目录和注册见[人物模块说明](CHARACTER_MODULES.md)，规则与展示文件见[技能程序运行时](content/skill-composition/RUNTIME.md)。内容包入口见[内容清单](content/CONTENT_MANIFEST.md)。

## 当前玩法与桌面功能

- 身份模式包含五人、八人及多种武将池；经典八人选将支持按人物去重、版本选择和加权候选。
- 公开阵营 2v2 复用选将、结算、AI、胜负、玩家视图和回放。
- 国战提供四人双将 Lite 与六人独立势力实验：暗将、明置、双将技能和体力、公开势力关系及 AI 明置。它们的规则范围见[国战说明](NATIONAL_WAR_EXPERIENCE.md)。
- 基本牌、即时锦囊、延时锦囊、装备、转换牌、无实体牌、改判、伤害、回复、濒死、死亡及插入阶段/额外回合沿原生结算帧推进。具体支持条件由内容配置及能力校验决定。
- WPF 提供手牌与目标选择、私有响应、选将、技能草稿、存档恢复、回放/观战、出牌建议、指南与教学、战绩及声音/动画偏好。运行入口见[本地游玩](LOCAL_PLAY.md)。

## 必须保持的边界

正常宿主与桌面操作通过命令会话提交，先准备事件和各玩家视图，再提交并通知观察者。玩家与 AI 使用 `CreateSnapshot(viewerSeat)`；可信诊断栈及内部牌区不作为玩家数据源。所有公开的嵌套集合在提交准备阶段冻结。

暂停状态属于其拥有帧。已支付成本和原生子结算通过类型化返回继续，不能在恢复时重复付款。规则事件使用 `AdvanceEventRulesAndQueueFact`，状态推进使用 `AdvanceRulesAndPublishState`；宿主输出通知不作为修改规则状态的入口。

Checkpoint 保存不可变开局设置、已接受命令前缀、修订号、模式、包签名和内容指纹；恢复在当前实现下重放并验证。格式与内容不匹配或重放失败时，桌面新建对局，并保留源存档。详见[存档与继续](SAVE_AND_RESUME.md)。

## 开发与验证

普通新增人物使用已有能力时，只修改人物资料、技能规则、展示和必要注册。内容指纹区分配置变化；不逐人物修改格式或内容包发布版本。无法用现有能力完整表达的规则，先形成来源、精确缺口与共享能力合同，见[能力入口与缺口](content/CORE_API_REQUESTS.md)。

开发时运行相关名称过滤。批次结束使用 `tools/Test-Changed.ps1` 的规定例行范围，记录真实耗时和失败；范围来自 `tools/VerificationScopes.psd1`。只有用户明确要求才运行 `-Full` 或未过滤检查程序。仅 UI 行为需要 WPF 检查，纯配置沿现有加载器、Registry 与机制覆盖，不添加逐人物重复定义快照。

发布、打包、提交与推送分别遵从用户授权。普通文档和开发校验不生成发布包。临时输出按 [AGENTS.md](../AGENTS.md) 清理，规则来源和必要诊断单独保留。
