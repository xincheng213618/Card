# 开发门禁边界

本项目把“内容指纹”和“引擎回放语义”分开管理，避免新增武将、技能或表现资源时反复抬高全局 `RulesVersion` 或内容包版本。

## 必须保留

- Checkpoint schema、当前规则版本、内容包签名和内容哈希必须全部精确匹配；不匹配的开发期存档直接判为过期。
- 同一内容包、同一内容哈希和同一命令前缀的解释发生变化时，统一提升当前规则版本并废弃旧开发存档，不维护迁移分支。
- 技能程序声明的最低引擎能力检查；旧规则不能执行它不理解的程序结构。
- 命令合法性、隐私、牌区守恒、原子性、帧续接和伪造输入防护。

## 不再作为门禁

- 仅新增武将、技能、卡牌、素材、说明或测试，不增加 `RulesVersion`。
- 未发布开发期不为每个武将递增内容包版本；Registry 内容哈希已经能让旧开发存档失效。只在形成明确的内容发布批次时调整包版本。
- 已由内容包版本和内容哈希隔离的功能，不再额外添加 `_rulesVersion >= N`。
- 不再为“旧规则版本 + 新内容包”补负向回归；真实旧存档必须携带并匹配它原来的包签名和内容哈希。
- 技能 JSON 的能力元数据可以先于全局规则版本解析；只有实际创建不满足最低能力的牌局时才拒绝。

## 规则版本何时可以增加

只有以下任一项成立时才增加：

1. 同一内容指纹下，既有命令的解释发生变化；
2. 事件顺序、结算帧、随机数消费或可恢复暂停点发生变化；
3. 当前开发存档需要明确失效，避免用旧命令前缀进入已经改变的结算路径。

新增内容时应验证内容哈希、正式玩法和当前 Checkpoint/Replay；不要同时制造内容包版本、全局规则版本两套逐项门槛。

## 开发期单项流程

新增普通武将或技能时默认只维护：内容定义、当前武将池、实际运行逻辑、针对性 Core 测试，以及确有 UI 变化时的 WPF 测试。不要逐项修改 `Replay.cs`、`SAVE_AND_RESUME.md`、`SKILL_COMPOSITION_DESIGN.md` 或追加旧版本对照分支。

迭代统一使用 [Test-Changed.ps1](../tools/Test-Changed.ps1)，按本次变更选择现有检查名称。脚本只构建一次，随后直接运行同一输出中的测试 DLL；默认使用仓库外稳定、项目隔离的输出目录，不发布、不清理原产物。相关验证使用名称过滤，例如：

```powershell
.\tools\Test-Changed.ps1 -CoreFilter @('execution plans', 'skill executor', 'schema-19')
.\tools\Test-Changed.ps1 -WpfFilter 'program'
# 一批共享机制整合完成后，再做一次完整 Solution/Core/WPF 验证。
.\tools\Test-Changed.ps1 -Full
```

每次输出 `summary.json`，记录定向或完整范围、过滤条件、步骤退出码、耗时和日志。定向结果只证明所选检查；零匹配、构建失败、测试失败均以非零退出，不能当通过。相同产物目录的脚本调用互斥；直接启动的 dotnet 不受该锁协调，实施任务仍统一安排构建。可通过 `-ArtifactsPath` 明确指定输出目录。

内容组合开发默认只改规则/展示定义、人物默认绑定和自身行为场景。已有 bundle 直接加入定义，不新增一套 loader、人物专用测试入口或引擎分支；不为每个人物同步维护所有架构历史文档。缺少基础能力时先补公共节点及机制边界检查，把同类需求合并验证。架构设计和共享语义变化完成一个完整批次后集中回归，不给内部每一步重复设置完整验收。

内容包历史构造仅供现有历史测试，不要求新内容继续扩展历史版本矩阵。迁移边界测试固定“首次支持版本”和相邻旧定义；除集中发布检查外，不把 `CurrentVersion` 精确值写入无关技能检查，让新增内容迫使旧检查跟着改常量。规则/schema 只随实际语义或格式能力变更，不随使用已有能力的新组合递增。

差异卫生使用 `git diff --check`。已有全库格式问题不作为每次内容迭代的新增阻断，也不为通过检查重排无关文件。必要的命令合法性、隐私、牌区守恒、暂停恢复和当前版本回放验证仍保留。

## 已清理的历史范围

原 rules v102–v114 都只是给 `standard-classic-generals` 1.80.0–1.92.0 的内容增量重复设门禁，此前统一回收到引擎语义版本 v101。共享拼点子帧曾将语义版本提升为 v115；组合式生命周期程序把当先、伏枥、称象迁入通用执行器并提升为 v116；统一规则查询随后把距离、攻击范围、摸牌数、杀次数和手牌上限归入带来源解释的组合管线并提升为 v117；v118 加入 schema 13 冻结触发事实、`PlayEnding`／`TurnEnding` 生命周期窗口、可序列化结束阶段游标和精确武将正反面状态原语；v119 加入 schema 14 `CardsMoved`、原子移动批次及嵌套父批次身份，并把枭姬／连营迁入公共程序窗口；v120 加入 schema 15 `AfterDamageApplied`、每次／每点伤害出现策略、伤害牌及来源牌选择、绑定牌交付和动态补牌表达式，并把标准／经典奸雄、反馈、遗计、节命迁入公共程序窗口；v121 加入 schema 16 `DrawPhaseStarting` 和可序列化的摸牌阶段继续点，把标准／经典英姿迁入公共程序窗口；v122 再以 schema 17 为同一窗口加入显式 `additive`／`replacement` 模式、通用一至两目标选择和随机暗手牌转移，并迁移经典突袭；v123 以 schema 18 加入按已损失体力动态亮牌、花色过滤、绑定牌分流及按绑定牌数回复，并迁移经典再起；v124 以 schema 19 加入普通摸牌调整和带牌型、来源、实际用牌者与回合期限的伤害修正，并迁移经典裸衣；v125 以 schema 20 加入互斥可选分支、动态势力数摸牌、动作禁止、规则查询修正和仅可指定自己的目标限制，并迁移经典将驰与自守；v126 以 schema 21 加入共享判定结果绑定与按绑定牌颜色授予的回合牌转换，并迁移经典双雄。对局内技能绑定索引和不可变执行计划缓存只改变当前定义的查找与取指方式，不改变事件、命令、随机数或存档结构。新存档与恢复只接受当前 v126，不迁移旧开发存档。

第二轮按重要性把 Core 中显式的运行时版本判断从 126 个减至 63 个：移除了经典技能逐项启用、神势力选择、武魂目标选择和仁德的重复版本判断，保留核心结算顺序、序列化结构、技能程序能力、国战结构及事件账本边界。旧规则版本测试只作为历史记录，不再阻断开发；当前玩法与当前版本 Replay、内容包签名及内容哈希仍严格验证。
