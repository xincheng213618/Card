## 规则来源与实现范围

现行依据为 [官方司马朗页面](https://www.sanguosha.com/hero/360) 和 hero/info 接口。来源记录、HTTP 状态、文本及图像哈希保存在 [来源档](../content/sources/ol-sima-lang-2026-10-08.json)。官方原画为 750×950；图库新增一项，原有 258 项逐项规范化内容完全保留。

郡兵分成自己的结束阶段与其他存活角色的结束阶段两个互斥入口。技能拥有者不替外人决定是否发动；真正结束回合的角色收到私有选择。接受后真实摸一张牌，排空子结算，然后将当前全部手牌交给司马朗。赠牌数量 N 固定在原结算帧；获得牌子结算后，拥有者从完整手牌、装备候选中严格选够 N 张返还。若真实子结算耗尽部分资源，强制交尽可交的 HE 牌，保留原 N，不添加未来回合债务。自己发动仅摸牌并排空子结算，不移动自己的装备。

去疾采用出牌阶段一次、已受伤、无预选牌与目标的入口。首先冻结 X 并从所有合法 HE 牌中选足 X 张；不足在命令开始前拒绝，不缩量付款、不消耗次数。真实弃置并等待子结算，随后公开已弃牌，按明确命名的费用绑定选择 0 至 X 个不同存活目标，各执行一次原生回复。弃置白银狮子导致自己回血、或产生其他牌绑定，都不重算 X。

当前文本的“至多 X 名角色”按允许自己、零目标、满体力目标实现；满体力执行原生无效回复。2018 年官方介绍对受伤目标的分析与同页正文、现行文本有差异，来源档保留该冲突。自己的郡兵补牌有历史官方分析支持；HE 返牌、资源不足交尽、阶段与子窗映射属于实现推断。没有声称已在现行官方客户端验证这些解释。

选择时统一冻结每张费用牌的有效花色，真实弃牌和子结算后仍按该收据判断是否包含黑色。无色 None 不视为黑色。没有找到官方去疾与红颜的交叉 FAQ；统一花色冻结是引擎合同选择，不能称为官方互动裁定。

## 通用能力与兼容边界

新增通用 `offerCurrentTurnHandExchange` 单节点结束阶段操作；入口限制为 owner、mandatory、Own/OtherLiving 与冻结手牌数不大于 1。原帧持有完整阶段、原父窗、候选、技能实例、内容 hash、实际回合、真实支付事实及私有选牌收据。真实 draw、gift、return 子窗逐段返回，不回退游标、不重复支付。新交换事件只带标量，实体集合保留在可信诊断帧；新收据与嵌套提示集合均防御复制为只读。

新增选牌的 nullable `requireExactCount`、`freezeSelectedCardSuits`，仅接受首个无条件 owner lost-HP、零输入主动入口。旧选牌缩水路径与旧花色条件路径保留。`selectTargets` 的具名 `sourceBind` 分支读取明确绑定的冻结数量，旧未命名 BoundCardCount 仍使用原语义；零目标常量回复安全地不生成回复子帧。新增 SupportRecovery AI 根据公开体力和关系为真实目标集合评分，包括空集合。

自己的结束阶段事实只在新交换操作中保留实际手牌值。旧已接受的自用结束阶段节点仍保留原事实形状。所有新增 nullable 字段忽略 null，旧枚举值和旧 JSON 保留。规则版本、schema、内容包版本没有调整。
