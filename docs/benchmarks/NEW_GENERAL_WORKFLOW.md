# 三路武将实施约定

这些约定来自 2026-09-26 三批实际失败与返工，用于减少重复探索；不省略行为验收。协调者加三个 Sol 是当前并发上限，三个工作进程使用同一已验收源码快照和各自构建／渲染目录。

## 派发前

协调者锁定官方年份／版本、完整人物和技能 ID、图鉴分类、技能图、可复用入口与缺口、必要验收场景。把公共能力约束按“资源／上下文／生命周期”描述，不把消费者整图写成引擎白名单。共享枚举值和 schema 由协调者统一分配；人物注册使用固定首次接入包版本。

冻结主目录所有相关源文件的 SHA-256 并复制到三个独立目录。记录派发前本机标记、实际 worker 开始、首版可编译、首次行为通过、最终测试与交付时间；缺失的时间留空，不用文件修改时间冒充精确事件。公共能力只是编译通过时不要写成行为已验收。

## 构建与测试夹具

使用 PowerShell 7 的 `pwsh`。新复制的目录没有 obj/assets，首次构建允许正常 restore，直接使用 `tools/Test-Changed.ps1`；不要先必然失败地尝试 `--no-restore`。先从 `tests/CardGame.Core.Tests/Program.cs` 和 WPF Program 查实际测试名称，名称过滤未命中不是通过。

在 PowerShell 7 会话中传数组：

```powershell
& .\tools\Test-Changed.ps1 -CoreFilter @('自己的实际测试名称', '直接受影响的公共检查') -ArtifactsPath 'C:\Temp\自己的检查目录'
```

跨进程只有一个过滤项时可用 `pwsh -NoProfile -File ... -CoreFilter '完整过滤项'`。多个过滤项应放到 `.ps1` 包装脚本或 `pwsh -Command` 的 PowerShell 表达式中，不能把逗号字符串当原生 `-File` 数组传参。每次验证保留独立产物或先归档前次 summary/logs，避免失败细节只剩手工回忆。

- 正式身份技能夹具沿用 `identity:classic-...` 模式前缀、真实势力和主公身份；护驾等正式模式行为不能在无前缀的任意测试模式中推断。
- `game.PendingDecision` 是公开投影，可能隐藏 AI 角色的私有技能提示。AI 私有暂停点应参照 `BoundaryCaoCaoIntegrationChecks` 或 `ZhuHuanChecks` 的测试内读取方式；不能因为测试看不到就改生产隐私契约。
- 先把起局推进到明确的选择／出牌／伤害窗口，再断言。按技能原因的精确牌区移动与事件断言收益，避免把随后正常摸牌混算。
- 一次有界搜索找到可复现自然场景后固定种子；不要在每次 Full 中重复遍历数千种子。界曹操决斗和丈八双牌样例均已固定为 1。
- 命令日志之外的夹具状态注入不能自动重放。真实命令分支检查 Checkpoint/Replay；注入边界只声明其实际行为覆盖，并保留自然分支的回放验证。
- 新公共能力至少有一个其他技能的合法组合用例及缺资源／错入口／旧 schema 负例，不以定义加载替代真实技能执行。

## 交付与整合

工作进程只跑人物及受影响机制的定向检查，交付相对路径、逐文件 SHA-256、实际通过数量、全部失败及未覆盖项，然后冻结源码。协调者三方合并共享文件；已有冲突导致第三份文件被跳过时，必须补入第三份所有变更，不能只删除冲突标记。

父审补验与修复单列耗时，不追改已冻结 worker 的交付时长。整合源停止写入后统一跑一次 Full，并校验执行前后全部 src/tests/tools 哈希一致。写回主目录之前检查其仍匹配整合快照，备份被覆盖文件，再逐文件核验写回哈希；保留无关脏改动。

Full 通过后只有新改动、失败或具体未解决风险才追加检查。UI 自动化为实际 WPF 控件离屏渲染，不宣称实机、多 DPI 试玩。持续目标与完成记录由协调者维护；用户已授权每批验收后及时本地提交，提交时保留其他任务的修改，不自动推送或发布。
