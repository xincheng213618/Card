来源：`docs/content/sources/ling-tong-2026-09-30.json`。

> 【旋风】弃牌阶段结束时（若你于此阶段内弃置过你的至少两张手牌）或每当你失去装备区里的牌后，你可以依次弃置一名有牌的其他角色的两张牌，或选择两名有牌的其他角色，弃置这些角色的各一张牌。

## 实现设计

| 技能 | 形态 | 依赖 |
| --- | --- | --- |
| 旋风·弃牌阶段分支 | trigger `discard-phase-gust`：discardPhaseEnded 窗口（subject owner、turnOwnerScope **own**、optional）+ condition compare(turnOwnerDiscardPhaseHandDiscardCount ≥ 2) → chooseOtherOwnedCardDiscard × 2 | 既有窗口/触发值/操作 |
| 旋风·装备区分支 | trigger `equipment-loss-gust`：cardsMoved 窗口（sourceZones [equipment]、perBatch、optional、无 excludedMovementReasons、无 ignoreOwnSkillMovements）→ chooseOtherOwnedCardDiscard × 2 | 既有窗口/操作（屯田样例） |

- 弃牌阶段分支：引擎既有回合弃牌阶段手牌台账（`CollectDiscardPhaseHandDiscard`，张昭张纮批为固政落地）只统计当前回合拥有者在弃牌阶段从手牌进弃牌堆的牌，与官方"于此阶段内弃置过你的至少两张手牌"精确对应；触发值 `turnOwnerDiscardPhaseHandDiscardCount`（枚举 26）解析/事实捕获/AI 上下文三侧早已接线，本批是它在触发条件中的第一个消费方。
- 装备区分支：`cardsMoved + sourceZones [equipment] + perBatch`（邓艾屯田 `judge-on-equipment-loss-outside-turn` 同款形态）。"每次失去发动一次"固化为 perBatch（一次移动批=一次失去）；无排除原因、无 ignoreOwnSkillMovements，按 BWIKI 细则覆盖被拆/被换/被顺/技能弃置交换/自身技能代价等一切失去。
- 效果语汇："依次弃置一名有牌的其他角色的两张牌，或选择两名有牌的其他角色，弃置这些角色的各一张牌"以既有 `chooseOtherOwnedCardDiscard`（弓骑同款，弃置他人牌唯一现成操作：手牌按暗置槽位、装备区按明牌，逐张选择）两步组合承载。两步自由选择的可达集 {目标 A 两张} ∪ {A、B 各一张} 与官方两分支划分完全一致；弃置区域沿用弓骑先例 hand+equipment（不含判定区）；每步自带"不弃置其他角色的牌"拒绝项。
- 提示文案由操作内置（"可以弃置一名其他角色的一张牌"+逐卡选项），无需 presentation optionLabels（无 chooseOption）。

## 引擎扩展清单（已落地，一处）

- **E1 `CanRunProgramTrigger` 的 `DiscardPhaseEnded` 臂按 turnOwnerScope 分支**：原臂 `owner.Seat != _currentSeat && owner.IsAlive && context.SourceSeat == _currentSeat && _phase == TurnPhase.Discard` 只服务固政类 otherLiving 观察者，硬拦截 scope-own 候选（收集侧 `TryBeginDiscardPhaseEndedProgramWindow` 的双向 turnOwnerScope 过滤早已支持 own 候选入窗，此臂是唯一单边拦截点）。改为 `owner.IsAlive && context.SourceSeat == _currentSeat && _phase == TurnPhase.Discard && (TurnOwnerScope == Own ? owner.Seat == _currentSeat : owner.Seat != _currentSeat)`——与 turnEnding/playEnding/playPhaseStarting 三臂既有形状逐字同构，otherLiving 路径语义不变。新窗口/新操作/新触发条件为零，五点注册清单不适用；无新 ProgramCompositionDefinitionChecks fixture 负担。

## 诚实归因

- **逐张可拒的偏差（既有语汇的固有限制，照实记录）**：官方文本把"依次弃两张"作为一次整组决定（0 或 2 张）；`chooseOtherOwnedCardDiscard` 每步自带拒绝项，故本实现的可观察行为是 0/1/2 张的超集——玩家可在弃第一张后拒绝第二步。这与弓骑（单张可选可拒）既有语义一致，属复用既有语汇的已知粒度，未为消除它新增共享操作；两分支的目标/张数可达集与官方完全一致。
- **弃置区域不含判定区（沿弓骑先例）**：官方"弃置…的各一张牌"未限区域，BWIKI 页未直接说明判定区；仓内同措辞的弓骑实现取 hand+equipment，本批沿用先例保持同语汇同口径，未擅自扩大。
- **`ProgramBindingResolvedEvent` 的窗口断言时点**：首版检查在接受触发前断言窗口事件，实际该事件在绑定结算推进时才发布（暴露/跳过阶段不发）——检查改为结算后断言 activated+window，属检查自身时点错误，非引擎缺陷。
- **共享资产修复（预存问题，非本批引入）**：`sync_general_art.py --phase verify` 在基线 HEAD 即失败于 `zhou-yu/201203`（盘内文件 sha256 d3bd4a1a… 与目录记录 3741dad2… 不符，HEAD 上二者已不一致）。归因：盘内 PNG 结构完整（块遍历到 IEND、574×761、778,004 字节与目录记录同长）但字节级损坏且 WPF 解码失败；现从官方 CDN 重新下载即得 3741dad2…（与目录记录一致）。判定目录元数据正确、盘内副本为损坏下载（与本仓台账在记的"对象库损坏后自实体副本重建"事件同族），遂以 CDN 原件覆盖该 PNG、未改任何元数据；修复后 verify 全过。该文件属并行批资产，整合时请协调者知悉此覆盖。
- 拒收面 fixture 首版左目搜索串误带前导 `{`（"left" 是条件对象的键而非嵌套对象起点）致 Replace 空转、用例假阴性，已修正——记一笔防再犯。
