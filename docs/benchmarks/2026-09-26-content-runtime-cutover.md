# 单内容运行路径与转换契约清理

本批基线 `790a03975cafc3faccd101987e24358f1cf1ff19`。复用已附属、无运行进程使用且已跟踪文件干净的 `general-expansion` 工作树，分支 `codex/content-runtime-cutover`；其中旧批次未跟踪副本保留。主目录由整合者在验收后写回，不由 worker 直接覆盖。

## 范围与分工

最多三个 Sol 共用本批工作树，按文件和方法分工，不再制作三个整仓副本。

用户在本批收口时确认：后续此类全局重构直接在主工作区协作，由主任务分配写入范围、统一验收和提交。本批沿用当前工作树完成验证并一次写回，避免中途重复搬迁。

- 内容路径：先删除引擎及回放 API 的可空默认注册表，再按编译错误整批修调用，删除引擎独立演示内容执行路径。演示内容可以作为显式内容包存在，不能有第二套引擎执行逻辑或旧 API 兼容重载。
- 转换及数值：先删除 `ICardConversionSkillRule`、`INumericSkillRule` 及聚合适配器，所有现行消费者改用 Program。缺失的牌种转换、濒死转桃与按牌种查询距离作为公共能力实现，不增人物分支。
- 命令和 host：删除默认抛错/忽略参数的 Program host 方法，所有 host 显式实现接口。命令执行明确的合法动作及转换来源，删除来源猜测和布尔响应到八卦的旧适配。
- 主任务：能力和版本协调、源变化检查、内容池审计、整批验证、写回及本地提交。不逐武将全量检查；不推送或发布。

## 基线与初始编译证据

从上一批最终构建程序集审计完整注册表：160 个技能、118 位武将、11 个模式，其中 62 个技能仍无 Program 且带 C# 技能绑定。转换相关的 9 个注册为：`boundary:qixi`、`classic:duanliang`、`classic:guose`、`classic:jijiu`、`classic:qixi`、`sp:guan-yu-wusheng`、`standard:jijiu`、`standard:longdan`、`standard:wusheng`。此口径是完整注册表，不等同于单个正式模式选将池。

删除可空默认内容接口后，首次正常还原构建得到 63 个错误：62 处缺注册表参数及 1 个连带的静态局部函数错误。删除 host 的 21 个默认抛错及扩展参数转发后，生产 Core 编译通过，完整测试工程暴露 22 个 FakeRuntime 缺失成员。保留首次错误日志，随后成批修复，禁止重新添加默认体掩盖缺口。

## 集成审查

本批使用 rules 169 / rules schema 59 / presentation schema 3；解析器只接受这一种当前格式。转牌新增基本/装备类别筛选、锦囊输出及濒死转桃；没有执行路径的多牌锦囊、主动转桃组合在加载时直接拒绝。

沿实际消费者继续检查后，火计、看破、连环也纳入相同转换能力，共迁移 12 个现行技能注册。连环的使用与重铸均提交同一准确来源，界面显式选择技能来源后再确认；存档和回放保留该来源。涅槃、双雄不可达的旧流程、事件和专有状态一并删除。

审查还发现并修正了接口删除之外的隐含路径：单牌转牌和锁定身份曾拼造技能实例 ID，改为使用实际授予记录；多牌转换不再漏入单牌候选。响应选项和执行命令保留完整来源，原生火杀/雷杀仍可按杀响应。武将定义取消首技能和附加技能投影，只保存技能集合；Core 的重复演示武将与牌堆目录退役。

11 个未注册、全库无业务调用的旧测试方法合计约 1,951 行删除，其中包含历史内容指纹和已被当前行为测试替代的旧接口验证；仅为压制未用提示而保留的 8 个委托引用及其独有辅助函数也一并删除。现行模式、武将、技能和选将池另作前后审计，不能通过删注册掩盖未迁移行为。

实现期间有一次误将自制测试程序的筛选参数写成 `--filter value`，触发了非预期的全量运行；该输出只用来定位失败，不作为正式验收。Core/WPF 测试入口现会立即拒绝该参数和空筛选，防止静默扩成全量。正式全量由主任务在三个 worker 停写后统一执行。
