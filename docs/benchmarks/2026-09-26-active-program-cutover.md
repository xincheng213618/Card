- Program 方向扩展公共选择约束、操作描述、唯一执行器和受控 host；内容方向迁移现行注册与对应行为测试。主任务负责 AI、WPF、整合验证，并接手阶段累计和虚拟决斗的独立运行时实现。
- 移除 `UseSkillCommand`，主动技能统一提交准确的 `UseProgramSkillCommand`；装备仍使用自己的领域命令。内部 AI 的提示选择记录使用 `SkillChoice`，它不是可执行的旧主动命令别名。
- 模型统一使用 rules 170 / rules schema 60，不保留旧格式执行和历史指纹。

## 实现要点

同花色组合、武器槽候选、合法目标与共享次数上限由 Program 发布和执行时复验。WPF 和 AI 不再查询旧主动目录，也不根据人物名称判断乱击选牌是否合法。强袭两种付费方式共享 `usageGroup`，不能通过切换入口多用一次。

阶段累计选牌计数使用现有 `SkillRuntimeStateStore` 的 Phase 用量记录。公共操作只记录本次冻结选择的张数、判断是否第一次跨过指定阈值，再绑定 `crossed` 或 `not-crossed`；回复由后续普通 `recover` 执行。没有新增仁德专用账本。标准演示版仁德的单次赠牌门槛和受赠者回复、经典仁德的阶段累计门槛和自己回复保持为两个明确的当前定义。

虚拟决斗通过 Program 父帧进入共用决斗响应流程；第一个选择目标是决斗来源，第二个是响应目标，后续伤害来源随双方应答变化。男性限制属于内容的目标筛选规则，通用决斗原语不包含该限制。若付款触发其他效果、导致参与者死亡，跳过已无法开始的决斗，不对已付成本的合法流程抛异常。

WPF 主动目标草稿原先会排序为座位号。本批改为保留点击顺序，指南按同一顺序显示，练习模式退出后也按原顺序恢复并提交。对应行为检查使用离间的逆座位选择，避免普通多目标集合相等掩盖顺序错误。

旧主动限次实际按整回合记录。此次迁移保留为 `usesPerTurn: 1`，可重复技能照旧重复。与“出牌阶段限一次”文案在额外出牌阶段下的差异单独作为规则审计待项；没有因更换执行器而隐式修改限次语义。

弃置成本统一为原区域直接移动到弃牌堆，不再制造只为旧主动链服务的 Processing 中间记录。验收检查精确来源、去向、支付次数、装备失去触发和回放；不保留旧事件形状。UI 技能按钮按武将拥有技能的顺序显示，多个技能仍用各自精确的 Program 身份提交。
