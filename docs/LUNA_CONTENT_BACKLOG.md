# 内容开发工作清单

本文是内容维护的工作入口。当前可用能力、目录与模式见[内容现状](CONTENT_BACKLOG.md)和[内容清单](content/CONTENT_MANIFEST.md)。人物实现状态以当前资料、规则、注册和行为为准。

## 工作划分

| 范围 | 主要位置 | 完成条件 |
| --- | --- | --- |
| 人物与技能配置 | `src/Characters/<人物>/<版本>/Content`、`Skills` | ID、属性、技能绑定、来源与当前规则一致，加载及注册有效 |
| 共享规则能力 | `src/CardGame.Core/`、人物的注册运行时模块 | 能力校验、原生费用与返回、查询/事件/隐私完整，有针对性行为覆盖 |
| 内容装配 | `src/CardGame.Content.Standard/` | 包依赖、牌堆、模式和将池引用完整，不重复登记 |
| UI 与素材 | `src/CardGame.Wpf/`、素材目录表 | 文案、选择器、技能状态和资源绑定准确，不以素材已下载代替接入 |
| 来源与合同 | `docs/content/sources/`、规则说明和裁定文档 | 产品线、页面/客户端版本、正式规则与工程解释可区分 |

独立人物可以并行编写自己的资料、规则和运行时文件；共享 Core、中央注册及共同协议由同一负责人协调。合入时保留并发修改与现有精简覆盖。

## 每项规则的核对顺序

- 对照采用的官方规则、FAQ 和保存的来源档案，核实触发时点、主体、目标、费用、次数、期限及失源/死亡后的续接。
- 查当前原语与正式消费者；已有能力直接配置，缺口写成可验证的共享能力请求。
- 检查所有实际牌区、实体来源、原生用牌/打出分类和类型化父返回。零实体牌不伪造实体或移动。
- 检查本人、对手和旁观者视图；AI 只评估本座视图和已发布选择。
- 需要新行为覆盖时使用现有名称过滤和小型固定夹具，验证暂停与完成态的 Checkpoint/Replay。
- UI 行为变动才增加 WPF 覆盖，核实文本和选择器实际可见；需要真人/硬件环境的验收单独标明。

## 验证与版本

开发验证使用 `tools/Test-Changed.ps1 -CoreFilter '<名称>'` 或 `-WpfFilter '<名称>'`；批次例行运行使用不带过滤的 `tools/Test-Changed.ps1`。规定范围由 `tools/VerificationScopes.psd1` 维护，实际耗时和失败来自本次输出，不沿用文档中的旧计数。

完整运行仅在用户明确请求时使用 `-Full` 或未过滤检查程序。普通配置新增依靠内容指纹区分，不逐人物增加 JSON 格式或包发布版本。格式版本只取其源文件；存档恢复使用当前实现、schema、内容和命令验证。

临时构建、截图和日志属于任务输出，按 [AGENTS.md](../AGENTS.md) 管理和清理。长期文档保留规则与来源，不依赖临时目录证明当前实现。
