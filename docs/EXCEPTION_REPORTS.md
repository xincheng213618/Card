# 异常日志与复现材料

桌面版把异常报告保存在 `%LocalAppData%\CardGame\Logs\Exceptions\`。每次异常使用 UTC 时间和随机 ID 创建独立目录，不使用自动或手动存档槽；新开局、再次保存和再次报错都不会覆盖已有报告。

牌局命令抛异常时，先保存原始异常，再处理停止推进和恢复提示。相同故障牌局在命令层与界面层只记录一次。若目录不可写，界面明确显示日志写入失败，仍保持停止推进和已有存档保护。界面线程、进程和未观察任务的未处理异常也记录堆栈；记录行为不改变原本的异常传播方式。

报告文件：

| 文件 | 用途 |
| --- | --- |
| `exception.txt` | 异常时间、入口、原始异常、内部异常和调用堆栈；优先写入并刷新到磁盘 |
| `manifest.json` | 运行时、系统、程序集模块 ID、规则版本、修订号和故障状态 |
| `checkpoint.json` | 健康会话的已提交命令，或故障会话的最后可信命令前缀；包含随机种子、选项、内容包与指纹 |
| `failed-command.json` | 直接导致 `Submit` 抛异常、尚未提交的命令；非命令入口异常可能没有此文件 |
| `battle-log.json` | 最近 400 条牌局记录 |
| `resolution-stack.json` | 故障时的可信宿主结算帧诊断 |
| `card-zones.json` | 故障时的完整实体牌位置诊断 |
| `player-snapshot.json` | 本地玩家视图 |
| `capture-errors.txt` | 单项材料采集失败的原因；一项失败不阻止其余材料保存 |
| `README.txt` | 材料说明和复现步骤 |

通过 `GameCheckpointJson.Deserialize` 和 `GameReplay.Restore`，使用当前规则实现及匹配的内容包恢复可信前缀，再用 `CommandJson.Deserialize` 读取失败命令，提交这一条命令。异常发生后的可变状态和结算栈只用于诊断，不作为恢复入口。规则标记不限制恢复，复现仍保留文件结构、内容指纹和命令校验；缺少可信前缀或失败命令时，报告会注明限制。

这些报告属于本机可信宿主材料，可能包含其他玩家的隐藏牌、身份与私有选择。它们不会进入普通玩家快照或公共牌局记录，也不会自动上传。异常报告不会自动轮换覆盖，排查完成后可手动删除相应目录。
