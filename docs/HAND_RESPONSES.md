# 手牌响应与群体结算修复 · 2026-09-12

受到杀或南蛮入侵等效果时，玩家现在可以直接选中底部亮起的响应牌，再点击主按钮或按 Enter。救援、无懈、火攻展示和火攻弃牌同样使用这个流程。1–9 选择手牌，Esc 只取消选牌，不代表放弃响应。

操作区和指南显示实际选择的效果，支持急救等牌转化。选中不会立即消耗牌；关闭指南、取消新局面板及教程往返保留选择。主按钮不再自动使用第一张响应牌。中央候选仍可直接执行装备、技能、放弃或具体响应。

手牌映射只使用当前玩家询问中的完整候选。一张牌对应多个效果时，需要在中央明确选择，例如急救者的红色酒可选择按桃转化或直接用酒救援。规则 v41 的经典华佗若以红色装备急救，也只在中央候选出现，不伪装成手牌。不能从手牌直接选取时，悬停说明会解释原因。新手演练的闪响应也改用同样操作。

规则 v42 的借刀杀人同样使用中央精确 Choice：持武器者可以直接点击亮起的手牌杀，也可以在中央选择武圣装备转化、发动激将，或明确选择“交出【具体武器】”。候选只对当前持武器者可见；若武圣支付的就是所装备武器，Core 会按移除该武器后的攻击范围验证目标。选择杀后进入普通杀响应链，不由界面模拟伤害或武器转移。

规则 v43 的贯石斧在最后一张有效【闪】已经抵消【杀】后，向攻击来源发布另一个私有中央 Choice。每个发动按钮都明确列出两张实体牌及其“手牌/装备区”来源，也可选中贯石斧本身；另有单独的不发动按钮。WPF 只提交该精确 Choice，Core 负责验证归属、弃置两张牌并恢复原杀的伤害链。

规则 v44 的丈八蛇矛把自己的两张手牌组合投影为一个精确【杀】响应 Choice；界面显示两张牌但只提交一个 Choice，Core 同时移动和结束两张实体牌。规则 v45 的雌雄双股剑则在异性目标被指定后先向来源显示发动/跳过，再只向目标显示自己每张手牌的精确弃置按钮与“令来源摸一张牌”按钮；另一方视图不会看到该私有候选。

## 实战阻塞修复

固定种子 1 的八人牌局中，反馈角色被万箭齐发打到 0 点体力，先取得造成伤害的万箭齐发，随后救援失败阵亡。实体牌因阵亡进入弃牌堆，而万箭齐发仍需要处理后续目标。原来的处理区一致性检查只允许该牌在目标手里，从而错误中断下一次推进。

群体结算现在记录该实体牌是否已被伤害技能取得，允许取得后合法进入手牌、弃牌堆或因洗牌进入摸牌堆；未取得的卡牌仍受原处理区检查约束。没有修改伤害、救援或胜负规则，也没有升级规则版本与存档格式。

`GroupClaimChecks` 从真实命令前缀恢复到阵亡前，检查实体牌清理、后续目标响应、效果只结束一次、结算栈和处理区清空，以及最终存档确定性恢复。复现数据位于 `tests/CardGame.Core.Tests/Fixtures/group-claim-before-death.json`，仅供可信宿主测试，不向玩家提供其他人的私有状态。
