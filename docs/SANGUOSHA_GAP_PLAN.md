# 三国杀差距评估与 Sol 持续迭代计划

评估日期：2026-09-18。基线提交：`f607ece`。本报告由当前源码、完整构建、Core/WPF 回归及官方基础牌说明交叉核实。

## 结论与目标边界

当前项目是可玩、可存档、有 AI 和桌面交互的三国题材卡牌原型。单机体验骨架已经较完整，但距离规则较完整的经典三国杀单机版仍有明显距离：当前内容混合了经典规则、演示简化和原创技能。优先补规则一致性与真实武将组合，才能使后续内容积累有效。

不将所有功能折算成一个完成率：基础工程、单机交互较成熟；经典规则和内容仍处中段；完整国战只完成部分切片；真人联网系统尚未建立。测试全绿证明当前实现符合现有测试，不能直接证明符合三国杀。

默认近期目标是**经典身份玩法的本地可玩版本，逐步支持标准内容及军争扩展**。每批必须声明所采用的规则版本，不能混用标准、界限突破、国战和线上活动规则。现有演示包与历史存档继续兼容。完整国战、局域网/在线对战排在身份玩法稳定之后；账号、商城和运营服务不属于近期迭代目标。

## 按优先级施工

同一级按表内顺序推进。每行再拆成能独立验证与提交的小块；单张牌/技能的代码、AI、界面文案和测试应一并闭环。用户补充指出“鬼才是司马懿的”，因此首批先完成 P0-将名/归属核对，并尽早交付司马懿等正确的正式人物，再继续基础牌修正。多技能基础若是必要前置，可直接提前。

| 顺序 | 优先级 | 工作与差距 | 验收门槛 |
| --- | --- | --- | --- |
| 1 | P0 | 正确武将归属与经典规则：首先处理“鬼才者→司马懿”“刚烈者→夏侯惇”、华佗误挂反馈等演示配置，并审查真实技能效果；随后修正乐不思蜀、兵粮寸断、酒、诸葛连弩，核对防具和技能时机。 | 正式池人物、技能和体力有依据；需要多技能时提前交付最小兼容模型；四花色判定、自己/他人濒死和装备交互场景；旧规则回放兼容。 |
| 2 | P1 | 正式武将模型与武将归位：多技能模型、首批正式武将、曹操护驾及刘备激将已落地；其他主公技、完整标准武将池、更多频次与组合时机仍缺。 | 继续将代表人物做完整；支持同将多技能、频次/时机和体力；图鉴、选将、AI、存档一致；不静默改旧包指纹。 |
| 3 | P1 | 真实牌堆与缺失牌：现有 90 张计数配方按 ID 循环生成花色/点数；补选定版本的实体牌配方，并补借刀杀人及关键武器/防具。 | 配方有版本和来源，实体牌逐张指定类型/花色/点数；新牌含合法目标、取消、死亡中断、AI、回放；先借刀，再丈八/贯石斧/青龙等武器，再藤甲/白银狮子等交互。 |
| 4 | P1 | 深层结算与技能正确性：扩展多技能触发、使用/打出/弃置区分、濒死与伤害触发时序、连环与防具、重复救援、目标死亡后的父帧续接。 | 固定场景覆盖多层嵌套与中途存档；卡牌守恒、隐私、非法命令不改状态、终局无悬挂帧；先有真实内容需求再增加扩展点。 |
| 5 | P2 | AI 与平衡：已有基础战术，但尚不能据少量整局通过证明身份推断、内奸控场、技能组合和装备收益可靠。 | 建固定种子对局矩阵，记录胜率/回合数/非法动作/卡死/明显失策；按身份和武将检查；改策略保留旧存档策略版本。 |
| 6 | P2 | 依据用户截图完善大厅、独立武将图鉴和开局流程：模式入口、系列/势力筛选、姓名搜索、完整技能/体力说明、身份揭示、选将对比与确认、清晰的本方技能区；强化判定和响应反馈，并同步文档。 | 大厅→模式→身份说明→选将→发牌→对局→结算/再战连贯可用；实际鼠标/键盘、小窗口与 DPI 验收；交互使用真实引擎状态。 |
| 7 | P3 | 完整国战：现为魏蜀 Lite 和六人独立势力试验；补完整势力池、暗将/明置时机、奖励、野心家、珠联璧合、国战牌堆与专属技能。 | 先选定国战版本，逐项可测；完整双将/隐私/胜负/奖惩和 AI 回归；不能把现有 M3 试验标成完整国战。 |
| 8 | P3 | 真人多人系统：当前没有网络宿主、房间、多人客户端、断线重连与同步实现。 | 先局域网房间和服务端裁决，再重连/托管/超时/观战；始终使用脱敏视图和命令边界。公网部署与服务采购另行处理。 |

第一阶段完成项 1；第二阶段围绕项 2、3 建立经典身份玩法内容；第三阶段用项 4、5、6 达到稳定可玩的单机版本；第四阶段再做完整国战与多人。后两项是独立的大里程碑，不能按几张新卡的工作量估计。

## 已确认的高优先级证据

1. **乐不思蜀、兵粮寸断已按正式花色版本化。** 规则 v11 起，乐不思蜀仅红桃通过、否则跳过出牌阶段；兵粮寸断仅梅花通过、否则跳过摸牌阶段。`JudgmentResolvedEvent.Succeeded`/`DelayedCardResolvedEvent.JudgmentSucceeded` 对这两张牌表示“命中安全花色”，跳阶段由独立字段表达。鬼才按具体判定类型、目标阵营和当前公开结果选牌；v1–v10 保留历史红黑行为与 AI 路径，WPF 指南也按存档规则版本切换文案。
2. **酒已按正式濒死规则版本化。** 规则 v12 起只有濒死者本人能从自己的私有候选中使用酒自救；其他角色仍可使用桃。规则 v3–v11 的跨座位酒救援由 `UsesHistoricalCrossSeatAlcoholRescue` 保留，Prompt、AI、事件、牌区移动和恢复流程继续按旧存档版本执行；v1/v2 原本也只允许自救。
3. **武器牌面攻击范围已版本化。** 规则 v13 起，诸葛连弩攻击范围为 1 且仍允许出牌阶段使用任意数量的杀，青釭剑攻击范围为 2 且直接杀无视防具；`EquipmentDefinition.WeaponAttackRange` 表达牌面范围。v1–v12 继续按旧实现回放：连弩基础范围 +1、青釭剑沿默认范围 1。Standard 包内容签名保持冻结，Core 规则日志和 WPF 卡牌说明按存档规则版本投影。
4. **防具效果与响应时机已版本化。** 规则 v14 起，八卦阵在当前实现所有需要闪的路径（直接杀与万箭齐发）都可发动；群体判定成功/失败写入 `GroupResponseEvent`，但不伪造物理闪。仁王盾不再从合法目标列表移除黑色杀，而是在杀声明、目标确定后发布 `ArmorEffectAppliedEvent` 并令效果无效；青釭剑仍无视防具。v1–v13 保留直接杀八卦阵和仁王盾目标过滤。
5. **空城的杀/决斗目标限制已版本化。** 官方标准诸葛亮原文同时禁止空手角色成为杀或决斗目标。规则 v15 的经典身份局通过通用 `ProhibitsCardTarget` 查询过滤三类杀与决斗，合法动作、AI、WPF 目标和命令复核共用同一结果；v1–v14 与演示模式保留原先只禁杀的行为。
6. **奸雄的可选性与牌型范围已版本化。** 官方标准曹操原文是受到伤害后“可以获得造成此伤害的牌”。规则 v16 的经典身份局复用伤害触发候选游标，为任何仍在 `Processing` 的伤害牌发布私有取得/跳过 Choice；取得后同一实体牌进入曹操手牌。v1–v15 与演示模式保留原先自动取得杀类伤害牌的历史语义。延时锦囊等不在处理区的伤害来源尚未纳入本次切片。
7. **制衡的选牌区域与频次已版本化。** 官方孙权页明确为“出牌阶段限一次”且可弃置“任意张牌”，不限定手牌。规则 v17 的经典身份局把自己的手牌与公开装备合并为同一候选集合，混合来源逐张进入处理区后弃置并摸等量牌，发动后写入本阶段已用标记；v1–v16 与演示模式保留原先手牌限定、可重复发动的历史语义。
8. **兵粮寸断的正式目标条件已版本化。** 官方牌页明确目标为“距离为 1 的一名其他角色”，不要求目标有手牌。规则 v18 起合法动作、命令复核和 AI 共用战斗距离，奇才通过既有锦囊距离豁免扩展目标；目标在无懈链中打空手牌仍正常置入判定区。v1–v17 保留“目标有手牌”以及结算时空手则跳过效果的历史语义，Standard 包签名不变，WPF 按存档规则版本投影说明。
9. **火攻的目标与展示牌生命周期已版本化。** 官方牌页写的是“有手牌的一名角色”，没有排除使用者；目标“展示”手牌也不等于弃置。规则 v19 起合法动作允许自选，但要求使用火攻后仍有牌可展示；展示牌继续位于目标手牌，仅由 `PublicRevealedCards` 临时公开，自选时该牌可支付同花色弃牌并造成 1 点火焰伤害。v1–v18 保留只能选择其他角色以及展示牌 `Hand → Processing → DiscardPile` 的历史路径，AI、牌区守恒、WPF 说明与 Checkpoint/Replay 均覆盖两条分支。
10. **酒的出牌阶段限次已版本化。** 官方牌页明确饮酒令本回合下一张杀伤害 +1，且“一回合只能使用一次”。规则 v20 起第一次在出牌阶段使用酒会写入回合内限次标记；直接杀只消费酒效、不清除此标记，下一回合开始才重置。v1–v19 保留旧实现中酒效被杀消费后可再次饮酒的合法动作。濒死自救仍走独立路径，不计入出牌阶段限次；伪造命令、AI、WPF 指南、牌区守恒和 Checkpoint/Replay 均有覆盖。
11. **正式武将持续用独立包归位。** `standard-classic-generals@1.0.0` 新增刘备/仁德、孙权/制衡、司马懿/反馈+鬼才、夏侯惇/刚烈、华佗/青囊+急救；1.1.0 再加入郭嘉/天妒+遗计，1.2.0 用英姿+反间的经典周瑜替换旧单技能定义，1.3.0 再用观星+空城的经典诸葛亮替换旧单技能定义，1.4.0 再用奸雄+护驾的经典曹操替换旧单技能定义，1.5.0 为经典刘备补齐仁德+激将，1.6.0 为经典孙权补齐制衡+救援，1.7.0 再加入黄盖/苦肉，1.8.0 再加入甘宁/奇袭，1.9.0 再加入吕蒙/克己，1.10.0 再加入张辽/突袭，1.11.0 再加入许褚/裸衣。`ContentGeneralDefinition.AdditionalSkillIds` 与运行时有序技能投影只在经典规则启用。旧演示包及 1.0–1.10 历史定义和内容指纹均保留。
12. **牌堆不是经典实体配方。** `StandardContentPackage.cs:361` 为 90 张计数配方；`src/CardGame.Core/Content.cs:316` 的建牌路径循环分配花色/点数。牌堆差异会改变闪、桃、判定、火攻、转换技与 AI 的实际收益。
13. **存档可用，但并非完整状态快照。** `src/CardGame.Core/Replay.cs` 明确通过元数据和命令前缀重建。当前 rules=27、schema=3；旧规则版本仍逐条走各自历史语义。完整状态 Checkpoint 应由恢复性能/网络需求驱动，不能把命令恢复误报为完整状态序列化。
14. **后续需要实测的规则疑点。** 经典急救、空城、制衡、观星、护驾、激将、救援与当前处理区内奸雄边界已经闭环；仁德的“一次交牌至少一张、达到两张回复且每阶段限一次”已与选定的 2.48 新标准版公告及现有实现核对一致。其他主公技、延时伤害牌的奸雄归属和更多技能频次仍需沿 Core 调用链与选定经典版本逐项复现，再形成修复。
15. **英姿的可选性已版本化。** 官方标准周瑜页写明摸牌阶段“可以多摸一张牌”。规则 v21 的经典身份局发布私有发动/跳过 Choice，并以 `DrawSkillResolvedEvent` 记录是否发动与最终摸牌数；v1–v20 和演示模式保留自动多摸一张。
16. **天妒已进入正式郭嘉。** 官方标准郭嘉页写明自己的判定牌生效后可以获得此牌。规则 v22 在公开 `JudgmentResolvedEvent` 后、判定牌离开 `Judgment(owner)` 前发布私有发动/跳过 Choice；发动后同一实体牌进入手牌并发布 `JudgmentCardClaimedEvent`，随后恢复原判定父结算。v1–v21 与 `standard-classic-generals@1.0.0` 保留旧自动弃置路径。
17. **反间已进入正式周瑜。** 官方标准周瑜页写明目标先选择花色，再获得并展示周瑜的一张随机手牌，花色不同时受到周瑜造成的 1 点伤害。规则 v23 将花色 Choice 发布在随机牌选择之前，转移实体牌后以 `FanjianCardRevealedEvent` 公开结果，并复用普通伤害、受伤触发和濒死链；v1–v22 与经典包 1.0/1.1 保留旧单技能周瑜。
18. **观星已进入正式诸葛亮。** 官方标准诸葛亮页写明准备阶段可观看牌堆顶 X 张牌（X 为存活角色数且至多为 5），再以任意顺序置于牌堆顶或牌堆底。规则 v24 将牌面与顺序限制在技能拥有者的私有 Prompt，分两阶段明确顶/底顺序，完成后只公开数量并继续延时判定与摸牌；v1–v23 与经典包 1.0–1.2 保留旧单技能诸葛亮。
19. **护驾已进入正式曹操。** 官方曹操页写明主公需要使用或打出闪时，可以要求其他魏势力角色按行动顺序选择是否打出闪。规则 v25 将请求嵌入现有闪响应窗，逐席私有投影实体闪/转化牌与提供者自己的八卦阵；成功时实体提供者和有效响应者分开记录，全部失败后曹操仍可自行响应。v1–v24 与经典包 1.0–1.3 保留旧单技能曹操。
20. **激将已进入正式刘备。** 官方刘备技能页和规则示例明确主公需要使用或打出杀时可按行动顺序要求其他蜀势力角色提供，出牌阶段全员拒绝后仍可再次发动。规则 v26 将主动目标草稿与决斗/南蛮入侵杀响应接到同一私有游标；实体杀由提供者支付，刘备保留有效 source/responder、目标范围和出杀次数语义。v1–v25 与经典包 1.0–1.4 保留不含激将的刘备。
21. **救援已进入正式孙权。** 官方规则集明确这是锁定主公技：其他吴势力角色对濒死孙权使用桃时，该桃回复的体力 +1；恢复事件流程也把救援列为回复数值修正。规则 v27 在既有濒死桃使用和恢复帧之间计算 2 点回复，不改变实体桃提供者、私有 Choice 或牌区；v1–v26 与经典包 1.0–1.5 保留不含救援的孙权。
22. **苦肉已进入正式黄盖。** 官方黄盖页写明出牌阶段可失去 1 点体力，然后摸两张牌；官方规则集同时明确，只要体力值大于 0 就能支付失去体力的技能消耗。经典包 1.7.0 复用既有 `standard:kujin` 主动技能帧，同一阶段可重复发动，1 点体力发动先走濒死救援续接；包 1.6.0 保留不含黄盖的历史武将池，无需新增 rules 版本。
23. **奇袭已进入正式甘宁。** 官方甘宁页与标准规则集写明可将一张黑色牌当过河拆桥使用，官方案例包含已装备的黑色装备且转换牌可被无懈。经典包 1.8.0 与 rules v28 因而同时覆盖手牌/装备来源、有效牌型 Dismantlement、目标牌选择和无懈暂停；包 1.7.0 与 rules v27 保留旧合法动作集合。
24. **克己已进入正式吕蒙。** 官方吕蒙页写明，若本回合出牌阶段未使用或打出过杀，可以跳过弃牌阶段。经典包 1.9.0 与 rules v29 因而在 Play 阶段记录实际使用/打出的有效杀，并在 Discard 阶段发布可暂停 Choice；发动后保留超上限手牌并结束回合，包 1.8.0 与 rules v28 保留旧阶段流。
25. **突袭已进入正式张辽。** 官方张辽页写明，摸牌阶段可以改为获得至多两名角色的各一张手牌。经典包 1.10.0 与 rules v30 因而冻结有手牌的其他存活角色，发布一人/两人组合，并用随机暗手牌转移替代普通摸牌；包 1.9.0 与 rules v29 保留旧摸牌流程。
26. **裸衣已进入正式许褚。** 官方许褚页写明，摸牌阶段可以少摸一张，并使本回合使用杀或决斗对目标造成的伤害 +1。经典包 1.11.0 与 rules v31 因而保存回合标记，并把原始用牌者与决斗中的实际伤害来源分开；只有许褚本人使用且由许褚实际造成的伤害得到加成，包 1.10.0 与 rules v30 保留旧流程和旧归因。
