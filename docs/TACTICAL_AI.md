# AI 阵营决策与实战稳定性 · 2026-09-12

新开局使用战术策略 v3，改善身份场中的目标判断、保命与队友配合，并把火攻纳入公开攻击证据。旧存档继续使用其记录的 v1/v2，避免升级后同一命令记录重放出另一盘棋。

## 玩家可见的变化

- 忠臣和多人阶段的内奸不在主公 1 血时打出群伤；其他局面比较敌我承受伤害的净收益。
- 桃园结义只计算受伤角色，并区分敌我；不为只受伤的敌方主公白送治疗。
- 酒必须有另一张可合法打出、目标有正收益的杀来接续；不能把同一张红酒同时算成武圣的杀。1 血且缺桃时优先保留酒自救，自救时先用酒再用可救队友的桃。
- 武圣、龙胆比较转化成本；同一目标能用普通杀时保留桃，低血量时提高最后一张闪的保留价值。
- 马术不增加新的隐藏输入：AI 直接消费 Core 发布的距离型合法动作，距离一的顺手牵羊和杀目标会随公开距离修正自然出现；奇才同样只通过公开合法动作放宽距离型锦囊目标。
- 濒死救援、遗计、节命、援护采用同一阵营判断，避免一边攻击对手、一边为其补血补牌。
- 无懈区分有益与有害效果，不取消自己主动打出的摸牌、治疗等锦囊，可以用反无懈恢复有益效果。
- 公开攻击和阵亡会更新有限的阵营置信度；残局结合身份场公开配比与已揭示身份判断剩余敌人，不把曾经协助击杀反贼的内奸永久当作队友。
- 拆除乐不思蜀等判定牌按帮助该角色计算；不会把替敌人解除限制当作拆除敌方装备的收益。
- 苦肉在体力大于 0 且仍有出牌机会时按主动合法动作评分；降至 0 时先进入共享濒死救援窗口，AI 仍只按自己的私有救援选择继续推进。制衡按本座快照从手牌保留价值最低的合法集合中稳定选择所需数量；青囊按公开受伤状态选择恢复收益最高的合法目标，并从自己的手牌选择最低保留价值的弃牌；回春按公开受伤状态稳定选择所需的 2–3 名目标，并从自己的手牌选择两张最低保留价值的弃牌。AI 通过本座快照权衡公开体力/牌差收益，不读取牌堆顺序或其他玩家暗牌。
- 国战明置现在不再把主将/副将视为同分动作：AI 会在自己的视角中比较双将技能与当前机会，例如红牌转杀、杀转闪、突破杀次数限制和空手防护；明置信息成本只作小幅扣分，所有评分和思路仍不读取牌堆或其他玩家暗牌。同一 seed、策略版本和快照会得到相同的明置选择。
- 国战 M3 追加有限公开证据推断：战术 v2/v3 通过 Core 的 `PublicAttackEvidence` 只记录杀、决斗、群体攻击和火攻中“公开己方攻击隐藏座位”或“隐藏座位攻击公开己方/敌方”的弱信号，调整隐藏势力的攻击与濒死救援评分；已公开势力仍以 `FactionId` 为准，信号限制在 [-6, 6]，不会读取隐藏势力、暗牌或牌堆顺序。v3 另外把身份局火攻接入同一公开攻击观察入口；v1/v2 保持身份局火攻的旧行为。公开攻击后的中途 Checkpoint 会重放出相同 AI 知识与暂停 Prompt。

上述均为小型确定性启发式。仍无搜索树、跨局学习、难度分档或复杂阵营平衡；未知身份判断仍可能出错。AI 的输入只有自己的手牌、身份、已公开信息与合法动作，不读取他人暗牌、隐藏身份或牌堆顺序。

## 实战中修复的结算问题

1. 目标把最后一张手牌作为无懈打出，随后效果被反无懈恢复时，过河拆桥/顺手牵羊原先会尝试选择空手牌而抛异常，火攻也会要求从空手牌展示。现在在响应后重新检查目标，发布 `CardEffectSkippedEvent`、弃置已使用的锦囊并结束父结算；不会改选另一张牌或留下空询问。
2. 刚烈反杀主公时，如果伤害触发窗口后面还有援护等候选，原先会留下 `Winner = Rebels`、`Status = Running` 和处理区中的杀，无法继续。现在在胜负确定后关闭剩余候选与父伤害，清理用牌并发布一次终局。

三个空手牌场景使用真实受控牌堆、合法出牌、AI 消耗最后一张无懈、人类反无懈和命令重放；不通过反射修改引擎。致命刚烈使用实际五人牌局 seed `1112031`。

## 存档契约

`GameOptions.AiPolicyVersion` 默认 1，供缺少字段的既有 JSON 恢复；WPF 新牌局显式设为 3。引擎将该值传入每个 `SimpleAiBrain`，检查仅支持 1/2/3。Checkpoint SchemaVersion 仍为 3，规则行为版本单独由 `RulesVersion` 标记，缺少该字段的旧 JSON 按 v1 恢复；外层存档 FormatVersion 仍为 1。v3 保留 v2 的战术与国战公开证据语义，并新增身份局火攻公开证据；v1/v2 的既有命令日志和 Checkpoint 不被新观察入口改写。

`tests/CardGame.Core.Tests/Fixtures/legacy-ai-checkpoints.json` 在改动 AI 前捕获，不应重新生成来适配实现。它含三场旧版全 AI 完整牌局及一份真实 WPF 暂停存档；测试比对可信完整快照和全部事件负载 SHA-256。WPF 另测试缺少版本字段的文件能够读取、继续、再次保存为 v1，然后新开局切到 v3；非法版本文件保留原游戏。

同一策略版本的评分和随机调用顺序属于回放行为。今后再改变 AI 决策时应新增策略版本，不能悄悄改动已发布的 v2 或 v3。内容指纹只覆盖内容定义，不替代此策略版本。

## 验证结果

固定 64 个 seed（`724000 + index × 7919`），分别跑五人和八人桌、v1 和 v2，共 256 场。均采用实际交互开局和全 AI，400 回合上限；检查每场完成、结算栈与处理区为空、90 张实体牌唯一且守恒。v3 沿用 v2 的既有战术评分，并额外覆盖身份局火攻公开证据的确定性回归。

| 观察项 | v1，128 场 | v2，128 场 |
| --- | ---: | ---: |
| 正常胜负结算 | 128 | 128 |
| 达到回合上限的平局 | 0 | 0 |
| 忠臣/多人内奸在主公 1 血时群伤 | 26 | 0 |
| 反贼桃园仅回复敌方主公 | 6 | 0 |
| 酒效未用于杀，在回合末失效 | 110 | 0 |
| 内奸有桃却不救多人局主公 | 26 / 26 次机会 | 0 / 18 次机会 |
| 自救有酒仍优先花桃 | 4 | 0 |
| 平均回合数 | 36.5 | 31.4 |
| 最长牌局回合数 | 126 | 116 |

统计在游戏结束后根据类型化事件重建公开体力、存活状态及可信手牌移动，仅用于诊断，绝不作为 AI 输入。策略改变后后续局面也不同，分母因此不同；自我对弈的阵营胜率不能证明对人类的棋力或模式平衡。完整逐局记录在 `artifacts/ai-review/simulation.json`。

 完整 Release 构建零警告/错误；早期 AI 基线为 Core **116/116**、WPF **23/23**，当前全量为 Core **135/135**、WPF **45/45**。规则版本 4 的 AI 目标牌选择只使用脱敏手牌数量和不透明 slot 候选；规则版本 5 的致命伤害后触发仍由 AI 自己的玩家视图决定，不读取目标暗牌或宿主栈；WPF 五场不同人数与身份的完整对局通过实际界面命令出牌 49 次、回答响应 30 次，均验证终局恢复；新增扩展内容的主动/被动技能观察和 Core 结果回读也通过离屏控件回归，苦肉濒死后的私有救援续接与当前规则版本跨座位酒救援另有 Core 确定性回归。国战 M3 新增测试覆盖公开攻击对隐藏势力置信度的有界更新、公开势力优先级、新 AI 实例隔离，以及含公开攻击证据的中途 Checkpoint/Replay；v3 另覆盖身份局火攻公开证据，同时验证 v1/v2 的旧行为不漂移。真实控件还覆盖存档、手动弃牌、音效与动画路由。截图在 `artifacts/ai-review/ui-final/`。没有显示或操作桌面窗口，因此不宣称真实鼠标、键盘、多 DPI 或扬声器试听已验收。

本次涉及的策略与结算文件通过格式检查；全量格式检查仍有既有 `GeneralArt.cs` 和 Core 测试 `Program.cs` 空白格式问题，未批量改写这些历史段落。记录在 `artifacts/ai-review/format-check.txt`。
