# 技能边界整批迁移

## 本轮目标

用户要求停止按武将逐个迁移、逐项全量检查。本轮按调用边界并行替换：被动规则能力、主动动作执行、共享拼点及回合状态。冻结起点为 `1a80ea40625b9877e37de7636e1232f39f879ca3`，三个 Sol 使用同一提交的独立副本。

先删除旧接口，记录编译错误，再批量修复依赖。禁止用同名空实现恢复编译，禁止将同一个巨型接口改名后声称完成解耦，禁止仅把人物分支搬到另一个 `GameEngine` partial。

## 验收边界

- 源码不再定义或调用 `IPassiveSkill`、`IActiveSkill`、`SkillRegistry.GetActive`。
- 被动规则按能力参与聚合；身份定义不代理暴露全部旧接口。
- 主动技能的规则与效果执行有独立契约；引擎保留命令校验、受控状态操作和续接。
- 共享拼点负责参与者、牌、结果与父流程续接，不包含天义、驱虎、烈刃的人物执行分支。
- 天义的专有胜负布尔位和消费者由通用回合状态能力替代。
- 不丢弃现有技能行为，不把本轮接口替换等同于全库人物规则已全部独立。

`tools/Test-SkillBoundaries.ps1` 提供上述旧名称与拼点边界的低成本静态检查。它只防止明确的旧入口回流，不能替代代码审查或玩法测试。

## 验证安排

开发过程中仅编译与受影响的定向验证，不为每个技能重复全量。三路合并并修复编译错误后，再运行一次整批 Core 与 WPF 检查；若失败，只重跑失败范围，修复影响到其他范围时才扩展验证。版本号由整合者统一处理。

## 不保留历史兼容负担

用户明确取消保留旧内容指纹的要求，并要求移除已有兼容投影和旧执行链。现有技能定义可直接更新，内容指纹随当前定义变化；不再新增旧技能到新程序的兼容投影，也不为旧包保留退役执行器。

规则版本统一变化，旧存档直接拒绝恢复。当前存档的内容一致性检查仍用于发现当前数据损坏或不匹配，它不承担迁移旧存档的职责。测试以当前完整玩法为准，纯粹维护历史指纹、旧分派接口和退役行为的断言一并清理。

## 迁移前的事实

起点正式身份池有 133 个去重技能：80 个挂载 Program，其中 68 个使用组合式实现，12 个使用专用运行时；51 个仍走 LegacyKind，2 个仍由技能 ID 专用分支处理。这个分类仅描述入口，Program 非空也不能证明引擎中已没有人物耦合。

此前拼点 partial 的拆分属于职责归位，共享接口尚未覆盖全部人物续接。近期同时进行了公共能力、新武将和界面工作；现有记录不能准确分配用户所述十小时的具体去向。验收以本轮实际移除的依赖和保留的行为为准。

## 本批已实现的边界

- 删除 `IPassiveSkill`、`IActiveSkill`，按规则查询、转换、救援等能力接入；主动动作由独立执行器经受控 host 操作状态。
- 删除 23 个公开 `Start` / `Advance` / `Human*` 旧写入口及 `RespondCommand` 别名。产品修改状态只经 `Submit`；测试驱动也提交正式命令。
- 天义、驱虎、烈刃改用共享 Program 拼点与回合效果。删除旧阶段模块原型、拼点结果回调和人物胜负字段。
- 删除历史规则版本执行分支、旧包构造签名和十二代内容哈希投影；当前规则为 167，内容哈希只有当前结构。旧存档拒绝恢复，当前存档仍检查一致性。
- `PlayerSnapshot` 删除主副将的六个单技能字段，统一使用技能集合：`null` 表示不可见，空集合表示可见但没有技能。
- 删除从旧对局存档导入音画偏好的路径，以及对局存档中的重复字段；音画偏好只由设备偏好存储负责。

整合中修复了三个实际边界问题：神速第一段清理误删第二段询问；AI 猜测存在的闪与引擎合法候选不一致导致空引用；雷击致胜后父杀留在处理中。相关测试覆盖连续神速、合法响应、终局清理及回放。强袭报错另定位为测试对多个合法天香选择误用 `Single`，保留选择身份一致和回放断言后修复。

## 第二批：一个 Program 模型与执行器

以 `040b9a9` 为共同基线，三个 Sol 分别负责当前 schema、判定入口、卡牌响应入口。主任务删除 AI 版本分流、批量迁移夹具、三方整合和验收；开发过程中使用同一份集成构建产物，避免三个副本重复修复相同依赖。

- 触发和主动效果均直接存储 `SkillProgramEffect`。删除 `SkillProgramTriggerEffect` 及其两个枚举、`ToExecutionEffect`、`UsesCompositionKernel`、`UsesSharedExecutor`。
- 17 条原专用触发经 `ProgramSkillFrame` 和唯一 `SkillProgramExecutor` 执行。事件边界仍负责冻结候选、父事件与卡牌来源，但不再维护自己的效果游标。
- 判定替换增加受控 `ReplaceJudgment` 原语；取得转换对手手牌使用现有 `selectAndMoveOwnedCard`。没有正式资源使用的旧直接判定致死链一并移除。
- 66 对正式资源统一为 rules schema 58 / presentation schema 3，114 个 Program 的最低规则版本为 168。仅解析当前格式，旧格式直接拒绝；一次性离线转换脚本只留在本批证据目录。
- AI 的主动、触发与互斥选择读取相同操作目录，删除旧摸牌估值器和对应旧 schema 校验器。
- 删除未使用的历史 AI 金样本及固定指纹断言，保留当前数据一致性、命令回放、牌区清理、隐私与嵌套效果测试。

完整验收数据见 [第二批执行器清理记录](benchmarks/2026-09-26-shared-executor-cutover.md)。

## 尚未完成的全库清理

第二批移除了 Program 模型内部的双执行路径和 schema 1–57 的解析分支。由事件边界提供上下文与恢复父流程是引擎职责，不意味着保留第二套技能效果执行器；事件专用的效果循环已删除。

目前还存在 `LegacyKind` 对应的实际 C# 技能实现，以及演示规则与正式模式的分派。技能类有不少只提供名称、资格和规则查询，真正效果仍在引擎人物分支中；这正是“已有接口”却未真正独立的原因。下一批按主动动作、伤害触发、判定、转换、数值及用牌规则这些公共能力切除完整旧链，同时同步合法动作、AI、UI 和续接消费者。先删除 host 的默认抛错/忽略参数转发及已确认死入口，再统一技能身份与内容注册；不能只改名或删注册来制造“无耦合”。牌种 `CardKind` 是真实领域模型，不属于应删的技能投影。持续新增武将保持暂停，直到公共执行链清理完成。
