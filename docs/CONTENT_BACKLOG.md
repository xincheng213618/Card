# 内容现状与扩充入口

当前内容由 `CardGame.Content.Standard` 的包组合入口和 `src/Characters/<人物>/<版本>/` 共同管理。实际武将、技能、模式和牌堆以 Registry 注册结果为准；图鉴收录、来源抓取成功或配置能够加载，分别只证明对应层面的状态。

## 当前内容

| 范围 | 实现与入口 |
| --- | --- |
| 卡牌与装备 | Standard 基础牌、即时/延时锦囊、装备和牌堆；经典扩展包含借刀杀人与更多装备 |
| 武将 | 经典、界、SP、神、谋及普通 OL 等独立版本资料；人物目录自动发现并按资料中的包及顺序注册 |
| 模式 | 五人/八人身份、技能演示、公开阵营 2v2、四人国战 Lite 与六人独立势力实验 |
| 程序技能 | 查询修正、牌身份/转换、主动步骤、触发、贡献、状态、牌策略和人物运行时操作 |
| 桌面 | 当前注册的技能文案、选将版本、图鉴、立绘、响应与技能选择；素材状态独立于规则状态 |

具体来源、注册位置与包组合见[内容清单](content/CONTENT_MANIFEST.md)，技能格式与能力见[运行时](content/skill-composition/RUNTIME.md)，身份选将偏好见[选将说明](content/IDENTITY_DRAFT.md)。

## 新增或校正规则

1. 锁定产品线、人物版本和当前采用的规则来源，保存人物属性、技能文本、官方 FAQ 及明确的工程解释。
2. 对照已注册能力、正式配置和[能力请求](content/CORE_API_REQUESTS.md)，核实完整规则是否可表达；同名人物或技能不自动共用规则。
3. 在人物目录添加资料、规则和展示，复用共享机制。只有现有能力不足时才扩展运行时，并接入现有注册协议。
4. 采用现有检查覆盖纯配置；新行为或修复增加针对性检查，验证原生材料、费用、子结算返回、隐私及命令恢复。
5. UI 行为变化补相应 WPF 检查；素材核对来源和资源绑定。离屏渲染、程序化交互与真人前台操作分别表述。

## 当前关注范围

完整国战的规则集合仍超出已提供的 Lite/独立势力实验；普通新人物的完整性需要逐条对照来源。能力清单中的已有实现可复用，不能把旧批次的待办直接当作当前缺口。武将目录不是在线官方全量图鉴的完成度统计。

详细开发约束见[开发门槛](DEVELOPMENT_GATES.md)，验证入口见[内容场景边界](content/SCENARIO_MATRIX.md)。
