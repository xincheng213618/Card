# 局域网房间原型

当前支持五人、八人标准身份局：真人与 AI 混合入座，使用标准 108 张实体牌和首批标准武将池。服务端负责规则、AI、随机数和命令顺序，WPF 只显示自己的玩家视图并提交已发布的选择。现有单机玩法、快速开始和存档保持原入口。

## 启动服务器

在安装仓库 `global.json` 所指定 .NET SDK 的机器上，从仓库根目录运行：

```powershell
./tools/Start-LanServer.ps1 -Port 5088
```

该进程监听所有网卡的 5088 端口，按 Ctrl+C 停止。服务器也可以直接运行跨平台项目：

```powershell
dotnet run --project src/CardGame.Server --no-launch-profile -- --urls http://0.0.0.0:5088
```

WPF 客户端运行在 Windows；服务端没有 WPF 依赖，可以放到已有 Windows 或 Linux 服务器。客户端填服务器实际地址，例如 `http://192.168.1.10:5088`。同机调试可用 `http://127.0.0.1:5088`。若其他电脑无法连接，确认服务器端口对测试网段可达。启动脚本不会修改防火墙。

## 进入房间

正常打开游戏，选择八人身份、五人身份、2v2、国战或活动场等模式后，直接进入该模式的本地房间：你默认入座，其余为空位，可逐个添加/移除 AI，或“补齐 AI”。满员后点击“开始对局”。难度、身份、阵营和牌堆仍在房间设置中选择；“快速开始”直接沿用单机流程，不要求手动安排座位。

需要真人联机时，在五人/八人标准身份房间点击“联机房间列表”，或使用首页“联机房间”。也可以单独打开联机窗口：

```powershell
dotnet run --project src/CardGame.Wpf -- --lan http://192.168.1.10:5088
```

1. 填服务器地址、昵称，选择五人或八人标准身份，刷新房间列表。
2. 房主创建房间，其他玩家选择同一模式下的房间并进入。
3. 房主可在空位添加 AI、移除 AI，或点击“补齐 AI”。真人座位不能被 AI 覆盖。
4. 每位真人点击“准备”；座位满员且全部准备后，房主点击“开始对局”。
5. 按当前提示选将、出牌、响应、发动技能或弃牌。普通出牌选项已列明牌和目标；需要手动选择材料的技能在右侧列出候选牌和目标，勾选后确认。

“快速开始”使用原单机流程：自己操作，其余座位由 AI 控制，不需要服务器。各桌面模式都使用本地房间准备流程；首批真人联机开放标准身份局。

## 原型边界

- 房间和对局保存在服务端内存，重启服务器会清空。当前没有账户、跨进程重连凭证、服务端落盘、匹配或观战。
- 网络短暂中断时窗口会自动重试读取，恢复后继续原座位。关闭房间窗口后，同一 WPF 应用进程可以从列表重新进入原座位；退出整个应用后不能找回该凭证。
- 对局中离线的真人会暂停在其输入处，当前没有超时自动托管或中途替换 AI。等待中的房间可返回列表离座，房主离开后转交给下一名真人。
- 提交超时后显示“确认上次操作”，重试使用相同请求编号；服务器拒绝旧提示、重复编号的不同内容及越权操作。界面不自动重复出牌。
- 每个连接只获得自己的快照、选择和经过白名单筛选的公开动态。完整事件、命令日志、随机种子和 checkpoint 不下发给客户端。
- 这是受信任局域网内的原型，尚无公网账户与服务治理。每个服务端最多保留 64 个房间，已无人等待的房间会在创建新房间时移除。

## 验证

使用现有检查入口：

```powershell
./tools/Test-Changed.ps1 -CoreFilter @('Multiplayer:', 'LAN rooms:')
./tools/Test-Changed.ps1 -WpfFilter 'LAN room UI:'
./tools/Test-Changed.ps1
```

定向覆盖多真人选将、回合与响应、冷回放、真实回环 HTTP 对局、混合 AI、座位权限、手牌隔离、重复请求、重连、房间准备和选择保持。回环测试不能代替两台物理机器及远端服务器的验收。全量检查仍只在明确要求时运行。
