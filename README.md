# 八人身份局 · C# 最小 Demo

这是一个本地运行、以代码可读性为首要目标的三国身份卡牌 Demo。它不是完整复刻，而是用较小的规则集合展示：

- 八人身份分配：1 主公、2 忠臣、4 反贼、1 内奸；
- 服务端式的纯规则核心与玩家可见状态；
- 杀、火杀、雷杀、闪、桃、酒、决斗、无中生有、南蛮入侵、万箭齐发、桃园结义、五谷丰登、过河拆桥、顺手牵羊、火攻的使用和响应/即时效果；普通杀、火杀、雷杀共用杀的响应路径，未打出闪时分别产生普通、火焰、雷电伤害；酒可在出牌阶段准备本回合下一张直接杀的 +1 伤害，濒死时仅由濒死者自救 1 点体力，决斗支持双方交替出杀，南蛮入侵按座次逐个请求出杀，万箭齐发按座次逐个请求出闪，桃园结义按座次逐个恢复存活角色，五谷丰登公开翻牌后按座次私有选牌，过河拆桥按确定性盲选移除目标一张手牌，顺手牵羊按座位环距离一盲取目标一张手牌，火攻通过目标展示与同花色弃牌进入火焰伤害链；
- 摸牌、出牌、弃牌、死亡奖惩与三方胜负；
- 奸雄、反馈、咆哮、英姿、空城、武圣、龙胆、遗计、节命、援护十种被动技能；武圣支持红色实体牌按杀使用，龙胆支持闪/杀双向转化，遗计支持受伤后摸牌并向其他存活角色分配一张，节命支持受伤后私有选择一名手牌数低于体力上限的角色补牌至上限，援护支持其他角色受伤后由拥有者弃置一张手牌令其回复 1 点体力；
- 不读取暗身份的可解释 AI；
- 固定随机种子、状态快照和逐步推进；
- 手牌、摸牌堆、处理区、弃牌堆等唯一牌区与移动账本；
- 状态提交后通知及观察者异常隔离；
- 八人 WPF 牌桌、日志、AI 候选评分与当前事件栈。
- 基础牌内容目录、标准演示牌堆配置和可复现的发牌参数。
- `Submit(GameCommand)`、Revision、PromptId 和精确 Choice；旧 WPF 方法作为兼容适配器保留。
- 可信宿主可记录已接受的 `GameCommand`，通过 `CommandJson` 编解码并用 `GameReplay` 在相同 seed/Registry 下确定性重放；命令日志不进入玩家视图。
- 独立的 `CardGame.Content.Standard` 内容包与不可变 Registry，内容 ID 使用 `standard:*` 命名空间。
- 可暂停的模式化开局、私有武将候选、共享池去重、AI 选将和逐轮发牌；旧构造式 Demo 仍可用作兼容路径。
- 杀/火杀/雷杀/闪/桃/酒/决斗/无中生有/南蛮入侵/万箭齐发/桃园结义/五谷丰登/过河拆桥/顺手牵羊/火攻/伤害链路的可序列化 `ResolutionFrame` 栈、交替响应、群体逐目标响应、无目标即时摸牌、酒的一次性杀伤害修正、濒死者酒自救、可暂停多目标恢复、公开牌 draft、隐藏目标牌盲弃/盲取、火攻私有展示/同花色弃牌和基础濒死求桃及提交后的类型化结算事件；伤害事件携带 `DamageNature` 与实际金额，伤害后触发现在有独立的可序列化候选游标和暂停/恢复边界，遗计与节命分别覆盖跨手牌分配和补牌至上限，援护覆盖一次明确的跨座位弃牌恢复效果。

界面没有复制商业游戏或开源项目的美术素材。武将头像是 WPF 根据姓名和势力颜色绘制的字印，卡牌也是自绘文字牌面，因此仓库可以离线、自包含地运行。
- 华佗的反馈在目标存活且伤害牌仍在处理区时发布私有触发选择；选择发动后取得同一张伤害牌，`DamageTriggerWindowFrame`、`DamageSkillFrame`、`DamageSkillResolvedEvent` 和 `DamageCardClaimedEvent` 记录完整宿主结果，普通玩家视图不会泄漏取得牌 ID。
- 郭嘉的遗计在受伤后由 `DamageSkillFrame` 记录两张私有摸牌，AI 或人类从合法的牌/目标组合中选择一张交给其他存活角色；`DamageSkillCardsDrawnEvent`、`DamageSkillCardGivenEvent` 和 `skill.yiji.*` 移动原因只属于可信宿主，普通观察者不会看到候选牌面。
- 荀彧的节命在受伤后由同一 `DamageTriggerWindowFrame` 发布私有目标 Choice；目标只按公开的存活状态、手牌数量和体力上限筛选，补入的牌通过 `DamageSkillCardsDrawnEvent` 与 `skill.jieming.draw` 移动原因记录，普通观察者不会看到牌面。
- 援护者在其他角色受到正伤害后由同一 `DamageTriggerWindowFrame` 发布私有弃牌 Choice；发动时将拥有者的一张手牌移入弃牌堆，再通过 `RecoveryFrame` 令固定的受伤目标回复 1 点体力，`DamageSkillCardDiscardedEvent`、`RecoveryAppliedEvent` 和 `DamageSkillResolvedEvent.EffectTargetSeat` 记录可信宿主结果，普通观察者不会看到被弃牌的 ID。

## 运行

需要 Windows 和 .NET 8 SDK。项目已经用 `global.json` 固定到本机的 .NET 8.0.408。

```powershell
dotnet build .\CardGame.sln -c Debug
dotnet run --project .\src\CardGame.Wpf\CardGame.Wpf.csproj
```

不依赖测试框架或第三方 NuGet 包的核心自测：

```powershell
dotnet run --project .\tests\CardGame.Core.Tests\CardGame.Core.Tests.csproj -c Release
```

## 怎么玩

你固定坐在底部，并在默认配置中担任主公。其他身份默认隐藏，阵亡或开启“开发者视图”后才显示。

1. 新对局开始时，在中央候选按钮中选择一个武将；候选只对你可见；
2. 点击一张可用手牌；
3. 使用杀、火杀或雷杀时，再点击绿色描边的合法目标；若你是关羽，红色非杀牌会显示为可按杀使用的转化动作；若你是赵云，闪会显示为可按杀使用的转化动作；
4. 点击“使用选中的牌”；
5. 桃会自动选择自己；酒可在出牌阶段使用并公开显示酒效，使本回合下一张直接杀造成 2 点伤害，酒效在直接杀声明时消费，未消费则在回合结束失效；濒死时酒只可由濒死者自救 1 点体力，不能用酒救援其他角色；闪只能在响应杀、火杀、雷杀或万箭齐发时使用，火杀/雷杀未被闪避时分别造成 1 点火焰/雷电伤害；无中生有不需要目标，使用后摸两张牌；南蛮入侵不需要目标，所有其他存活角色按座次依次响应杀或承受 1 点伤害；万箭齐发不需要目标，所有其他存活角色按座次依次响应闪或承受 1 点伤害；桃园结义不需要目标，所有存活角色按座次依次回复 1 点体力，满血角色跳过恢复；五谷丰登不需要目标，公开展示等同于存活人数的牌，所有存活角色按座次各选一张，选择 prompt 只对当前选牌者可见；过河拆桥选择一名有手牌的其他角色，规则核心用确定性随机数盲弃一张，牌面不会展示给使用者；顺手牵羊只能选择距离为 1 且有手牌的其他存活角色，规则核心盲取一张手牌，取得的牌只对使用者可见；火攻选择一名有手牌的角色，目标私有展示一张手牌，攻击者再选择同花色手牌弃置后造成 1 点火焰伤害；
6. 结束出牌后，引擎停在 AI 阶段，可点击“AI 单步”观察一个状态转换/动作，也可直接“运行至我行动”；
7. AI 对你使用杀、火杀、雷杀或万箭齐发时，用底部按钮或中央精确响应选项选择打出闪或不响应；AI 对你使用决斗或南蛮入侵时，按钮会切换为打出杀；若你是关羽，选择红色非杀牌和合法目标后可用独立按钮按【杀】使用；若你是赵云，杀/闪响应会在中央列出物理牌与转化牌型，选择杀也可以当闪打出；若你是华佗并受到伤害，中央会显示只对你可见的“发动反馈/不发动”选项；若你是郭嘉并受到伤害，中央会显示只对你可见的遗计牌/目标组合按钮；若你是荀彧并受到伤害，中央会显示只对你可见的节命目标/跳过按钮；若你是援护者且其他角色受伤，中央会显示只对你可见的援护弃牌/跳过按钮；若进入濒死，中央会显示使用桃/酒救援或让其阵亡的选项，酒只对濒死者本人可用；五谷丰登出现时，中央会显示公开牌和你的私有选牌按钮；过河拆桥可在选择手牌后点击有手牌的合法目标，顺手牵羊可点击距离为 1 的合法目标。开发者视图下，桃园结义和五谷丰登的事件栈会显示当前目标/选牌游标，反馈、遗计、节命和援护会显示 `DamageSkill` 子帧。

同一个种子会产生完全相同的身份、武将、牌堆与 AI 决策。普通“新对局”使用系统安全随机数产生不可预测的种子；为避免据此重建暗身份和牌堆，当前种子只会在开发者视图或游戏结束后显示。测试则显式注入固定种子，便于复现。

## 有意保留的简化

为了让第一次阅读能顺着一次调用走到底，目前只实现座位环上的最小距离查询；马匹修正、装备、其余锦囊、判定、主动出牌技能和联网协议仍未实现。普通杀、火杀和雷杀共用杀的可暂停响应路径，并通过 `DamageNature` 区分伤害类型；酒支持一次性直接杀 +1 伤害和濒死者自救 1 点体力，武圣已接入红色实体牌按杀使用，龙胆已接入闪/杀互转并复用精确响应 Prompt；属性抗性、铁索连环、属性伤害转化和更复杂的多伤害嵌套尚未实现。决斗已作为第一张锦囊接入双方交替出杀的可暂停响应，无中生有接入无目标即时摸牌，南蛮入侵和万箭齐发共用最小群体逐目标响应，桃园结义接入可暂停的多目标 `RecoveryFrame` 子帧，五谷丰登接入公开翻牌与私有逐人 draft，过河拆桥接入目标合法性和确定性隐藏手牌盲弃，顺手牵羊接入距离一合法性与确定性隐藏手牌转移，火攻接入目标私有展示、攻击者同花色弃牌和类型化火焰伤害，遗计接入受伤后两张私有摸牌和向其他存活角色交一张牌，节命接入受伤后按公开手牌数量选择目标并补牌至目标上限；目标装备/判定区选择、无懈链、用酒救援他人、通用可配置的非受伤者触发条件和复杂濒死技能仍未实现。选将已实现为 K4 的单将私有候选流程；桃可在出牌阶段治疗自己，也可在基础濒死窗口救援一名角色，弃牌由规则核心自动完成，AI 也不会保留跨局学习数据。

这些简化没有写死在窗口里。当前 WPF 已经通过 `CardGame.Content.Standard` 创建不可变内容 Registry；后续继续增加牌、武将和模式数据时，仍由 Core 提供稳定契约，WPF 只消费玩家快照并提交动作。

伤害后触发中的跨座位语义目前只通过援护这一项显式示例开放：援护者只能从自己的私有手牌中选择一张牌弃置，并令伤害目标回复 1 点；它不等同于所有技能都已获得通用的非受伤者触发能力。

伤害后技能当前统一走可暂停的候选窗口：Core 按稳定顺序冻结 `DamageTriggerCandidate`，压入带 `CandidateIndex` 的 `DamageTriggerWindowFrame`，再为可选技能创建 `DamageSkillFrame`；反馈取得处理区伤害牌，遗计在私有摸两张牌后通过精确的牌/目标 Choice 将一张牌交给其他存活角色，节命在受伤者的私有 Prompt 中按公开手牌数量选择一名角色补牌至其体力上限，援护在其他角色受伤后通过私有弃牌 Choice 将一张拥有者手牌移入弃牌堆并令固定受伤目标回复 1 点体力。AI 通过自己的快照决定，人类通过 `AnswerPromptCommand` 选择，完成后继续同一候选游标。每个技能通过 `CanTriggerAfterDamage` 声明时机；援护是当前唯一显式 opt-in 的非受伤者触发示例，通用可配置跨座位候选、复杂伤害后效果和多层触发仍未实现。

内容扩充的边界和待开放的锦囊、装备、技能入口见 [`docs/CONTENT_BACKLOG.md`](docs/CONTENT_BACKLOG.md)。当前 72 张基础演示牌堆已包含 18 张杀、2 张火杀、2 张雷杀、18 张闪、10 张桃、2 张酒、4 张决斗、2 张无中生有、2 张南蛮入侵、2 张万箭齐发、2 张桃园结义、2 张五谷丰登、2 张过河拆桥、2 张顺手牵羊和 2 张火攻；其余锦囊和装备仍需对应的类型化结算/区域入口，不会被伪装成基础牌。
